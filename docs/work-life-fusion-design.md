## 1. 背景与问题

### 1.1 产品主张

Owli Team 不做"工作工具 + 生活玩具"的缝合，而做**一个 AI 团队同时陪伴用户的工作与生活**——白天帮你干活，晚上陪你生活。市面上 Character.AI 系只做生活陪伴、Agent 平台系只做工作效率，"同一团队跨心境连续陪伴"的中间地带无人占据。场景资产（研发/投研/财务法务 + 塔罗/风水/TRPG/家庭/健康）已全部就绪，缺的是把两类场景**组织成一个产品**的上层设计。

### 1.2 已具备（本专项的直接基座）

| 能力 | 现状 | 位置 |
| --- | --- | --- |
| 场景与角色资产 | 40+ 场景 165 角色包，工作/生活双侧均已覆盖 | `agents/` |
| 灵魂变体 | 同角色多人格，创建可选、运行中可切换、落 system 事件条 | M15–M18 |
| 记忆分层 | 会话/角色/项目/全局四层向量记忆 + remember 工具 + 记忆面板 | M25 |
| Project 层 | 项目隔离 + git worktree + 交付件体系 | `server/src/workspace.ts` 等 |
| 调度与通知 | schedule 模块、完成后 WS 推送、断点续跑 | `server/src/schedule/` · `ws.ts` |
| 平台路由 | 零选择开聊，PRS 自动组队派发 | M48（ADR 0101） |
| 仪式化场景先例 | 塔罗仪式化交互设计已定稿 | `docs/tarot-ritual-design.md` |

### 1.3 缺口（代码核实结论）

| # | 缺口 | 后果 |
| --- | --- | --- |
| 1 | **无空间概念**：会话列表是单一平铺流，40+ 场景入口无分组 | 工作/生活混杂，首屏噪音大，用户无法按心境切换 |
| 2 | **记忆无域隔离维度**：四层关联中无 space/生活域概念 | 工作内容可能被生活角色召回；用户无法验证"不互通"，信任受损 |
| 3 | **灵魂与场景无绑定**：灵魂需手动选择与切换 | "同一角色上班/下班不同人格"的一体化卖点无法自动呈现 |
| 4 | **无时间线/日程化编排 UI**：schedule 是后台能力，无面向用户的"今日"视图 | 陪伴连续性无载体；生活场景缺少每日回访钩子 |
| 5 | **跨域协同为零**：工作产出与生活复盘互不感知 | "一体"沦为"都有"，没有 1+1>2 的融合价值 |
| 6 | **商业化无分层锚点**：能力全量平铺 | 无法回答"为什么付费"；工作线价值被生活线稀释 |

## 2. 专业评估（结论先行）

### 2.1 可行性结论：**高**

- **不动编排内核**：本专项全部改动位于「数据模型（space 字段）+ 记忆召回过滤 + 前端 IA」三层，parser/scheduler/engine/波次循环零改动；
- **记忆隔离是过滤器而非新系统**：向量召回在 L1.5 注入处加 space 谓词即可，sqlite-vec 双后端均支持带 WHERE 的查询路径；未命中即降级现状行为；
- **灵魂绑定复用既有机制**：空间 → 默认灵魂 = 创建会话/成员入编时的默认值解析，运行中换装能力不变；
- **时间线是组合而非新建**：schedule + 通知 + PRS 组队已能支撑"定时发起一场固定角色组合的会话"，缺的是聚合视图与订阅式模板；
- **就低改造**：space 默认值（`default` 空间）使存量会话零迁移、零行为变化，与 M79 kind='team' 默认值策略同先例。

### 2.2 关键风险与边界（详见 §7）

1. **信任边界是第一优先级**：记忆域隔离必须"可看见、可验证"，否则一体化是减分项；
2. **场景平铺诱惑**：40+ 场景必须按空间折叠，首屏入口 ≤5；
3. **双心境的通知克制**：生活空间推送不得打扰工作时段（通知策略按空间 + 时段分级）。

## 3. 目标设计

### 3.1 空间（Space）——一级信息架构

**数据模型**：
- 新表 `spaces`：`id / name / kind(work|life|custom) / icon / theme_key / sort / created_at`；
- `sessions.space_id`（默认 `default` 空间，存量零迁移）；`projects.space_id` 同理；
- 内置三空间：`工作` / `生活` / `我的`（default），用户可自建（如"我的小店"、"备考"）。

**每空间独立**：
- 会话列表、交付件目录、通知策略（§3.5）、配色氛围（浅色主题内的色调变量，不做暗黑）
- 成员编排预设：工作空间置顶快速组队（研发/OPC），生活空间置顶仪式场景（塔罗/复盘/家庭）

**前端 IA**：
- 左栏顶部加空间切换器（图标 + 名称，⌘K 可搜）；
- 场景选择器按空间过滤：工作空间默认隐藏 tarot/trpg/fengshui 等（可手动"显示全部"），生活空间反之——**隐藏而非禁用**，跨空间组队是一体化的合法用法。

### 3.2 记忆域隔离与可见化

**隔离规则**：
- 记忆表与向量表加 `space_id`；写入时按会话所属空间落域；
- 召回（L1.5 注入 + remember 面板检索）默认 `WHERE space_id = 当前空间 OR space_id IS NULL`（`NULL` = 用户显式标记的全局记忆，如"我叫 X"）；
- 角色维记忆（跨会话）同样按空间分域：同一角色在两个空间各有一份画像。

**可见化（信任的关键）**：
- 记忆面板加空间 Tab 与「此空间记忆不互通」明示文案；
- 角色档案卡：「TA 记得我什么」按空间分组展示，支持单条迁移到全局 / 删除；
- 设置页提供「跨空间记忆审计」：一键查看哪些记忆是全局的。

### 3.3 空间默认灵魂（"上班/下班"状态）

- `agents` 目录约定不变；新增空间 → 灵魂的**默认绑定表**（settings 级，可改）：
  - 例：`coach` 在工作空间默认灵魂「职业教练」，在生活空间默认「人生教练」；
- 绑定只是**入编默认值**：运行中换装、分身同台等既有能力零变化；
- 无对应灵魂的角色行为与现状完全一致（协议优先级永远高于灵魂，沿用 M15 不变量）；
- 配套：鼓励为跨域角色补「工作/生活」双灵魂资产包（check:agents 增加可选的双灵魂覆盖度报告，不进 strict 门禁）。

### 3.4 今日时间线首页

**首页 = 时间线**，而非会话列表：
- **晨间**（定时任务）：`assistant` + `wellness` 生成今日安排卡（日程、天气、健康提醒），落一条系统消息 + 推送；
- **日间**：工作空间的进行中队列（活跃 Run、待审批、待你指示）聚合置顶；
- **晚间**：生活入口（每日塔罗、复盘、阅读）+「今日回顾」卡（§3.5 复盘闭环入口）。

**仪式化订阅模板**：
- 场景包可声明 `ritual: { cron, roster, opener }`（front-matter 扩展，check:agents 校验）；
- 用户一键订阅（如「每日塔罗 22:00」「每周复盘 周日 20:00」「月度财务盘点」）→ schedule 模块建任务，到点自动开会话并发 opener 消息，走 PRS 语义零变化；
- 通知按空间策略分级：生活空间晚间推送默认静默入收件箱，不弹打扰。

### 3.5 跨域融合闭环（一体化的真正价值）

1. **晚间复盘**：工作会话的交付件/任务收口事件 → 晚间定时任务由 `coach`/`life-admin` 发起复盘会话，引用当日工作摘要（经 §3.2 全局化审批：复盘发起时把「今日完成 3 项任务」这类**事实摘要**显式提升为全局记忆，细节内容不跨域）；
2. **状态感知编排**：健康场景记录的约束（"昨晚失眠"→ remember 全局条）→ 工作空间 `pm` 在计划范式下读取全局约束，调整当日计划强度；
3. **人设连续性**：跨空间共享的仅有「全局记忆 + 角色档案卡」，细节隔离——用户可预期、可审计。

### 3.6 商业化分层配套

- **免费**：生活空间全量 + 工作空间基础会话（留存与传播引擎；娱乐内容自带截图传播性）；
- **订阅（Pro）**：工作空间高级能力——Project/worktree、审批流、评测门禁、多用户协作（M79）、仪式订阅数量上限放开；
- 一句话定位文案：**"白天帮你干活，晚上陪你生活的 AI 团队"**。

## 7. 风险与边界

| 风险 | 缓解 |
| --- | --- |
| 记忆隔离失效导致工作内容泄露到娱乐会话 | 隔离谓词单一实现于召回层（杜绝前后端双判）；审计页 + eval 断言常态化；全局提升必须显式且留 trace |
| 空间切换增加会话列表复杂度 | 默认折叠，首屏 ≤5 入口；⌘K 跨空间直达 |
| 生活推送打扰工作 | 通知策略 = 空间 × 时段二维分级，生活空间工作时段默认静默 |
| 双灵魂资产维护成本高 | check:agents 报告制而非门禁制；优先补 10 个高频跨域角色 |
| 商业化分层误伤免费体验 | 生活线永免费；工作线按"高级能力"而非"基础会话"收费 |
