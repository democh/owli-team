## 1. 背景与目标

### 1.1 现状与用户诉求

用户原话（两条）：

1. **「详细设计下塔罗相关的交互性和可玩性、趣味性，让用户能参与进去，比如随机选牌等等，请详细设计优化下，同时需要专业性」**
2. **「在设计好看的一套卡片效果，完整的，或者使用专业的卡牌」**

M69 交付后的塔罗场景现状：

- 抽牌是 **AI 单方行为**：用户发出问题 → tarot-reader 调 `tarot_draw`（seed 可复现）→ 回复内 `::: cards` 牌阵卡；用户全程只能「看」；
- 牌阵呈现为 **纯文字行**（`牌位 | 牌名 | 正逆位 | 关键词`），无牌面视觉——78 张象征符号系统失去了它的视觉本体；
- 既有参与先例：metaphysics 摇卦台（M54-C）已验证「**用户亲手完成仪式 → 交复现参数请解 → 工具复算逐位核对**」的闭环模式可行（TsToss 状态机 + 种子公开 + 请解回填草稿），且本地推导与工具逐位同源的工程约束已有成熟实现（`pan/coin.ts` ↔ `server/src/pan/gua.ts`）；
- 合规框架已就位：`agents/tarot/_protocol.md` 七条铁律 + 三条质量红线 + `pan/trail.ts` 明确「不做签到/连击/成就/排行」。

差距：**塔罗缺一个「摇卦台」**——且因牌阵（1/3/5 张）× 正逆位 × 78 张牌面视觉，塔罗的仪式交互上限远高于摇卦，应是全仓参与式交互的最强形态。

### 1.2 设计目标（验收导向）

| # | 目标 | 验收口径 |
| --- | --- | --- |
| G1 | 亲手抽牌全流程 | 用户可独立完成「提问 → 洗牌 → 切牌 → 亲手选牌 → 逐张翻牌 → 请解」，全程零 AI 参与 |
| G2 | 选择即结果（诚实参与） | 用户点选的位置直接决定牌（picks 进复现参数）；不存在「假随机装饰动效」 |
| G3 | 完整牌面视觉 | 78/78 张牌有视觉牌面（公版韦特位图；缺图自动回退程序化牌面，永不缺失） |
| G4 | 逐位可复现 | 用户所见牌面 = `tarot_draw(seed, cut, picks)` 复算结果（交叉测试向量锁定）；同参数重放逐位一致 |
| G5 | 专业性 | 牌阵牌位语义 / 正逆位中性口径 / 牌组构成事实 / 78 张图鉴研习，均为体系化知识承载 |
| G6 | 合规零违反 | 第 9 节自检表逐条通过；无恐吓、无付费暗示、无 gamification |
| G7 | 零回归 | m69 既有测试断言不破（第 12.4 节核对清单）；server 工具缺省行为与现行为完全一致 |

## 2. 设计总则

### 2.1 三层架构

```
┌─ 仪式层（新增 · 本文档）────────────────────────────────────┐
│ TarotRitual 抽牌台：静心 → 洗牌 → 切牌 → 亲手选牌 → 逐张翻牌 → 成阵  │
│ 产物：复现三元组（seed + cut + picks）+ 请解草稿（回填 Composer）    │
└──────────────┬──────────────────────────────────┘
               │ 请解草稿（不自动发送，ADR 0064）
┌─ 正式层（既有 · 零契约变更）─────────────────────┐
│ tarot_draw(seed, cut, picks) 复算 → ::: cards 卡 → 场景面板牌阵台   │
│ 四步解读（逐牌 → 关系 → 主题 → 参考区间）· 协议铁律全量适用          │
└──────────────────────────────────────────────┘
┌─ 视觉层（新增 · 本文档 §3）──────────────────────┐
│ 公版韦特牌面（client/public/tarot/rws/）+ 定制牌背 + 牌框/正逆位语言  │
│ 服务仪式层与图鉴；正式卡（cards 容器）保持文本行渲染不变            │
└──────────────────────────────────────────────┘
```

### 2.2 设计原则（八条）

1. **诚实参与**——用户点选的位置直接决定牌（`picks` 进复现参数）；不做「结果已定、动画演戏」的假交互；种子全程公开。
2. **逐位同源**——客户端推导（`deck.ts`）与 `tarot_draw` 同算法同常数；用户所见的本地牌面必须与工具复算一致；**正式解读一律以工具复算为准**（本地仪式展示交参数，不交结论——与摇卦台「报数不本地预测卦名」同一诚实边界）。
3. **中性牌面**——逆位无凶兆视觉（不用红色/警示色/裂纹）；负面牌名（死神/塔/恶魔）不配任何灾难化图标。
4. **仪式克制**——动效 ≤700ms；无音效、无彩带、无庆祝动画；quiet / reduced-motion 直出终态。
5. **零奖励机制**——任何形式的奖励、进度目标、解锁机制都不做；研习数据只以只读小字呈现（对照 `trail.ts` 口径）。
6. **完整兜底**——78 张牌面三级降级（位图 → 程序化 SVG 牌面 → 文字牌），任何环境任何时刻不缺失。
7. **本地私密**——手记与足迹存 sessionStorage（`ma:tc:*`），不落库、不上行。
8. **断言保护**——新增样式与类名一律走 `.tc-*` 命名空间，不复用 `.pn-*` / `.md-cards-*` / `.scene-cards-*`（后者已被测试锁定）。

## 3. 牌面视觉系统（用户诉求 2 的正面回应）

### 3.1 素材探测结论（2026-09-19 实测，先探测后下载纪律）

| 候选源 | 结果 | 说明 |
| --- | --- | --- |
| `commons.wikimedia.org` | ✗ 不可达 | TLS handshake timeout |
| `upload.wikimedia.org` | ✗ 不可达 | （历史结论，本次未复测） |
| `raw.githack.com` | ✗ 不可达 | 连接超时 |
| `api.github.com`（树 API） | ✓ 可达 | 仓库结构检索成功 |
| `cdn.jsdelivr.net`（gh 直链） | ✓ 可达 | 实测 HTTP 200 · image/jpeg |

**选定源**：`mixvlad/TarotCards` 仓库 `tarot/rider-waite/720px/`（经 jsDelivr 直链拉取）。

- 完整性：实测目录 **80 个文件** = 22 大阿卡纳（`00_Fool.jpg` … `21_World.jpg`）+ 14 圣杯 + 14 宝剑 + 14 权杖 + 14 星币（`Pents*.jpg`）+ `Cover.jpg` / `Cover_Rare.jpg`；
- 体积：原始 720px JPG 单张 **260–330KB**（实测 3 张），78 张约 22MB——**必须压缩后再落盘**；
- 授权：**公有领域**（Public Domain）——原画 Pamela Colman Smith（1878–1951），Rider & Company 1909 年出版，版权已过期；仓库 `SOURCES.md` 载明来源 Steve-P.org 高质量扫描与致谢要求；
- 静态直链验证：`Cover.jpg` 单次失败（偶发，脚本重试覆盖），其余 3/3 成功、1.0–2.0s 延迟。

### 3.2 资产规格

| 项 | 规格 |
| --- | --- |
| 落盘路径 | `client/public/tarot/rws/<slug>.jpg`（Vite 静态；dev 与 prod dist 同路径 `/tarot/rws/<slug>.jpg`） |
| slug 规则 | `major-00` … `major-21`；`wands-01` … `wands-14`；`cups-01` …；`swords-01` …；`pents-01` …（两位补零） |
| 映射 | 原仓库文件名 → slug → deck 索引（**附录 B** 全表；与 `tarot.ts` DECK 顺序一一对应） |
| 压缩 | `sips -Z 560 -s format jpeg -s formatOptions 70 <源> --out <目标>`：最长边 560px；目标 ≤80KB/张、总量 ≤6MB |
| 拉取脚本 | `tmp-fetch-tarot-cards.mjs`（临时脚本，先例 `tmp-fetch-instruments.mjs`）：jsDelivr 直链 + 逐张重试（≤3 次，退避 1s/2s/4s）+ 校验（HTTP 200 且 >5KB）+ 已存在跳过（断点续传）+ 收尾全量校验并输出缺图清单 |
| 失败处理 | 单张最终失败 → 不阻塞：该牌运行时自动回退程序化牌面（§3.6）；脚本输出缺图清单供人工补拉 |
| 许可登记 | `client/public/tarot/rws/README.md`：PD 声明（原作 1909、作者 Pamela Colman Smith）+ 来源仓库与 SOURCES.md 出处 + 致谢措辞（见附录 B） |
| 主题色 | 深紫底 `#2a0a4a → #3b0764`；金色描边 `#d8b4fe → #e9d5ff`；与场景 `theme: ["#3b0764", "#d8b4fe"]` 对齐 |

### 3.3 牌背设计（定制「星月紫金」）

不依赖任何外部资产（`Cover.jpg` 偶发失败、`Cover_Rare.jpg` 未确证为牌背），牌背以 SVG/CSS 绘制，确定性交付：

| 层 | 规格 |
| --- | --- |
| 底 | 径向渐变 `#241040 → #3b0764`（中心偏上光源感） |
| 边框 | 双线描金：外线 1.5px `#d8b4fe`（60% 透明）+ 内线 1px `#e9d5ff`（35%），间距 6px |
| 中心纹样 | 八角星（八芒）＋弯月组合 emblem，线宽 1.2px 描金，居中 |
| 点缀 | 四角小星点（每角 3 枚，1–1.5px 圆点，透明度 0.45/0.3/0.2）；星点避开中心安全带（缩放时不挤压） |
| 实现 | 内联 SVG 组件 `CardBack`（`viewBox 0 0 100 170`，`preserveAspectRatio` 自适应任意尺寸）；无外部请求 |
| 可选增强 | ImageGen 牌背纹理**样例已生成并留档**：`data/tc-back-v1.png`（1024×1792，深紫渐变 + 双线金框 + 八角星月 emblem + 四角星点，无文字，2026-09-19 目视验收通过）→ **批 B 已落盘** `client/public/tarot/back.jpg`（sips `-Z 896` / 质量 80，51KB）；实现改为**位图优先 + 加载失败回退纯 SVG**（避免双框叠加，比原「纹理叠 SVG」方案更简洁一致） |

### 3.4 牌面信息层（牌框版式）

揭示后的单张牌由「框 + 图 + 标注」三层构成（网格态只显示牌背）：

```
┌─────────────────┐
│ ① 牌位标（过去/现在/未来…）      │   ← 顶部 18px 胶囊标
│   ┌───────────┐  │
│   │  ② 牌面图   │  │   ← 公版韦特位图（object-fit: cover）
│   │           │  │      缺图 → 程序化牌面（§3.6）
│   └───────────┘  │
│ ③ 牌名（死神）        │   ← 16px 楷/宋风衬线（font-family 沿用全局栈）
│ ④ 正位 / 逆位 角标    │   ← 圆点 + 文字（中性色）
│ ⑤ 关键词（结束 · 转化 · 重生）  │   ← 12px 次要色，折叠态 2 行截断
└─────────────────┘
```

- 序号 ①② 与卡片同宽；③④⑤ 组成底部信息带（深紫 90% 透明底 + 上描边）；
- 关键词默认完整显示（1–3 个词，最多 2 行）；点牌展开「牌义抽屉」（关键词 + 花色域 + 牌位语义，见 §4.6）；
- 该版式同时服务：揭示态卡、成阵态卡、图鉴卡（三处复用同一 `TarotCardFace` 组件）。

### 3.5 正逆位视觉语言（中性口径）

| 状态 | 牌面图 | 边框 | 角标 | 说明 |
| --- | --- | --- | --- | --- |
| 正位 | 原样 | 实线 1px `#d8b4fe`（40%） | 「正位」文字 + 实心点 | 无额外装饰 |
| 逆位 | **180° 倒置**（真实塔罗语义：牌倒着放） | 虚线 1px `#d8b4fe`（40%） | 「逆位」文字 + 空心点 | 与正位仅此三处差异 |

**红线**：不使用红色 / 橙色 / 警示图标 / 裂纹 / 骷髅等任何凶兆化视觉；逆位与正位的信息层级完全对等（字号/对比度一致）。

### 3.6 三级降级链（78 张永完整）

| 级别 | 触发 | 呈现 |
| --- | --- | --- |
| L1 位图 | 正常 | 公版韦特 JPG（`loading="lazy"` + `decoding="async"` + 骨架占位） |
| L2 程序化牌面 | 图片 `onerror` / 文件缺失 / quiet 网络受限 | 内联 SVG「文字牌」：主题底 + 描金边框 + 罗马序号（大牌）/ 花色符号 + 点数阵列（小牌）+ 牌名 |
| L3 文字牌 | 测评环境 / SVG 禁用 | 与 `::: cards` 行同构的文本（牌名 | 正逆位 | 关键词） |

- L2 的「点数阵列」按花色语义排布（权杖/宝剑 = 竖排；圣杯 = 弧形；星币 = 菱形），10 个数字各有固定布局——与马赛体系 pips 传统呼应（**体系正确性**而非装饰趣味）；
- 降级是逐卡的（单卡失败不影响其余），且不影响复现参数与请解链路（链路只依赖 seed/cut/picks 与 78 张表，与图片无关）。

### 3.7 尺寸令牌与响应式

| 场景 | 尺寸（宽×高） | CSS 变量 |

| 选牌网格（78 格） | 56×96（桌面）/ 44×76（窄屏） | `--tc-w-grid` |

### 3.8 动效系统

| 动效 | 规格 | reduced-motion / quiet |
| --- | --- | --- |

- 弹窗沿用摇卦台模态规格：Portal 到 body、焦点陷阱 + Tab 环回、Escape 关闭、遮罩点击关闭。

## 4. 抽牌台交互详设（TarotRitual）

### 4.1 状态机

```
idle ──开始洗牌──▶ shuffle ──洗牌（≥1 次）──▶ cut ──选堆置顶──▶ draw
  ▲                  │                                          │
  │                  │（关闭/刷新按进度恢复）                     │ 选满 N 张
  └──重新洗牌（新种子）◀── complete ◀──全部翻开── reveal ◀──揭示──┘
```

| 阶段 | 快照字段（`ma:tc:ritual`） | 主动作 | 播报 |
| --- | --- | --- | --- |
| idle | `{ stage, spread, question }` | 开始洗牌（生成仪式种子） | — |
| shuffle | `+ { seed, shuffleCount }` | 洗牌 → 切牌 | 「已洗牌，请切牌」 |
| cut | `+ { cut }` | 点选一堆置顶 | 「已切牌」 |
| draw | `+ { picks[] }` | 点选第 k 张 / 撤销 | 「已选第 2 张，还需 1 张」 |
| reveal | `+ { revealed }` | 翻开第 k 张 / 全部翻开 | 「过去位已揭晓：死神，逆位」 |
| complete | — | 请解 / 重放 / 重新洗牌 | 「牌阵已成」 |

- 快照只存**参数与进度**（seed/cut/picks/revealed/shuffleCount），牌面恒由 `seed+cut+picks` 现推（与摇卦台「只存种子与进度」同口径）；
- 关闭 / 刷新 / 面板卸载后重开：按 stage 恢复到对应阶段（draw 阶段恢复已选槽位，牌背网格重新呈现）；
- 恢复路径不触发 `onRitual`（足迹记账只在真实动作发生时）。

### 4.2 阶段交互规格

**阶段 1 · 静心（idle）**

- 牌阵选择（三选一卡）：单张「今日一牌 · 当下指引」/ 三张「过去 → 现在 → 未来」/ 十字阵「核心 / 横越 / 根基 / 过去 / 未来」（每卡附一句牌位语义，专业）；
- 所问输入（可选，≤80 字，placeholder「例：最近这段时间该把注意力放在哪里」）；
- 边界提示（小字常驻）：「一次一个清晰的问题；涉及健康 / 法律 / 财产请咨询专业人士」；
- 主按钮「开始洗牌」；次按钮「今日一牌」（直接进单张模式，所问留空）。

**阶段 2 · 洗牌（shuffle）**

- 78 张牌背叠成的牌堆视觉（3 叠错位）；
- 主按钮「洗牌」（每次点击播放 700ms 交错动画，`shuffleCount+1`；≥1 次后按钮变「切牌」）；
- 种子公开行：「种子 {seed}」+ 说明「与研习师工具逐位同源，可复现」；
- 洗牌动作不消耗随机数（seed 在进入本阶段时一次性生成）——**洗牌次数不进复现参数**（诚实：动画是仪式，不是随机源）。

**阶段 3 · 切牌（cut）**

- 三堆牌背（各 26 张）横向排列；
- 提示「凭直觉把一堆放到最上面」；点选 → 合拢动画 → `cut = {0|1|2}`；
- 语义（专业）：切牌在传统仪式中用于「切断并重组牌序」，本实现等价于牌堆旋转（堆 0 置顶 = 保持原序）；
- 键盘：按钮组，Tab + Enter 可选。

**阶段 4 · 亲手选牌（draw）·核心**

- 78 格牌背网格（13×6，全部背面朝上）；hover/focus 抬起；
- 顶部进度：「凭直觉点选 3 张 · 已选 2/3」+ 当前牌位语义提示（选第 1 张时提示「第 1 张 = 过去：事情的来处」）；
- 右侧/底部牌位槽列：与所选牌阵的牌位一一对应（未选为虚线空槽，已选显示牌背缩略 + 「第 k 张已选」）；
- 点选即时反馈：该格牌背变暗 + 槽位落位动画 + 播报；**不提前翻面**（选牌与揭示分离，保留仪式节奏）；
- 「撤销上一张」按钮（仅撤销最后一支，保序撤销）；选满后「撤销」仍可用（撤销后回到选牌态）；
- 选满 N 张 → 主按钮变「揭示牌面」；
- 网格位置映射：**格 k ↔ 旋转后牌堆索引 k**（picks 直接记录格位索引，简单可复现）。

**阶段 5 · 逐张翻牌（reveal）**

- N 张牌呈牌阵布局（1 张居中 / 3 张横排 / 5 张十字）——与 CardsBoard 布局同构（复用布局类名 `.tc-spread.is-3` 等，**不复用** `.scene-cards-*`）；
- 逐张翻：点击某张牌或主按钮「翻开第 k 张」→ 600ms 3D 翻转 + 逆位落定 → 显示牌面（§3.4）与播报；
- 「全部翻开」快捷（串行 80ms 错峰动画）；
- 每张翻开后下方浮现对应牌位语义一句（专业承载：「过去位 = 事情的来处与因由」）；
- 全部翻开 → 自动进入 complete。

**阶段 6 · 成阵（complete）**

- 牌阵完整展示（详见 §3.4 版式）；
- 信息行：`所问：…` ｜ `牌阵：三张牌阵` ｜ **复现参数**：`种子 123456 · 切牌 2 · 选牌 [7, 23, 61]`；
- **牌组构成（事实行，专业承载）**：`构成：大阿卡纳 2/3 · 元素 火 1 水 1 风 1`（只列事实分布，不给解读判断——解读归观照四步法）；
- 按钮组：
  - 主：「请观照解读」→ 回填草稿（附录 A 文案 1），关闭弹窗；
  - 次：「同参数重放」（恢复成阵态，展示「本组牌与请解记录逐位一致」）——复盘与演示；
  - 次：「重新洗牌（新种子）」→ 回 idle 并保留所问与牌阵选择；按钮副文案一行纪律提示：「重抽不改写结果；对牌面不满时，换问法更有用」；
  - 次：「收进手记」——**默认自动记录**（成阵即入 `ma:tc:journal` 会话手记），此按钮实为「打开手记」入口；
- 底栏固定边界声明：「文化研习参考，不构成决策依据」（协议质量红线 3）。

### 4.3 复现参数展示与请解链路

- 复现三元组全程可见（shuffle 阶段起种子常显；complete 全量展示）；
- 请解草稿（模板见附录 A）**带全参数 + 逐位核对条款**：「若复算牌面与我所见不一致，请指出并说明」——理论不应发生（§6 交叉测试锁定），该条款是诚实兜底；
- 用户在 Composer 中可编辑后自行发送（ADR 0064）；AI 复算 → 正式 `::: cards` 卡 → 面板牌阵台（既有链路，零改动）。

### 4.4 键盘与快捷键

| 键 | idle | shuffle | cut | draw | reveal | complete |
| --- | --- | --- | --- | --- | --- | --- |
| 空格 / Enter | 开始洗牌 | 洗牌 | —（Tab 选堆） | —（网格内 Enter 选牌） | 翻开下一张 | 请解 |
| ←↑↓→ | — | — | ←→ 切堆 | 网格移动 | ←→ 换牌 | — |
| Backspace | — | — | — | 撤销上一张 | — | — |
| Escape | 关闭（进度保留） | 同左 | 同左 | 同左 | 同左 | 同左 |

### 4.5 文案纪律

- 全部界面文案使用「研习 / 镜鉴 / 牌阵 / 请解」词汇；禁用「占卜 / 算命 / 预测」；

## 5. 工具契约扩展（`tarot_draw`）

### 5.1 参数扩展（向后兼容）

| 参数 | 类型 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `spread` | `'single' \| 'three' \| 'cross'` | 必填 | 不变 |
| `seed` | `number` | 随机 | 不变 |
| `question` | `string` | 可选 | 不变 |
| **`cut`** | `0 \| 1 \| 2` | `0` | 切牌：堆 c 置顶（等价牌堆旋转）；0 = 原序 |
| **`picks`** | `number[]` | `[0..N-1]` | 亲手选牌：格位索引序列（长度 = 牌阵张数） |

### 5.2 算法逐位规格（新 → 与缺省旧行为逐位一致）

```
1. seed := 入参或随机（1..0x7fffffff）
2. rand := mulberry32(seed)                     // 与 dice_roll / gua_pan 同实现，常数勿改
3. deck := 78 张全表副本
4. Fisher-Yates 洗牌：i = 77 → 1，j = floor(rand() * (i + 1))   // 77 次 rand
5. 78 张逐张定正逆位：orient[k] = rand() < 0.5 ? '逆位' : '正位'   // 78 次 rand（第 78..155 次）
6. cut 旋转：cut=1 → deck[26..51] + deck[52..77] + deck[0..25]；cut=2 → 同理（26 张一堆）
7. 取牌：card[i] = deck[picks[i]]，orientation[i] = orient 随牌（步骤 5 所定）
8. 输出 cards（牌位序 = picks 顺序）、seed、cut、picks
```

**兼容性证明**（对现有 golden 的不变量）：现有实现取「洗牌后前 N 张」并为每张按 `rand()` 序定逆位——即位置 k 的逆位取自第 78+k 次 rand；新实现步骤 5 一次性为 78 张定逆位，位置 k 同样取第 78+k 次 rand。缺省 `cut=0`、`picks=[0..N-1]` 时两者**逐位相同**——既有 golden（`seed=456 → 死神·逆 / 星币国王·逆 / 宝剑七·逆`）必须保持通过，作为批 A 第一道门禁。

### 5.3 校验规则

| 输入 | 规则 | 错误信息 |
| --- | --- | --- |
| `cut` | 整数 0–2；越界拒绝 | `切牌参数须为 0 / 1 / 2` |
| `picks` | 数组；元素为整数 0–77；**互不重复**；长度 == 牌阵张数 | `选牌参数无效：须为不重复的 0-77 整数，且数量等于牌阵张数（3）` |
| `picks` 缺省 | 自动 `[0..N-1]` | — |

### 5.4 输出与卡模板

- `summary` 追加复现参数：`抽牌完成：三张牌阵（死神·逆 / 命运之轮 / 星星；种子 456 · 切牌 2 · 选牌 [7,23,61]）`；
- `detail` 中 `牌序` 行下追加 `复现：种子 456 · 切牌 2 · 选牌 [7,23,61]`（「携带 seed / cut / picks 重抽逐位复现」）；
- **`::: cards` 卡模板不变**（行契约 `- 牌位 | 牌名 | 正逆位 | 关键词`）——面板与消息卡零改动；
- tier / readOnly / 白名单（tarot 全员）不变；工具数不变（无需工具可达性体检，扩展现有工具）。

## 8. 研习设施（手记 · 图鉴 · 足迹）

### 8.1 手记（TarotJournal）

- 自动记录：每次**成阵**即写入 `ma:tc:journal:<sessionId>`（无需手动收藏）；
- 条目结构：`{ id, at, question, spread, seed, cut, picks, asked }`——**只存参数不存牌面**（牌面恒由参数现推，存储最小化）；
- 列表：时间倒序；按日期分组；当天首个 `single` 条目挂「今日一牌」小标（无连续天数、无提醒）；
- 条目操作：「重放」（恢复成阵态，等同 §4.2 的同参数重放）/「再请解」（回填草稿）/「删除」（二次确认）；
- 条目展示：牌阵缩略（N 张小牌背 → 翻开态用位图缩略）+ 所问摘要 + 复现参数一行。

### 8.2 图鉴（TarotCodex）

- 78 张全表（`deck.ts` 单一数据源），分组导航：大阿卡纳 / 权杖 / 圣杯 / 宝剑 / 星币；
- 每张卡：位图缩略（缺图回退程序化）+ 名称（大牌附罗马序号）+ 三关键词 + 花色域词；
- 「遇见」计数从手记派生（去重牌名数），以只读小字呈现：`遇见 11/78 张`（对照 `trail.ts` 口径，**不做进度条/成就/解锁**）；
- 点卡展开详情：关键词 + 花色域 + 牌位语义通识；「问这张」→ 回填草稿（附录 A 文案 4）。

### 8.3 研习足迹

- 从手记派生，抽牌台/手记页脚只读小字：`抽过 3 阵 · 遇见 11/78 张 · 请解 2 次`；
- 无奖励、无提醒、无续期机制；空态不渲染。

## 13. 风险与被否决

### 13.1 风险与对策

| 风险 | 对策 |
| --- | --- |
| 图源后续不可达（jsDelivr 波动） | 拉取为**一次性预置**（落盘后运行时零依赖）；失败清单可分批补拉；L2/L3 降级兜底 |
| 压缩后清晰度不足 | 560px 上限 + 质量 70 起步；走查期目视验收，必要时提高至 640px（体积换质量） |
| 78 张体积过大 | 目标 ≤6MB；逐张 sips 压缩；图鉴缩略复用同图（CSS 缩放，不另存缩略图） |
| 本地与工具复算不一致（工程事故） | 交叉向量测试锁死；请解草稿带「不一致请指出」条款；批 A 门禁先行 |
| 抽牌台复杂度失控 | 状态机六阶段封闭（无自由分支）；快照只存参数；组件按 §10.1 拆小文件 |
| 断言冲突 | `.tc-*` 命名空间隔离 + §12.4 前置核对清单 |
| 合规漂移（趣味性滑向 gamification） | §9「不做」清单实施期逐条复核；评审以本文件为准 |

### 13.2 被否决方案

| 方案 | 否决原因 |
| --- | --- |
| Wikimedia Commons 直连下载 | 实测不可达（TLS 超时）×2 源 |
| 运行时直链 CDN（不落盘） | 离线不可用、波动不可控，违背「素材预置」惯例 |
| ImageGen 生成 78 张牌面 | 78× 成本、风格一致性不可控、经典牌义细节易错 |
| 纯 CSS/emoji 文字牌面作为主方案 | 用户明确要求「好看完整 / 专业卡牌」；文字牌降为 L2/L3 兜底 |
| 用户点选不影响结果（假交互） | 违背「诚实参与」原则；被用户感知即为信任事故 |
| 加入音效 / 庆祝动画 / 成就徽章 | 无先例 + 合规红线 |
| 凯尔特十字等新牌阵本批引入 | 范围失控；列二期开放点 |

### 13.3 开放点（二期候选）

1. 凯尔特十字（10 张）与二选一阵（5 张）牌阵扩展（工具 SPREADS + 布局 + 协议）；
2. 手记跨会话持久化（localStorage）——复盘价值 vs 「本地私密」口径的权衡；
3. RWS 平行牌面（Sola Busca / 马赛）切换（样张已在源仓库，授权均为 PD）；
4. 图鉴「牌义小测」练习模式（学习向，非奖励向）；
5. 双子阵对照（同问题两轮并排，复用 `::: cols` 先例）。
