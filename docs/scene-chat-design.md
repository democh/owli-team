## 1. 背景与目标

### 1.1 问题

17 个场景组（strategy / development / sre / brainstorm / research / marketing / sales / finance / bi / ops / funding / health / learning / travel / wealth / home / personal）在对话区几乎同构：线性消息流 + 气泡。现有场景差异只有三处：

1. 空态文案（仅 development / brainstorm / research 三个场景有专属标题，其余回退通用文案）；
2. 主题色（空态图标底色、消息卡左缘条、Composer 组色圆点）；
3. 并行组（仅 parallel 场景自然出现）。

而场景协议（`agents/*/_protocol.md`）里其实已写好了完全不同的「语汇」：头脑风暴的发散/收敛期与点子编号、研究的「事实/推断/观点」三分法与来源五要素、SRE 的分级止血与复盘、财务的金额必须 calc 口径纪律——这些语汇在对话区没有任何承接。

### 1.2 目标与验收（验收导向）

| 目标 | 验收标准 |
| --- | --- |
| 保线性事实源 | 消息序列 / Run 恢复 / SSE 重附着 / fork / 压缩 / 导出语义零变化；场景增强全部为视图层增量 |
| 场景可辨识 | 17 场景对话区具有可辨识的专属形态（空态、分隔、卡片语汇），同一操作在任意场景不破坏既有渲染路径 |
| 有交互 | 卡片可点选/勾选/回填（统一回填语义）；关键节点（计划、裁决、签收、打卡）可操作 |
| 有仪式感 | 开工/收尾/里程碑有轻量仪式（安静模式全部可关闭） |
| 零回归 | typecheck / lint / 双端测试 / build / check:agents / eval mock 基线 / E2E 全绿；主包 gzip 增量受控 |

### 1.3 定位与边界（与既有资产切割）

| 既有 | 定位 | 与本专项的关系 |
| --- | --- | --- |
| WaveGroup（M16 并行波次组） | 波内多成员成组渲染 | 本专项在其上加 `layout` 家族（grid / duel），不改分组逻辑与结构键契约 |
| 评审范式（M24，ReviewRecord verdict/findings） | 结构化评审判定 | 本专项以 PK 判定卡承接渲染，不改范式与工具语义 |
| 定时任务（M35，定时徽章/注入消息） | 时间驱动协作 | 本专项消息头预留徽章槽位，避免二次改头布局 |
| 金融投研专项（M34，多空博弈模拟） | 金融专业分析工具（建模/计算/可视化，产出均衡解与分布） | **职责切割**：M34 博弈是「算出来的结论」；本专项 PK 是「对话过程的呈现与裁决」。两者互补：M34 的博弈结果卡可作为 PK 场景的一种可视化承接（其自身设计见 finance-invest-design.md） |

## 3. 设计原则与全局约定

### 3.1 红线与纪律（所有里程碑适用）

1. **线性主干不变**：一切场景化体验为视图层派生；不为视觉分叉消息数据层（可回放/可追溯/可导出建立在消息序列上）；
2. **流式纪律（ADR 9 延续）**：新卡片流式期间降级为纯文本，完成态才挂载重组件；
3. **结构键契约**：`ChatArea.deriveRows` 仅依赖 `role~runId~turnIndex` 结构键——任何依赖消息内容的聚合不得做成独立虚拟行（挂消息内或波次组附属）；
4. **安静模式与 reduced-motion**：所有新动效登记 `client/src/index.css` 的 `.quiet-mode` 清单；
5. **统一回填语义**：卡片点击只写 Composer 草稿（composerInsert），由用户确认发送；交互态（勾选/点亮/打卡）存 sessionStorage，不落库；
6. **静默降级**：无容器/无标记/解析失败一律回退原文渲染，绝不报错、绝不空白；
7. **文案口径**：遵循全站精简口径（删解释性描述，保留状态与危险提示）；不渲染用户头像。

### 3.2 渲染契约模板（后续所有契约按此填写）

| 字段 | 含义 |
| --- | --- |
| 定位 | 消息内嵌 / 波次组附属（完成态）/ 悬浮条 / 新增虚拟行 |
| 触发 | 场景 + 精确条件（消息字段、toolCall 名、容器标记） |
| 来源 | 数据派生路径（优先纯前端；协议容器次之） |
| 呈现 | 布局、交互、配色 token（`group.theme`） |
| 降级链 | 流式→纯文本；解析失败→原文；quiet/reduced-motion→静态；窄屏→收起 |
| 复用 | 既有组件/通道（focusMessage、composerInsert、AgentAvatar、WaveGroup…） |

### 3.3 文档与编号纪律

- 每个里程碑实施时：design.md 新增章节（§52 起）+ `docs/adr/<006x>-*.md` 落盘 + design.md §11 索引追加；改动协议时追加 `agents/CHANGELOG.md` 并附 eval 结果；
- **编号为预定值**：动手前核对仓库最新章节 / ADR 编号；若被并行工作占用，按「让位 + 更新本文件」处理（历史先例：多会话并行编号冲突）；
- 无 Git 仓库：每里程碑动手前做目录快照备份（清理/回滚不可恢复）。

### 3.4 全局验收门禁（每个里程碑）

四包 typecheck / lint 全绿；双端 vitest 全量；`npm run build`（记录主包 gzip 增量）；`npm run check:agents`（改动资产时）；`npm run eval` mock 基线无回归（改动 mock/协议时先 `--update-baseline` 并复核）；E2E 对应新增 spec + 相邻既有 spec 回归。

### 11.4 与 M34 金融投研「多空博弈模拟」的边界

M34（docs/finance-invest-design.md）的博弈是金融专业分析能力：静态矩阵/序贯/演化/ABM 蒙特卡洛 → 均衡解与路径分位，属「计算结论 + 专业可视化」；本范式是「对话对抗过程的呈现与裁决」。二者互补：若 M34 落地，其博弈结果卡（均衡解/参数重跑）可作为 M43 输出侧的一种专业承接，但渲染契约与触发口径独立（走容器 `::: debate` / `::: game` 演进），不在本专项内实现。

## 14. 风险登记

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 内容聚合击穿虚拟列表重渲染隔离 | 性能回退 | ADR 0067：聚合只挂波次组完成态；代码评审硬检查项 |
| 协议容器输出不稳定（模型不用容器） | 面板不出现 | 协议显式示例 + mock/eval 断言；无标记静默降级 |
| 新动效破坏安静模式 | UX 回退 | 每个动效登记 `.quiet-mode` 清单 + reduced-motion 用例 |
| 包体（主包 gzip 已 229.95KB 超 150KB 门槛） | 欠账扩大 | 大件（kanban/回放/聚合面板）懒加载；每里程碑记录增量 |
| 并行会话编号冲突 | 文档错乱 | 动手前核对最新编号；「让位 + 更新本文件」 |
| 无 Git，回滚不可恢复 | 事故放大 | 每里程碑动手前目录快照备份 |
| 本地态（勾选/点亮/打卡）残留 | 数据卫生 | 键统一 `ma:*`；会话删除清理；不进导出 |

**收缩策略**：任一里程碑超预算时，优先保「契约表前 2 项 + 全部降级链」，其余延后到该里程碑 .1 补丁，保持章节完整、实现分批。
