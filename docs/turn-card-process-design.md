## 1. 背景与目标

### 1.1 用户诉求

用户原话：

> 「Agent 对话太啰嗦了，有些思考的是不是可以隐藏，这个不是大模型的思考，是否可以详细设计下相关的，将消息 turncard 进一步进行设计」

关键澄清（决定了本方案的落点）：截图中的「我听到的是…／我先把这轮记下来…／先不做分析…」**不是 reasoning 通道内容**——思考块（ReasoningBlock）只折叠 `message.reasoning`，折叠不到它们；它们走的是 **content 通道**，而 content 目前完全没有分层能力，只能逐段铺开。

### 1.2 现状盘点（证据）

| 项 | 现状 | 位置 |
| --- | --- | --- |
| 消息三通道 | `reasoning` / `content` / `toolCalls`；思考与工具各有折叠，**content 无分层** | `client/src/components/chat/MessageItem.tsx` L427–466 |
| 折叠范式 | 「流式展开 / 回合结束折叠一次 / 用户 touched 后不再干预」 | ReasoningBlock（MessageItem L92–138）· ToolCallsPanel（`client/src/components/chat/ToolCard.tsx` L171–221） |
| 容器管线 | 单解析实现 `::: ` 语法（栈式组装 / fail-safe / 缓存安全） | `client/src/components/chat/md-ext/remark-ext.ts` L1–63 · L2052–2108 |
| 折叠先例 | `::: details` 原生折叠块；tarot 协议已写「过程 `::: details` 折叠」 | `remark-ext.ts` L649–660 · `agents/tarot/_protocol.md` 条目 11 |
| 协议现状 | `<style_channels>` 只定义三通道（发言 / 交接 / 交付件），无「过程叙述」；无复述去重约束 | `agents/_protocol.md` L8–19 |
| 症状场景 | 陪谈类声纹要求「开口先复述」→ 多轮重复整段复述 + 内部动作自述 | `agents/wellness-mind/emotion-companion/voice.md` |
| 适用范围（v2 实测） | **40 场景 / 161 角色 / 24 声纹 / 70 技能**；19 份协议已有「渲染容器约定」（另 2 份内联引用：astrology / metaphysics）、19 份零容器引用；逐份审核见 §6 与附录 C | `agents/`（2026-09-23 实测计数） |

### 1.3 目标与非目标

**目标**

1. content 通道补齐第三类可折叠「过程叙述」，与思考、工具调用组成统一「过程族」；
2. TurnCard v2 结构：抬头 → 过程区（思考 / 工具 / 过程三件，固定序）→ 正文 → 交付件，正文成为唯一主角；
3. 源头降噪：协议定义「过程叙述」通道 + 复述去重 + 「安全提示不得折叠」红线；
4. **全量覆盖（v2）**：40 场景协议 40/40 铺设 + 161 角色逐份审核（3 改 1 免）+ 24 份声纹 / 70 份技能审计（§6、附录 C）+ check:agents 覆盖门禁（防未来新场景遗漏）；
5. 零回归：既有消息、断言、构建门槛（文件 ≤ 50 / 主包 gzip ≤ 150KB）、渲染缓存纪律全不破。

**非目标**

- 不做前端启发式叙述识别（误伤风险，被否决，见 §11）；
- 不改消息数据模型与 WS 契约（零 server 契约变更，仅 mock 剧本一条）；
- 不做「过程内容彻底不渲染」（信息可回溯优先）；
- 不改 `message.reasoning` 通道语义与既有文案（「已深度思考 · N 字」「工具调用 · N」原样保留）。

## 2. 设计总则

1. **只改呈现密度，不改信息完整性**：过程默认收起、按需展开、原文不丢。
2. **分层标记由 Agent 显式承担**：容器边界即语义边界；渲染端不做语义猜测（误伤陪谈复述这类核心内容比"漏折叠"更不可接受）。
3. **单一解析实现**：`::: process` 走既有 remark 容器管线；「过程上提」在同一次 mdast 遍历的收尾完成，不新增第二套字符串扫描器。
4. **范式对齐**：新折叠块加入既有范式（流式展开 / 完成折叠一次 / touched 优先），不引入第三种折叠行为。
5. **fail-safe 优先**：未闭合 → 内容展开回正文；代码块内不解析；空块不渲染；未知容器名保持原文。
6. **零新依赖**：客户端仅 +1 组件文件 + 1 CSS 块；协议改动全部为 `agents/` 文本资产。

## 3. 「过程叙述」定义与协议通道

### 3.1 定义（判定口径）

判定问题：「删掉这句话，用户是否损失行动所需的信息？」——损失 → 留正文；不损失 → 入容器。

**入 `::: process`（过程叙述，三类）**

| 类 | 例 |
| --- | --- |
| 内部动作自述 | 「我先把这轮记下来，等你补几句我再往下走。」「来源只写你原话里出现过的线索。」 |
| 方法论旁白 | 「先不做分析。」「我不替你猜。」 |
| 进度自述 / 动作预告（第二句起） | 「先看一遍现有文件再动笔，再核对交付契约。」 |

**留正文（禁止入容器）**

- 复述确认（**首次**）；
- 澄清问题 / 建议 / 结论 / 动作清单 / 提问；
- 交付与落盘声明（「方案已写入 `docs/照护方案-母亲.md`」——短句）；
- **安全与合规提示**（危机干预热线、就医建议、免责声明）——**最高红线，必须正文置顶、不得折叠**。

### 3.2 复述去重（源头治理核心）

同一事实整段会话只复述确认一次；后续轮次直接进入新增澄清或动作。这是对截图症状（「我听到的是…」数轮重复出现）的根因治理。

**豁免机制**：场景协议另有规定者从其规定——如 philosophy 苏格拉底场景的「复述以求定义精确」是教学法本体，显式豁免（写入该场景协议，作为机制先例）。

### 3.3 硬约束（协议层，写入全局契约）

- ≤ 3 句 / 回合；放发言末尾（过程收尾）；
- 容器内不写 @（沿用 society / tarot 既有约定）；
- 不复述正文内容；不得把正文与安全提示搬进容器；
- 违例降级：漏包 → 按正文渲染（与现状一致，不报错）；误包正文 → 渲染仍是可展开的折叠块（信息不丢）。

## 4. `::: process` 容器与渲染详设

### 4.1 语法

```
::: process [标题（可省，默认「过程」）]
过程叙述文本（段落 / 短句 / 列表均可）
:::
```

- 开标记直接命中既有 `OPEN_RE`（`^:::(?!:) name [参数]$`，name = `process`），零语法扩展；
- 与 `::: details` 的分工：`details` = 通用展开（参考资料 / 附录）；`process` = 语义化过程（默认收起 + 字数统计 + 流式跟随 + 上提归位）；
- 模型误用 `details` 写过程 → 渲染仍是折叠块，属可接受降级（不报错、不迁移）。

### 4.2 解析与上提（`client/src/components/chat/md-ext/remark-ext.ts`）

1. `makeBuilder('process')` → `{ type: 'mdProcess', hName: 'div', hProperties: { className: ['md-process'], 'data-process': '', data-title? } }`；
2. `finalize` 分支：`mdProcess` 保留 children（不拆 summary/body——摘要行由 React 组件渲染）；同时在收尾时递归统计容器内文本长度写入 `data-chars`（确定性、缓存安全）；
3. **上提（hoist）**：walk 收尾、`parent.children = out` 赋值之前，对根级节点做一次稳定分区——顶层 `mdProcess` 节点按原序移到 `out` 头部，其余节点保持原序；**仅顶层**（嵌套在 `::: cols` 等容器内的 process 原地渲染）；
4. `Markdown.tsx` 侧：`MdDivProps` 增补 `'data-process'?: string`、`'data-chars'?: string`；`MdDiv` 命中 `data-process` → `<ProcessBlock title chars>{children}</ProcessBlock>`（批 A 同步更新 `Markdown.tsx` 头部注释的容器清单，把 `process` 记入「流式期间直接渲染的轻结构容器」）。

### 4.3 ProcessBlock（新组件 `client/src/components/chat/md-ext/ProcessBlock.tsx`）

- **摘要行**：`过程 · {N 字}`（有自定义标题 → `{title} · {N 字}`）+ chevron（`rotate-180` 过渡），图标 `Footprints`（备选 `ScrollText`，lucide 现有依赖零新增）；
- **交互范式**（严格对齐既有两位成员）：
  - 初始 `open = streaming`（流式跟随展开）；
  - `useEffect`：`!streaming && !touched` → 收起一次；
  - 点击置 `touched` + 切换，此后不再自动干预；
- **展开体**：muted 面板（`border-l-2 border-primary/25 bg-primary/[0.04]`，12px / leading-5，同 ReasoningBlock 视觉），内容为容器 mdast children 的正常 Markdown 渲染（轻结构容器流式直渲染口径）；
- **锤点（E2E / 单测）**：`.md-process` / `.md-process-summary` / `.md-process-body` / `data-process` / `data-process-chars`；
- 空容器 → 组件返回 `null`（不渲染空行）。

### 4.4 边界与 fail-safe（逐条）

| 情形 | 行为 |
| --- | --- |
| 未闭合（流式中途） | 内容展开回正文（既有 expand 通用逻辑，标记行不显示）；闭合后归位过程区——单次重排，容忍（§11 风险 2） |
| 代码块内出现 `:::` | 不解析（既有 `isPureText` 规则天然覆盖） |
| 多个 process 块 | 多行摘要，按文中原序上提 |
| 空块 / 仅标题 | 不渲染 |
| 嵌套在其他容器内 | 不参与上提，原地渲染为折叠块 |
| 容器内含列表 / 引用 / 强调 | 正常渲染（mdast children 全保真） |
| 容器内含 @ | chip 正常渲染；交还语义不受容器影响（协议约定不写） |

## 5. TurnCard v2 结构详设

### 5.1 现状 → 目标

**现状**（MessageItem agent 分支 L427–466）：

```
[turn-card] turn-accent / turn-progress
  ReasoningBlock → ReviewVerdictCard → Markdown(content) → ToolCallsPanel → 交付件
```

**目标**：

```
[turn-card] turn-accent / turn-progress
  过程区（固定顺序，各项缺省不占位；三件合称「过程族」）
    ① ReasoningBlock   —— 文案与行为不变（「正在思考」「已深度思考 · N 字」）
    ② ToolCallsPanel   —— 文案与行为不变（「工具调用 · N」）
    ③ .md-process 行   —— 上提后位于 markdown 头部（可多行，原序）
  正文（Markdown 其余内容）
  评审卡（ReviewVerdictCard，评审范式）—— 移至正文之后（结论件归位，见下）
  交付件（ChangeCard / DeliveryFiles）
```

- 过程区三件仅在存在时渲染（无空态占位）；
- 正文与过程区的间距/分隔为 CSS 细节（批 A 走查精修）；
- 「正在酝酿…」与打字光标条件不变（光标仍锚正文末尾）；
- 错误 / 停止态边框规则不变（`border-destructive/40` / `border-amber-500/40`）。

### 5.2 两处位置变更（存量消息的全部视觉变化）

| 变更 | 前 | 后 | 理由 |
| --- | --- | --- | --- |
| 工具调用面板 | 正文之后 | 正文之前（过程族内） | 与思考/过程同族，过程信息集中收口 |
| 评审判定卡 | 正文之前（思考之后） | 正文之后（正文与交付件之间） | 判定属结论件，紧随被评审的正文；抬头已有评审徽章，语义不丢 |

已核验：m24-plan E2E 只断言 `.review-verdict-card` 存在 / `data-verdict` / 文案，不锁位置；m43-cards 单测同理。

### 5.3 流式行为逐条

- 三项各自沿用/对齐范式；`streaming` 为消息级单调标志（回合结束才变 false），区内多项不会抖动；
- 上提在每次节流渲染（150ms）执行，开销为一次 O(n) 数组分区；
- 流式期未闭合的 process 以正文形态呈现，闭合瞬间归位过程区（一次重排）。

## 6. 协议与资产修订清单（全量覆盖，批 B）

### 6.1 `agents/_protocol.md`（改写草案，决策完整）

`<style_channels>` 表格追加一行：

| 通道 | 文体 | 约束 |
| --- | --- | --- |
| 过程叙述（可折叠） | 短句自述：动作预告 / 检索与记录说明 / 进度自述 / 方法论旁白 | 统一收进 `::: process` 容器（≤3 句、放发言末尾、容器内不写 @）；渲染端默认收起为一行「过程」；禁止把正文与安全提示搬进容器 |

表格后的 bullet 区追加两条：

- 复述确认属于对话发言：仅在用户给出新信息时复述，同一事实整段会话不重复确认（场景协议另有规定者从其规定）；
- 安全与合规提示（危机干预 / 就医建议 / 免责声明）与交付落盘声明永远留在正文，禁止折叠进 `::: process`。

既有「工具调用前后的说明句也是你的发言」一条微调：一句自然过渡留正文；**第二句起的自述 / 进度说明收进 `::: process`**。

### 6.2 场景协议全量铺设（40/40）

**插入规则（机械统一，可核验）**：40 份协议各新增小节 `## 过程叙述约定（界面承接）`，位置统一为 `## 质量红线` **之前**（40 份均含该小节，门禁依赖此规则）；既有「渲染容器约定」小节（19 份）与内联容器引用（astrology / metaphysics）**保持原位不动**。

**标准段模板（A 型，40 份全含）**：

```md
## 过程叙述约定（界面承接）

1. 过程叙述（动作预告 / 检索与记录说明 / 进度自述 / 方法论旁白）收进 `::: process` 容器——≤3 句、放发言末尾；界面默认收起为一行「过程」，正文只留对用户的话（结论 / 建议 / 提问 / 交付说明）。
2. 安全与合规类内容（危机提示 / 就医建议 / 免责与合规声明 / 风险提示）一律留在正文，禁止入容器。
3. 容器内不写 @（转交只在正文单独一行）。
```

**C 型增补（陪谈 / 情绪 4 场景：标准段 + 第 4 条）**：

| 场景 | 第 4 条 |
| --- | --- |
| wellness-mind | 复述确认只在用户给出新信息时出现，同一事实整段会话不重复；危机提示与安全问询严禁入容器、必须正文置顶（铁律 2 优先）。 |
| personal | 复述确认只在用户给出新信息时出现，同一事实不重复；危机信号转介提示留正文置顶（质量红线 1 优先）。 |
| care | 「非医疗诊断」声明与异常症状就医提示严禁入容器；用户自述信息的复述只对新信息发生。 |
| relationship | 危机转介提示严禁入容器、必须正文置顶；情绪复述只对新信息发生，同一感受不重复复述。 |

**B 型增补（复述属方法本体 4 场景：标准段 + 第 4 条豁免声明）**：

| 场景 | 第 4 条 |
| --- | --- |
| philosophy | 本场景的复述（澄清定义 / 确认理解）属方法本体，不进容器、不受「同一事实不重复」约束。 |
| metaphysics | 摇卦 / 报数的复算核对复述（本卦 / 变卦 / 动爻 / 世应）属核验本体，不进容器。 |

## 11. 风险与被否决

**风险**

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | 模型容器语法遵从率不足（漏包 / 漏闭合） | 未闭合 fail-safe 展开不报错；协议给正反例（附录 A）；mock + E2E 覆盖；全局契约 + 场景 pointed 双重提示 |
| 2 | 上提导致的布局跳动（未闭合 → 闭合瞬间归位过程区） | 单次、与工具面板收起同类；E2E 可观察；如走查不可接受，可退化为「不上提、原地折叠」（设计保留此退化路径，一行开关） |
| 3 | 复述去重在个别场景不适配 | 全局契约含「场景协议另有规定者从其规定」；philosophy 显式豁免作先例 |
| 4 | 工具行上移 / 评审卡后移为全局视觉变化 | 已核验断言只锁文案与属性不锁位置；批 C 截屏走查确认；如需回退仅两处 JSX 顺序 |
| 5 | 摘要行文案（「过程 · N 字」）与既有卡片风格不统一 | 与 ReasoningBlock / ToolCallsPanel 共用 `process-row` 样式类，走查复核 |
| 6 | **40 份铺设措辞漂移 / 遗漏**（"所有 agent"的核心风险） | 统一模板 + 插入位规则（`## 质量红线` 之前）+ check:agents 门禁（40/40）+ 附录 C 逐条核验 |
| 7 | 协议 token 增量（每份 +4 行） | 位于 per-agent 稳定前缀（prompt cache 命中），约 +40 token/回合，成本可忽略；批 B 实测预算 |
| 8 | 门禁与铺设不同批落地 → CI 必红 | 门禁代码与 40 份资产**同批提交**；本地 `npm run check:agents` 先行验证全绿 |

**被否决方案**

| 方案 | 否决理由 |
| --- | --- |
| 前端启发式识别叙述段（句式 / 段落特征自动折叠） | 误伤陪谈场景的核心复述内容；规则脆弱不可控；违背「显式标记」总则 |
| 独立消息字段（`message.process`） | 需服务端对同一条流做增量拆分流，schema / WS / 迁移成本大，收益与容器方案等同 |
| 字符串级二次扫描器（提取段落到卡片底部聚合） | 违背「单一解析实现」；与 mdast 解析存在语义漂移风险 |
| 单行聚合「过程 · 思考/工具/过程」总行 | 破坏既有文案（「已深度思考」「工具调用」）与断言；可辨性下降；交互状态耦合 |
| 复用 `::: details` 作为过程语义 | 无字数统计 / 无流式跟随 / 语义与通用折叠块混用（保留为误用时的可接受降级） |
| 过程内容彻底不渲染（仅入库） | 信息不可回溯，违背 fail-safe 与可展开原则 |
