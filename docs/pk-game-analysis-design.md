## 1. 背景与目标

### 1.1 三域现状与缺口（一页判断）

批一交付了研讨域五容器族（idea / phase / score / sources / decision）与汇聚板专业化。**对抗 / 博弈 / 分析三域当前是「形态在、内容薄」**——四形态与面板骨架齐备，但各域的专业语汇（交锋、走子、立场、口径、分级）没有专属承接：

| 域 | 现状（已交付） | 核心缺口（一句话） |
| --- | --- | --- |
| 对抗 | debate arena（席位卡 / 回合轴 / 计分板 / 裁决流 / 论断树 + findings 配对卡仅在消息内）；brainstorm 红队（PK 分侧 + 配对卡）；invest 多空对弈协议（verdict 四要素 + 落盘） | **过程无计量、交锋无沉淀、参与无入口**——计分板开赛恒 0:0（只有终局裁决计数）；缺陷-修补配对不上面板；证据等级不可见；轮次无判定落点；用户无加轮 / 叫停 / 表态入口 |
| 博弈 | negotiation arena（offer 报价卡 + 报价流列表带让步差值）；invest（fin_game 四模型 + GameBlock 消息内 + verdict 裁决 + 快照） | **数值无图形、走子无聚合、复现无入口**——报价无折线 / 基准线 / 让步纪律带；fin_game 的模型 / 种子 / 快照散在消息里，面板不可见（复现是投研协议硬要求） |
| 分析 | invest versus（裁决派生：多空信号列 + 局势条 + 结论头）；bi / sre console（通用看板 + 消息摘要时间轴）；society pool（通用卡墙） | **专业语汇无承接**——四路观点卡未兑现（scene-expansion §7.10.3 承诺）；KPI 口径 / SQL 取数链 / 事故分级 / 立场图谱 / 共识分歧全靠消息正文自读 |

> 与 M34 边界复申：M34 博弈 =「算出来的结论」（引擎 / 快照 / 消息块）；本专项 =「对话过程与结论的呈现与交互」。互补不重叠，快照与工具契约零改动。

### 1.2 目标与验收标准

| 目标 | 验收标准 |
| --- | --- |
| 对抗可计量 | debate / brainstorm 红队 / invest 对弈三处共用交锋计量（发言 / 主张 / 提缺 / 已响应）；计分板开赛后即有读数；轮次判定（ruling）可逆 |

## 4. 对抗域设计（A1–A6）

> 域内统一：交锋度量的**单一事实源** = `lib/pk.duelTally`（扩展 `claims` 字段）；一切新交互只回填草稿；容器面冻结口径（ADR 0114）不变、席位发言流实时口径（ADR 0129）不变。

### A1 交锋计量板（计分板升级）

**现状与缺口**：`Scoreboard` 左右读数 = `longs / shorts`（裁决状态计数）——verdict 只在终局产生，开赛后全程 0:0，与「交锋」语义脱节（negotiation 已于 v68 摘除计分板，debate 保留）。

**交互设计**：
- 读数三行（每侧）：`发言 N` · `主张 N` · `交锋 x/y`（提缺 / 已响应）。
- 点击「交锋 x/y」→ 定位首条**未响应**缺陷所在消息（无可定位项时空操作）；
- 点击中列**终局徽标**（裁决后出现）→ 定位裁决消息；
- 全部读数 hover 显示口径 tooltip（如「交锋 = 本侧提出的缺陷编号被后续消息提及的条数」）——不做额外点击路径。

**前端展示**：
- 布局：`左席读数 | VS + 轮次 / 终局徽标 | 右席读数`；三行读数等宽（tabular-nums），左红右蓝（debate theme `#dc2626 / #3b82f6`）。
- 轮次读数：存在 ruling（A4）时 = `第 N 轮（进行中）` / 终局后 `共 N 轮`；无 ruling 回落现行 `第 N 波`。
- 终局徽标：`{左席}胜 · 置信度 高`（复用 `duelVerdictLabel` + `verdictConfidenceOf`）；僵持 = `势均力敌`。
- 空态：无波次时保持「未开赛」（现状）。

**数据源与口径**：`duelTally(messages, sides)` 扩展 `claims`（`claimNodesOfContent` 计数，按 agentId 分侧）；sides 优先 `stage.seats`、回落 `DUEL_STANCE`（lib/pk 现有）；rulings 计数与终局徽标取 `verdictsOf` + 新 `rulingsOf`（A4）。

**降级**：无席位 / 无消息 → 现行「未开赛」零变化；窄屏保留（读数折行）。

### A2 交锋看板 CrossFire

**现状与缺口**：findings 配对卡（`::: findings`，缺陷 N → 复用编号即「已响应」）只在消息内呈现；arena 中轴洞察区只有论断树 + 报价流，交锋的「提缺-修补」节奏不可一览；brainstorm 红队沉淀不进汇聚板。

**交互设计**：
- 条目点击 → 定位来源消息；
- 「催回应」（仅未响应条目，`title="请对方回应这条缺陷"`）→ 回填：`请回应「缺陷 N」：给出修补或反驳，不要跳过。`（编号口径与配对卡逐字一致）；
- 段头计数 hover = 口径说明；brainstorm 池段为**只读模式**（无催回应——红队对无固定轮次纪律）。

**前端展示**：
- 双泳道（左席 / 右席）：段头 `{席名} · 提缺 N · 已响应 M` + 响应率细进度条；条目 = `#N` 编号徽章 + 描述摘要（excerpt 40 字）+ 状态点（已响应 = 绿实心 / 未响应 = 灰空心）；**未响应优先排序**；每侧上限 6 条（超出折叠 `+N`）。
- 段位置：arena 洞察区首位（cross-fire → claim-tree → offers 固定序，parts 裁剪控制显隐）。
- brainstorm 池段：汇聚板「红队看板」段（同组件、只读 + 收敛回填按钮：`围绕被挑出的缺陷给出最小可行修补。`）。

**数据源与口径**：新 `lib/pk.crossFireOf(messages, sides)` → `{ left: Item[], right: Item[] }`，`Item = { id, text, messageId, responded }`；复用 `findingMentions`（全量消息顺序扫描、排除定义行——与配对卡同一推导）；单一解析：解析器（remark-ext findings）与面板共用 `lib/pk.findingsOfLines`。

**降级**：无 findings 容器 → 段不渲染（与 claims / offers 同「有数据才显示」）；窄屏见 U5；解析失败条目跳过不报错。

### A3 证据等级徽标

**现状与缺口**：claim 论据行 `- 论据 | 证据` 的「证据」为自由文本；协议要求附来源等级（官方 / 学术 / 权威媒体 / 待核实）与「无证据必标假设」，但前端无任何分级视觉。

**交互设计**：
- 点「无等级证据」徽标 → 回填：`请为「{论据}」标注证据来源与日期（等级：官方 / 学术 / 权威媒体 / 待核实）。`
- 点「假设」徽标（无证据论据）→ 回填：`「{论据}」目前是假设，请补一条证据，或明示其假设地位。`
- 已有等级徽标点击 → 定位该主张消息（无模板）。

**前端展示**：
- ClaimTree 论据行尾部徽标：`官方`（emerald）/`学术`（indigo）/`媒体`（slate）/`待核实`（amber）四色实心药丸；无证据 → 虚线空心「假设」徽标；未识别 → 中性「证据」灰点（不增噪）。
- 证据文本截断 12 字 + hover 全文（title）。
- 统一色板经 U1（`lib/evidence.ts`）供 society 事实卡 / 来源卡共用（来源卡现有「高 / 中 / 低可信」保持独立轴，色板映射复用）。

**数据源与口径**：`gradeOf(text)` 词表注册表（官方：官方 / 政府 / 监管 / 统计局 / 央行 / 交易所；学术：学术 / 论文 / 期刊 / 文献 / 学者；权威媒体：权威媒体 / 主流媒体 / 通讯社 / 报道 / 媒体；待核实：待核实 / 未核实 / 存疑 / 传闻 / 网传），多命中取**最高优先级**（官方 > 学术 > 权威媒体 > 待核实），未命中 → undefined。

**降级**：解析为 undefined 时渲染中性点（现状视觉不破坏）；`raw` 兜底路径零变化。

### A4 轮次判定容器 `::: ruling`（新容器）

**现状与缺口**：3 轮辩论是「回合制庭审」节奏，但轮间无判定落点——judge 只有终局 `::: verdict`；回合轴节点仅为「第 N 轮」无状态；计分板无过程分。

**语法与渲染**：

```
::: ruling 正方 第 1 轮小结
- 亮点 | 正方量化了成本口径；反方给出两条反例
- 未决点 | 规模化后的边际成本是否成立
:::
```

- 首参复用 verdict 词表（正方 / 反方 / 多方 / 空方 / 僵持；未命中 → 中性「轮次小结」无胜方色）；条目 `- 项名 | 内容`（pan 口径）；可选标题。
- **消息内 RulingCard**（md-ruling）：单行轻卡——判定徽标（左红 / 右蓝 / 灰）+ 标题 + 展开条目 chips；体量显著轻于 VerdictCard（过程件 ≠ 终局件，二者渲染分离、裁决流不含 ruling）。

**交互设计**：
- 回合轴节点徽标：该轮有 ruling → 节点附胜方色点；节点点击 → **有 ruling 时定位 ruling 消息**（否则保持现波次定位）；tooltip `第 N 轮 · 判定：正方`。
- 计分板轮次分：`x : y`（rulings 左右胜数；平局计 draw 独立显示为 `x : y · 平 z`）；无 ruling 显示 `—`（不伪造过程分）。
- 「未决点」为 A5「加一轮」模板的引用源（最新 ruling 的未决点值）。

**数据源与口径**：新 `derive.rulingsOf(messages)` → `{ side, title, items, messageId }`（parseVerdictArg 复用 + panRowsOf）；remark-ext 新增 builder/finalize（与 verdict 同结构、独立类族 `md-ruling`）。

**资产**：debate 协议第 13 条追加「轮次判定（可选，用户可要求每轮给判定）」；judge 人设「工作方式」+1 行。invest 协议 §11 注入「invest-lead 逐轮记录局势可用 ruling（可选）」；career P2（N5）。

**降级**：无 ruling → 全链现行行为零影响（计分板轮次分显示 `—`、回合轴无徽标）。

### A5 对抗参与条（arena）

**现状与缺口**：用户在对决中只能发消息；无「加一轮 / 叫停 / 表态」的一键入口（消息流对决组有 `verdictTemplates` 四键先例，arena 未接）。

**交互设计**（全部只写草稿）：
- 条位置：arena 中轴，裁决流之下（`data-arena-actions`）；仅当 `seats.left` 与 `seats.right` 均非空且 ≥1 波时渲染。
- 五枚药丸按钮：
  1. `加一轮` → `@judge 请再加一轮：重点交锋「{最新未决点}」，双方各挂一条新证据再回应。`（无未决点 → 通用文案「针对尚未回应的分歧点逐一回应，缺证据方补足」）；
  2. `叫停并裁决` → `@judge 请收束当前交锋，直接给出终局裁决（胜负 + 置信度 + 核心依据 + 翻盘条件）。`；
  3. `倾向·{左席}` / 4. `倾向·{右席}` → `我的观感倾向：{席名}——理由：…。请在终局裁决中回应这一倾向是否成立，并给出理由。`（`…` 留给用户补写）；
  5. `倾向·僵持` → 同上模板替换席名。

**前端展示**：单行 chips（换行容忍），secondary 样式、hover 说明；点击后按钮闪一下「已填入草稿」微反馈（quiet 静态）。

**数据源**：U3 模板库（`lib/pk.TEMPLATES`，集中常量、单测断言）；未决点取最新 ruling items 中 label 以「未决」开头的条目。

**降级**：席位缺失 / 无消息 → 条不渲染；narrow 保留（换行）。

### A6 终局结论条（arena）

**现状与缺口**：终局裁决后，结论信息只在裁决 chip / 裁决卡里；无 L1 结论横条（§7.4 分层阅读：L1 结论条 / L2 要点 / L3 论据的 L1 层缺位）。

**交互设计**：
- 点条体 → 定位裁决消息；点「关闭」→ 本会话隐藏（sessionStorage `ma:sc:concl:<sessionId>`，随手「已读」语义）。

**前端展示**：
- 出现条件：存在 `status ≠ none` 的最新裁决且未被关闭。
- 单行条：`结论 · {多方领先|空方领先|僵持} · 置信度 {label} · 翻盘条件 {值}`（翻盘值截断 18 字，hover 全文）；右端「看裁决」+ 关闭钮。

**数据源**：最新非 none 裁决（`verdictsOf` 末项）+ `verdictConfidenceOf` + 翻盘条件条目（`verdictItemSide` 现有「翻盘」识别口径）；versus 面板已有局面头，不重复（见 G4 声明条）。

**降级**：无裁决 / 已关 → 不渲染。

### N4 society 立场泳道与共识分歧板（pool 专业化）

**现状与缺口**：society 协议有五方视角语境（fact-checker / stakeholder / policy-advisor），但无容器约定；汇聚板通用卡墙，立场与共识分歧无沉淀（原「批六」事项，本专项承接）。

**语法（两个新容器）**：

```
::: stance 灵活就业群体
主张：平台应承担基本社保配套
核心关切：收入稳定性与职业伤害保障
被忽视视角：小微平台方的成本承受力
- 依据 | 2025 年灵活就业规模约 2 亿（统计局，已核实）
:::

::: split 议题共识与分歧

- 分歧 | 成本分摊比例（平台 / 个人 / 公共财政）

:::
```

- `stance`：字段行 主张 / 核心关切 / 被忽视视角 + 条目 `- 依据 | 内容`（依据文本走 U1 证据徽标）；

**交互设计**：
- 立场卡点击 → 回填：`请围绕「{立场方}」的核心关切「{关切}」再推演一层：他们的真实约束与合理边界是什么？`；

- 存疑条目点击 → 回填：`请为存疑项「{内容}」补充核实路径（来源与判定标准）。`；
- 共识条目点击 → 定位来源消息。

**前端展示**：
- 消息内：StanceCard（轻卡：立场方徽标 + 主张 + 三字段行 + 依据数）；SplitCard（三列：共识绿 / 分歧橙 / 存疑灰）。
- 汇聚板：stance → **立场泳道**（按立场方分组，色相 = 稳定哈希（6 色板）；卡 = 主张 + 核心关切 + 依据数）；split → 池底「共识 / 分歧 / 存疑」板（三列并列；分歧置中主位）。

**数据源与口径**：`SPECIAL_CONTAINERS` += `stance` / `split`（PoolPanel 场景感知分支，U4）；解析器 remark-ext 导出、面板共用（单一解析红线）。

**协议**：society 新增「渲染容器约定」段（立场卡三字段 / 共识分歧三类条目 / 事实基线用 sources 五列）。

**降级**：无容器 → 通用卡墙（现状零变化）；共识分歧缺失 → 仅立场泳道。

### N5 career 模拟面试轮次条（P2 · 复用 ruling）

**设计要点**：`::: ruling <通过|待改进|未达标> 第 N 问` + 条目（考察维度 / 亮点 / 改进）；ruling 词表按「注册表分组」扩展（对抗组 / 面试组——A4 的词表机制预留分组参数）；coach 面板「面试轮次」段 = N 个结果徽标（绿 / 橙 / 红）+ 点击定位。**P2 评估后实施**；不通过则保持现状（面试记录归消息与《面试手册》）。

## 10. 风险与储备

| 风险 | 缓解 |
| --- | --- |
| 容器 / 面板扩张的镜像面遗漏（历史高发） | §8 清单逐项打勾；`m21` 断言（parts / 协议）+ 组件测试先行 |
