# ADR 0114：arena 席位发言流投影 · 运行中回合号回填 · 贴底跟随末端锚定（M52-D）

- 状态：Accepted
- 引入：M52-D
- 相关：[design.md §70](../design.md)、[docs/scene-expansion-design.md §7.2 / §7.9](../scene-expansion-design.md)、ADR 0112（arena v1 口径与结构键契约）、[client/src/components/scene/SideFeed.tsx](../../client/src/components/scene/SideFeed.tsx)、[client/src/components/chat/ChatArea.tsx](../../client/src/components/chat/ChatArea.tsx)、[client/src/stores/run-store.ts](../../client/src/stores/run-store.ts)、[client/tests/run-events.test.ts](../../client/tests/run-events.test.ts)

## 背景

- arena v1（ADR 0112 / §7.9）上线「席位分栏 + 回合轴 + 计分板」后，左右席仅 SeatCard、两侧大面积留白——§7.2 目标形态「左 = 左席发言流 / 右 = 右席发言流」未兑现（用户实测反馈「辩论两侧是空的」）；
- 同期暴露两条实时性链路问题：① 运行中回合号缺省——计分板「未开赛」/ 回合轴不动 / 发言流无轮次徽标，直到刷新（run:end 全量刷新）才恢复；② 贴底跟随在流式收尾 / 收尾清单撑高后被虚拟列表的测量调整打断——视口偶发停在「距底几百像素」或误离底翻转（「回到最新」浮标误现、尾条被剪枝）；收口期全量 E2E 又甄别出第三处：③ 运行流订阅晚到——短 Run（单助手直答 ~600ms）在高负载下，前端 `attach` 订阅（消息 POST 响应后才发起）跑输 Run 生命周期（已被服务端收尾出栈）→ `/api/runs/:id/stream` 404 → 事件链整体缺失，前端永久停在「仅用户消息」的过期快照，刷新才恢复（服务端侧 Run 实际正常 `done` + `handed_to_user=1`、产出已落库）；
- 约束不变（ADR 0112 背景）：形态层纯前端——不改消息数据层与虚拟列表结构键契约、不改引擎协议、不新增后端接口。

## 决策

1. **席位发言流采「投影式」落地**（`SideFeed`）：从 `useSceneMessages`（500ms 节流 + 流式冻结）投影该席成员消息为条目列表（最新在上、轮次徽标「第 N 轮」、多成员显示名字、`excerptOf` 摘录正文 + 标题挂全文），点击条目 `focusMessage` 定位主轨原消息；不拆流、不复制数据层、不新增接口；
2. **发言流条目不参与虚拟列表**：席位栏为固定宽度轻量列表（arena 席位 1–3 人 × 本会话消息量级），独立渲染（与主轨虚拟化分离）；空态显示「该席发言将显示在这里」；零编制时席位栏保持空；
3. **turnIndex 运行中回填**：run-store 的 `turn:start` 归约直接采用服务端事件字段（engine 本就随 turn:start 下发 waveIndex，shared 类型已声明）——实时面（计分板 / 回合轴 / 发言流轮次 / M16 并行成组）随消息推进，不再等待 run:end 全量刷新；与 attach 重放路径保持同一数据口径；
4. **贴底跟随启用虚拟化器内建末端锚定**：`anchorTo: 'end'`（贴底态按总量差补偿）+ `followOnAppend: true`（贴底追加库内跟随）+ `scrollEndThreshold`（与上滑判定同宽）；手写兜底层保留（多帧 rAF 补正 + `ResizeObserver` 尺寸观察 + `pinnedTopRef` 回声守卫）；容器 `[overflow-anchor:none]` 消解浏览器原生滚动锚定竞争；
5. **E2E 口径统一**：断言「流上方」文本前先滚入渲染窗口（虚拟剪枝是正确行为而非缺陷）；`reload` 场景以「滚顶 + 短断言」重试覆盖消息加载竞态，断言后滚底恢复贴底跟随；邀请类场景（`m16-members`）把邀请链路移出运行收束窗口——成员视图预切换（发送前）+ 免「等停止按钮」护栏直走邀请三步，末波前落库由 +3.0s 提前至 ~+1.1s；
6. **运行流订阅晚到兜底（补全既有契约）**：`attach` 的订阅在「**HTTP 非 ok**（404 订阅晚到；`onEnd` 携带 `httpStatus` 供判定）且未见 `run:end` 事件（闭包 `sawEnd` 标记）且非主动取消（本流 controller 未 abort）」时，按 `run:end` 同一口径做本地收尾（`endRunLocally`：全量刷新 + 运行态清理；无真实结束原因 → 不写 `lastEndReason`）——仅 HTTP 非 ok 触发兜底，「200 流异常自然结束」保持旧行为（真实链路 `run:end` 必达；vitest 镜像面「200 + 非 SSE 体」不误触发），最终一致回到刷新后的真实状态。

## 理由

- 投影式是 ADR 0112「纯前端呈现、零数据层改动」约束下不破坏结构键契约的实现路径：消息数据只有一份（主轨），侧栏是其只读投影——不存在双份流的一致性维护面；
- §7.2 的两侧发言流在形态上是「该席成员的消息视图」而非独立消息序列——投影已覆盖其信息意图（谁在第几轮说了什么、可跳转原消息）；
- turnIndex 回填是「归约层丢弃字段」的修复而非新机制——服务端 / 重放 / 类型三处口径本就一致，仅归约层缺失；修复后计分板「第 N 轮」与回合轴等实时派生全量恢复；
- 贴底跟手的根因在「手写 scroll 时序无法区分自身回声与真实上滑」——虚拟化器内建末端锚定在库层按总量差补偿（不产生瞬时 gap），手写补正从「主力」降为「兜底」；三配置与既有 `STICK_BOTTOM_THRESHOLD` 同源，上滑语义不变（m12 / m37 滚动敏感 spec 全绿验证）；
- 订阅晚到是「生命周期竞态」而非数据丢失（服务端落库完整）——客户端兜底刷新即可恢复一致；且 `sse.ts` 注释契约本就如此约定（「404 交由调用方刷新会话兜底」），本批只是兑现该契约；`endRunLocally` 抽公共收尾消除事件路径与兜底路径的双份漂移风险（幂等）。

## 被否决的方案

- **拆分流（左右各自独立消息流 / 虚拟列表）**：违反 ADR 0112 结构键契约与 M37 波次 / 收束语义，双份渲染面带来性能与一致性维护成本（0112 已否决「拆虚拟列表虚拟化席位分栏」，本批维持）；
- **服务端新增「按席位查询消息」接口**：数据已在前端（`useSceneMessages`），新增往返与协议面收益为零；
- **发言流不过滤展示全部成员消息**：丧失「左 / 右席对峙」的形态语义——按席位投影过滤是形态本体；
- **用 wave:start 事件另存 waveIndex 做派生（不回填消息 turnIndex）**：与 attach 重放路径分裂为双口径（重放只有消息字段），刷新前后行为漂移；
- **纯手写贴底（多帧补正 + 回声守卫，不用库内建锚定）**：实测仍有概率落点漂移（复现日志：贴底赋值后库内 `applyScrollAdjustment` 按上方行重测差值回拉 offset，守卫锚点判据随之失效）——手写层无法获知库内测量调整意图，治本须在库层启用末端锚定；
- **把 CloseoutCard 纳入虚拟列表行**（消解非虚拟化撑高）：大对象测量与既有收尾卡渲染路径改动面大，收益仅为贴底时序，本批不动；
- **服务端为已结束 Run 保留短期「墓碑」（延长出栈窗口供晚到订阅重放 `run:end`）**：需引入定时清理与快速连发场景的窗口管理，内存与复杂度成本换取的仅是「客户端少一次兜底刷新」——客户端兜底刷新已使最终状态一致，不引入服务端生命周期面。

## 适用与失效条件

- 适用：`SideFeed` 参数化（agents / messages / label / onSeek）可复用于其它形态侧栏；`excerptOf` 摘录为通用纯函数；turnIndex 实时回填是计分板 / 回合轴 / 发言流轮次共同的数据基础；
- 失效条件：虚拟化库升级（`anchorTo` / `followOnAppend` / `scrollEndThreshold` 行为漂移）须复核 m12 / m37 / m14 滚动敏感 spec；`SideFeed` 若在 M43 合流后改为独立数据源须重审本决策；§7.2 目标形态若要求发言流含工具 / 交付件明细（超出摘录粒度）时需扩展投影字段；订阅晚到兜底假设「Run 出栈时数据已落库可全量拉取」（`finishRun` 先落库后 `runs.delete`）——若未来调整服务端收尾顺序须重审本决策。
