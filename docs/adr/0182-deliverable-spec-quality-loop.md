# ADR 0182：交付规格闭环——四档规格 · 分章撰写 · 落盘体检 · 评测锚定（报告专业化）

- 状态：Accepted
- 引入：报告专业化（2026-09-19）
- 相关：[agents/_protocol.md](../../agents/_protocol.md)、[skills/report-authoring/SKILL.md](../../skills/report-authoring/SKILL.md)、[server/src/context/deliverable-spec.ts](../../server/src/context/deliverable-spec.ts)、[server/src/util/doc-metrics.ts](../../server/src/util/doc-metrics.ts)、[server/src/tools/builtin.ts](../../server/src/tools/builtin.ts)、[server/src/eval/assertions.ts](../../server/src/eval/assertions.ts)、[agents/CHANGELOG.md](../../agents/CHANGELOG.md)

## 背景

- 现状：报告类交付件由各角色单次 `write_file` 成文；全局协议「一次发言 ≤200 字」未区分对话与交付件；交付契约只有章节结构、无篇幅/证据密度下限；`write_file` 无追加模式（LLM 单次输出上限决定长报告写不完）；无落盘质量信号与评测断言。结果：报告偏短、结构参差、「提纲式报告」常态化。
- 需求：同一套设施同时支持专业长报告（分章、证据密度、附录）与短报告（速览、结论先行），而非新增「写作 Agent」——深度来自领域角色，缺的是规格与质检层。
- 先例：deep-research / doc-coauthoring / formal-document 等技能已有方法论但无强制力；M24 评审范式、M9 断言框架、M61 交付清单可复用。

## 决策

1. **四档规格为一等公民**（协议 `<deliverable_spec>`）：速览（≤800 字）/ 标准（1500–4000）/ 深度（≥4000，分章 + 图表 ≥2 + 来源编号 + 附录）/ 专项（多件套）；档位优先级 = 用户显式 > 计划验收 > 角色契约默认；双向门禁：短报告防残稿、长报告防缩水。
2. **规格解析会话级粘性**（`deliverable-spec.ts`）：倒序扫描用户消息，最近一条含声明关键词的消息生效（速览/简报/快评 vs 深度报告/详细报告/深度研究/尽量详细…）；宽词（「深入」）不入表防误伤；未声明不注入（按角色默认档）。注入点 = execute 回合指令末尾一行。
3. **分章撰写纪律 + append 工具**：深度/专项禁止单次成文（协议 + 技能双处纪律）；`write_file` 增 `mode=append`（空行衔接；不存在等价新建），配合「骨架占位 → edit_file / append 逐节填充」流程；深度档回合工具步数上限 8 → 12。
4. **落盘体检回灌**（`doc-metrics.ts` + write_file detail）：Markdown 落盘即统计非空白字符 / 二级章节 / 表格 / 来源标记（URL、「来源：」、[编号] 三类口径），随工具结果回灌模型对照档位自检；**不做引擎强制补全回合**（留待观测后再评估，避免调度状态机扩张）。
5. **体检与断言同口径**：`measureDoc` 单一实现，供 write_file 体检与评测断言（`min_chars` / `min_sections` / `min_sources`）共用——「写时体检」与「验时断言」永不漂移。
6. **资产三层落位**：协议（全局四档）→ 技能 `report-authoring`（方法论 + 领域章节库 + 量化自检）→ 16 个报告密集角色契约（默认档 + 量化下限 + 降档裁剪规则）；其余角色经技能索引按需加载。**不新增角色**：报告深度来自领域（投研数据口径 / 研究证据链），通用写手角色只会引入交接损耗。
7. **评测锚定**：research / invest golden 任务补规格断言（阈值按 mock 实测定标），防回退到空文件/残稿基线。

## 理由

- **规格而非角色**：报告质量 = 领域深度 × 结构纪律 × 证据密度；前两项现有角色已具备，缺口在「没有下限标准 + 写不完 + 没人验」——横切三层（规格 / 工具 / 体检）一次改造全场景受益；
- **会话级粘性解析**：「开头说一次深度报告」在整个接力链生效，符合多 Agent 长任务交互现实；关键词表收敛避免「深入了解一下」类误触发；
- **append 而非新工具**：参数扩展零工具数增长（工具白名单 / 可达矩阵零扰动），mock 与存量调用零迁移（default overwrite）；
- **体检回灌而非强制门禁**：与协议/技能的「量化自检」形成模型侧闭环，先以观测与提示建立行为；强制补全回合涉及调度状态机（run 结束条件/波次/去重），收益/风险比留待数据说话；
- **同口径 measureDoc**：避免「工具说 4000 字、断言说 3800 字」的解释裂缝（吸取 eval 断言新增四处同改的教训）。

## 被否决方案

- **新增「报告写作 Agent」常驻编制**：领域素材交接损耗大、41 场景链与评测基线扰动、写手不懂 `fin_*` / 证据链领域语义——深度错位；
- **纯提示词强化（只改协议/技能）**：无法解决单次输出上限（长报告必须分节写）与无验收信号两个机制问题；
- **引擎强制补全回合（体检未达标自动 nudge）**：调度状态机扩张风险（循环/去重/结束条件），先行观测再评估；
- **按字数硬门禁阻断交还**：字数只是代理指标（防注水需要软上限），硬阻断会诱发凑字；量化指标用于自检与评测，不用于阻断。

## 边界与后续

- 专项档（多件套）暂无解析关键词与自动校验（用户显式描述或角色契约声明时执行）；
- 素材池（`docs/素材-<主题>/` 分片前置）与 L3 自动评审联动未实施，列入后续评估；
- 规格断言阈值当前按 mock 定标（研究 130 字/4 节、投研 300 字/6 节），真实模型评测走 `--real` 探针任务（`depth-report-spec`，maxTurns 16，不参与 mock 基线）；
- **真实模型探针实测（v93 续，三轮）**：首轮回合耗尽仅骨架 559 字（副发现：关键词表漏「深度档」致规格注入未触发）；次轮 10279 字但暴露两处实测盲区——引用格式 `S-01`（连字符）不在 min_sources 口径内、15 处占位残留未清理（lead 已写「待清理」但未执行）；修正后第三轮**全绿**：13947 字 / S01–S20 连续来源链 / 占位 0 / judge 8 分（「六章节完整非提纲、置信度逐条、证据链可追溯」），实测修正三项：关键词表补「深度档」、min_sources 支持 `S-01` 与裸编号（doc-metrics 共用口径）、体检增占位残留警告；汇总口径 162 来源标记（远超阈值）验证了「证据密度回灌」的有效性。
- **探针组扩编（v93 续）**：`invest-depth-report`（4 人链，6/7：13355 字 / 8 章 / 13 表 / 四件交付件齐全；judge 6 扣于降级场景一手核验深度）+ `bi-monthly-analysis`（3 人链 + `seedFiles` 播种 CSV，5/6：17847 字 / 10 章 / 23 表）——三探针组就绪（结构类断言全部通过；judge 6 分差阈值 1 如实登记为「无数据源降级场景」的严格读数）；任务侧纪律：`MAX_TOOL_STEPS=16` + 「不因口径待确认阻塞」；**编排层实测观察（登记不修，另批评估）**：① PRS 单助手扩编后新成员仅获一棒、探索工具耗尽回合预算而无产出文本；②「口径待确认」自锁阻塞下游；③偶发英文漂移（规划短句）；
- **交付件体检徽章（v93 续）**：`shared/src/doc-metrics.ts` 单一实现（server write_file / eval 断言 / client 预览徽章三端同口径）；ArtifactsView Markdown 预览体检条（字数 / 章节 / 表格 / 来源 / 占位残留警告）。
