# ADR 0087：roster_catalog 注入（Dispatcher-Turn Only Roster Catalog with Content-Signature Cache）

- 状态：Accepted
- 引入：M46
- 相关：[design.md §54](../design.md)、ADR 19（上下文工程：五层装配 + 压缩）、ADR 54（工具按需发现）、ADR 82（调度官为显式一等成员）、ADR 86（召集单一收口）

## 背景

- 调度官需要知道「有哪些角色可召集、属于什么场景、场景默认编制是什么」；候选方案：① 调度回合注入 `<roster_catalog>` 目录区块；② 提供 `list_agents` 检索工具（模型多一轮工具往返）；③ 全角色注入所有成员回合；
- 约束：**token 预算 2–4k**（仅调度官回合承担）；**内容级新鲜**——资产可热更新（mtime），在场集合随召集实时变化，目录必须随之收敛；**不扩大其他角色上下文**。

## 决策

1. 仅 `agent.dispatch === true` 的回合注入（`server/src/context/assembler.ts` L3 区块，仿 M28 `toolDiscoveryBlock` 先例）；
2. 由 `PromptLibrary` 派生（`server/src/orchestration/roster-catalog.ts`）：场景行（id / name / objective 截断 60 字符 / 默认编制链）+ 角色行（id / name / role / description 截断 60 字符）；**只列未在场**；头部「已在场」明细 ≤10 位（超出折叠为计数）——已在场角色不重复列出；
3. **缓存键 = 目录签名 + 在场集合**：签名由角色与场景关键字段内容拼接（`id|name|role|description|group` + `id|name|objective|chain`），内容编辑 → 签名变化 → 重建；LRU 上限 32 条；全员在场 / 空库 → 返回空串不注入；
4. 未注册场景兜底：资产异常的孤儿分组也渲染（不丢角色）。

## 理由

- **零额外工具回合**：目录随回合指令直达，模型首轮即可召集（`list_agents` 检索需多一轮工具往返 + 一个常驻工具位）；
- **上下文只让调度官承担**：其他角色零变化——不扩大任何业务角色上下文（对比全角色注入的乘人数膨胀）；
- **内容级热更新判定**：签名拼接**字段内容**而非 mtime——同秒内多次编辑 / 文件系统 mtime 精度不可靠时行为仍正确；在场集合入键保证「召集后目录即时收敛」（不会重复推荐已在场角色）；
- **token 可控**：双层截断（role 行 60 字符 + 场景 objective 60 字符）+ 未在场过滤 + 已在场折叠，实测 2–4k 预算内。

## 被否决的方案

- **`list_agents` 检索工具**：多一轮工具回合（延迟 + 成本）；mock / eval 脚本复杂化（每次召集预置检索结果）；目录体积可控时预注入更直接；
- **全角色注入**（所有成员回合都带目录）：上下文乘编制人数膨胀；业务角色并不需要召集目录；
- **不缓存每回合重建**：74 角色 × N 场景的字符串拼接每回合重复（调度官接手 ≤3 次 / Run，长会话累积可观）；
- **按 mtime 缓存**：文件系统 mtime 精度与同秒编辑问题（历史先例：mtime 热更新的边界 case）。

## 适用与失效条件

- 适用：资产规模现状（19 场景 / 74 角色）；全局单调度官（缓存键无调度官维度）；
- 失效条件：
  - **资产规模翻倍**（目录超 8k token）——需改分页 / 检索形态（此时 `list_agents` 工具方案重上桌面）；
  - **多调度官分区**——缓存键与控制流需含调度官身份维度（不同调度官可见目录可能不同）。
