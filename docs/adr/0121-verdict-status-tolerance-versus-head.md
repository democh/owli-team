# ADR 0121：裁决状态容错与局势面板局面头——自然语言前缀解析 · 置信度加权 · 元条目剔除

- 状态：Accepted
- 引入：M52-E
- 相关：[design.md §73](../design.md)、ADR 0112（场景工作区体系）、ADR 0117（PK 显式结构化触发）、ADR 0119（裁决回填语义）、[client/src/lib/verdict.ts](../../client/src/lib/verdict.ts)、[client/src/components/scene/derive.ts](../../client/src/components/scene/derive.ts)、[client/src/components/chat/md-ext/remark-ext.ts](../../client/src/components/chat/md-ext/remark-ext.ts)、[client/src/components/scene/panels/VersusPanel.tsx](../../client/src/components/scene/panels/VersusPanel.tsx)

## 背景

- 用户实测反馈：投资研究（dock·versus）多空对弈会话出现「面板上方多方 0 / 空方 0 / 暂无信号，下方裁决卡完整」的割裂；
- 根因一（解析）：`::: verdict` 首参数的状态判定是**精确词表匹配**（多方 / 空方 / 僵持 / 正方 / 反方）；真实模型输出为自然语言（会话存档实锤 `::: verdict 空方领先`）→ 判 none → 场景派生层丢弃全部条目（不落任何列）→ 两列 0/0、局势条 0、裁决卡无状态色；
- 根因二（信息架构）：即使状态命中，面板也没有「胜负 / 置信度」一等公民表达（只有条目数计分与条目列）；局势条只看条目数差（多数场景全偏 ±100，无区分度，与设计 §7.6「置信度聚合」口径不符）；裁决条目（胜负 / 置信度 / 声明）在信号列与裁决卡间重复；
- 边界：`::: verdict` 协议（M34 / M43）与裁决卡渲染（ADR 0119）均不改动——本决策只收敛「状态解析口径」与「面板信息架构」。

## 决策

1. **状态词容错 = 前缀命中 + 条目兜底**（新建 `lib/verdict.ts` 单一事实来源）：`matchVerdictStatus` 首词精确或前缀命中（「空方领先」「多方占优」→ 对应状态；正反方同构）；`parseVerdictArg` 命中后标题取剩余部分，无剩余且首词非标准词 → 保留原文为标题（不丢信息）；`verdictStatusFromItems` 首词未命中时退回条目「胜负」行（value 同口径前缀判定）；两层均未命中 → 仍降级无状态标题卡（原行为，零回归）；
2. **镜像面同口径**：`scene/derive.ts`（工作区派生）与 `md-ext/remark-ext.ts`（消息渲染）共用同一函数面——两侧状态分类不可能漂移；ArenaStage 裁决流 / WaveGroup 对决徽章（status 消费方）自动受益；
3. **置信度解析**（`verdictConfidenceOf`）：显式百分比直取；定性词（高 / 中 / 低）映射幅度（80 / 60 / 30）**仅用于驱动局势条幅度，展示保留原词**（不伪造精度）；
4. **局势面板信息架构**（VersusPanel）：局面头——最新裁决的胜负上移（多方领先 / 空方领先 / 僵持；色板同 md-verdict 族）+ 置信度 chip；局势条——最新裁决 status ≠ none 时 `momentum = dir × confidence.pct`（无置信度条目 → 满偏兜底），无有效裁决保持条目数差基准；信号列剔除元信息条目（`胜负 / 置信度 / 声明` 前缀，面板头 / 裁决卡 / 信号列不再三处重复）。

## 理由

- **前缀命中是「模型自然语言」与「协议结构化」之间必需缓冲**：协议要求状态词开头（invest / debate 裁决四要素），但模型常态输出完整判断句（「空方领先（程序性优势）」）——精确匹配把合法输入判为降级，损失全部结构化数据；前缀命中把容错成本压到最小（零协议变更）；条目「胜负」兜底覆盖「首词完全不含状态词」的第二类漂移（如 `::: verdict 结论如下`）；
- **非标准首词保留为标题**：降级信息不丢失——「空方领先」本身即模型的完整判断，作标题比空标题更有信息量；
- **单一事实来源**：状态解析同时服务消息渲染与工作区派生——若两侧各写一份，任何一侧修正都会造成「卡片有状态色、面板没有」的同类割裂（本缺陷的镜像面风险）；
- **置信度定性映射只用于幅度**：定性词无严格数值语义（展示「中」比展示「60%」诚实）；但局势条需要数值——映射集中一处（低 30 / 中 60 / 高 80），是明确的启发式而非测量；
- **三面分工**：局面头（结论：胜负 + 置信度）→ 局势条（幅度）→ 信号列（依据）——元条目上移后三处无重复，信噪比最大化。

## 被否决的方案

- **只改协议让模型输出标准词**：协议已要求状态词开头；模型遵守度不可保证（真实会话已实证）；前端容错是必选项，且成本远小于协议变更；
- **放宽为「包含状态词即命中」**（任意位置）：「空方优势被多方逆转」会误判；首词前缀是「判定词在开头」协议事实的宽容表达；
- **置信度落库为结构化字段**：裁决为消息内容器（无 schema），落库需协议 / 编排 / 存档三侧扩字段；派生即可（ADR 0112 / 0117 同口径）；
- **局面头做独立元件**（parts 注册）：局面头是 VersusPanel 的内部信息架构（无复用方），建元件会让注册表承载一次性组件；
- **信号列保留元条目**（仅面板头新增）：三处重复反而降低信噪比——信号列应只承载实质信号（核心依据 / 翻盘条件 / 失效条件等）；
- **局势条继续用条目数差**：与面板头状态并存会造成「头说空方领先、条说多方满偏」自相矛盾（条目数差多数场景全偏 ±100，无区分度）。

## 适用与失效条件

- 适用：`lib/verdict.ts` 为消息渲染与工作区派生共用；`verdictConfidenceOf` 同时服务 VersusPanel 与后续置信度消费方；状态词表（前缀词根）若协议扩词须同步注册表；
- 失效条件：`::: verdict` 协议若变更首参数语法（如改 JSON）解析面须重写；「裁决卡仅最新」口径若变化（历史全量展示），局面头取「最新」的语义须重审；定性词映射（低 30 / 中 60 / 高 80）若与协议术语表冲突须先改映射再改协议。
