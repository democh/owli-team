# ADR 0183：dock 右区宽度自适应——默认容器 1/3 · 上限最多一半 · 双击复位回自适应

- 状态：Accepted
- 引入：批九 · 场景工作区宽度自适应微批（2026-09-19；**编号让位**：0182 / design.md §110 / CHANGELOG v93 已被并行批「报告专业化 · 交付规格闭环」占用，本批落 0183 / §111 / v94）
- 相关：[design.md §111](../design.md)、[client/src/components/scene/persist.ts](../../client/src/components/scene/persist.ts)、[client/src/components/scene/DockStage.tsx](../../client/src/components/scene/DockStage.tsx)、[client/src/index.css](../../client/src/index.css)、[client/tests/m52-stage.test.tsx](../../client/tests/m52-stage.test.tsx)、[e2e/m52-stage.spec.ts](../../e2e/m52-stage.spec.ts)、修订：[ADR 0127](0127-scene-panel-ready-and-title-chrome.md)（固定 clamp 280–640 口径由本批取代）

## 背景

- 用户实测反馈（两栏 dock 截图）：固定口径不适应窗口——默认 360px 在宽屏下偏窄（盘面 / 看板阅读局促），上限 640px 写死（宽屏无法继续拖宽、窄宿主又近乎占满）；诉求原话「这种两栏的可以优化下宽度，支持拖动到最大为1半默认可以增大点宽度或者根据实际窗口自适应等等」；
- 现状（ADR 0127 / design.md §79.3）：`DOCK_DEFAULT.width = 360`、clamp `280–640` 全为绝对值——与容器 / 窗口宽无关：2560 宽屏下同样封顶 640（占比 25%），1280 宿主下 640 又近乎吃掉全部对话区；
- 既有邻近先例：arena 侧栏（ADR 0129）已确立「clamp 相对宿主（非 vw）」的自适应口径；dock 因拖拽需要 px 落盘，走 JS 收敛而非纯 CSS clamp。

## 决策

1. **上限 = 容器一半**：`dockMaxW(containerW) = max(280, floor(containerW × 0.5))`——右区最多占两栏区 50%，左对话区恒保 ≥50%；
2. **默认 = 容器 1/3（自适应）**：`dockDefaultW(containerW) = min(clamp(round(containerW / 3), 380, 600), dockMaxW)`——1280 宿主 ≈ 426 / 1440 ≈ 480 / 1920+ 600 封顶；宽屏下较旧固定 360 明显变宽，窄宿主不挤占对话区；
3. **容器宽度观测**：`DockStage` 用 ResizeObserver 观测 `.scene-dock`（窗口缩放 / 会话栏开合自动联动；无 RO 环境以视口宽兜底首帧，挂载后立即量测一次校正）；
4. **偏好语义升级（`DockPref.width: number | null`）**：null = 自适应（跟随容器比例）；数值 = 用户拖拽 / 键盘的显式宽。**双击把手复位回 null（自适应）**（旧口径复位到固定 360）；旧固定默认 360 在 `loadDockPref` 迁移为 null——未显式拖宽的用户升级后默认变宽；
5. **存储与收敛解耦**：存储只做下限护栏（≥280）；上限在渲染期随容器动态收敛（`clampDockW`）——窗口临时缩小压窄不写回存储，窗口再放宽恢复原始意图；
6. **CSS 硬上限兜底**：`.scene-dock-aside { max-width: 50% }`——JS 收敛之外的当帧保证（窗口骤缩 / 存量超限偏好），任何路径都不会越过一半；
7. **把手 aria 实时化**：`aria-valuemax` 随容器收敛（不再固定 640），`aria-valuenow` 报生效宽；拖拽 / 键盘 / 双击三入口共用同一动态口径。

## 理由

- **「一半」是对话区与工作区的可读性分界**：盘面 / 看板需要宽度，但左对话流是主角——半屏上限保证任何窗口下左区不被压到极限；
- **「1/3 + clamp」作为默认**：既满足「默认增大点宽度」（1440 下 480 > 旧 360），又满足「根据实际窗口自适应」（比例随宿主；380/600 双护栏防小屏过宽 / 超宽屏喧宾夺主）；
- **JS 收敛而非纯 CSS clamp**：拖拽需 px 落盘（localStorage 记忆）、双击复位 / 键盘步进需显式态语义，读回 computed 值再写回会让三条交互路径复杂化；JS 单函数（`dockMaxW` / `dockDefaultW` / `clampDockW`）是口径单一事实来源；
- **存储不写回临时收敛值**：宽屏拖到 800 → 换到 1280 窗口显示收敛为 ~500（不丢意图）→ 回到宽屏恢复 800，符合「用户意图 ≠ 当帧约束」；
- **360 → null 迁移**：旧固定默认值对未拖拽用户是「系统默认」而非「用户选择」，迁移后获得自适应宽；显式拖过的数值（≠360）原样保留。

## 被否决的方案

- **固定 px 上限上调（640 → 800 / 960）**：治标不治本——宽屏仍封顶、窄宿主仍近乎占满，且数值无从定标；
- **纯 CSS `width: clamp(380px, 33%, 600px)`（仿 ADR 0129 arena 侧栏）**：拖拽落盘与自适应态需共存——CSS 百分比宽无法直接落盘为「用户意图」，双击复位的「自适应态」也无显式表达；
- **默认固定增大到 480 / 520**：不随窗口变化，1280 及以下宿主会挤占对话区；
- **比例相对视口（vw）而非容器**：会话栏开合 / 未来多分栏并存时口径漂移（ADR 0129 已确立「相对宿主」原则）；
- **双击复位到「当前自适应默认」的显式数值**：窗口随后变化时不跟随，与「自适应」语义不符；
- **把收敛后的临时宽写回存储**：小窗口一次渲染即永久丢宽屏意图（否决）。

## 边界与失效条件

- 窄屏（<900px）不参与本口径：dock 右区转底部抽屉（§7.3-4，ADR 0112 / 0127 口径不变）；
- 容器极窄（<560px）时上限退化为下限 280（半屏 < 280 时以 280 为准）——此时右区可占超一半，属极端宿主宽度，与 `DOCK_MIN_W` 保底同理；
- 若右区未来改为多面板并排 / 可拖分栏，本「单把手 + 单宽意图（number | null）」模型需重估；
- `ma:sc:dock` 存储 `width` 语义变更（number → number | null）：旧值全兼容（数值照旧、360 迁自适应、非法值回落 null），无迁移脚本；
- 上限依赖 `.scene-dock` 实际宽度——若宿主结构调整（dock 不再独占两栏区），口径随实测自动跟随，无需改代码。

## 验证

- client `m52-stage`：+4 例（纯函数口径 8 断言 / 存量迁移 360→null / 默认渲染 380 + 把手 aria min 280·now 380·max 512 / 超限收敛 5000→512 + 不改写存储 + 双击复位 + 键盘 ← 调宽）→ **62/62 ✅**；
- E2E `m52-stage`（批九 · dock 右区宽度）：真实浏览器——默认自适应（≥380 且不越半屏）/ 拖拽到容器最左缘 → 右区 = 容器一半（±2px）/ 双击复位回自适应（±1px）/ 视口 1680 → 2400 变宽 → 自适应宽跟随增大 ✅；
- typecheck（client + e2e）0 错误；真实浏览器验收：传统数术 dock·chartboard（用户截图场景）宽度与拖拽手感。
