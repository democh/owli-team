# ADR 0002：协作范式——自主委派

- 状态：Amended（M3 起 handoff 工具优先）
- 引入：v1 决策，M3 修订
- 相关：[design.md §5](../design.md)、ADR 20

## 背景

多个角色 Agent 在同一会话中接力完成任务，需要一种「谁来接棒」的机制。备选：固定流水线调度，或由模型自主决定转交对象。

## 决策

**模型自主委派**：角色在输出中主动指定下一位接棒人。

- v1：文本 `@某角色` 由服务端解析，调度器过滤（自转交 / 循环 / 不在场 / 已发言）后入队；
- **M3 起（修订）：`handoff` 工具为第一优先级**——`handoff(target, reason, expected_output)` 结构化转交，调度器消费 `pendingHandoffs`（复用全部守卫）；文本 `@` 仅在无工具调用时作为兼容回退；
- `HANDOFF_MODE=auto | tool | text` 控制该行为（默认 `auto`）。

## 理由

- 接力链贴合真实研发协作：当前角色最了解「下一步该找谁」，比固定流水线灵活；
- 文本 `@` 简单但不稳定（被措辞干扰）；工具调用结构化、可校验、可回灌修正（目标不在场时立即报错让模型重选，取代 v1 的静默丢弃）；
- `auto` 双轨并存：新 prompt 用工具，历史行为不破坏。

## 被否决的方案

- **固定流水线**（PM→架构→…硬编码顺序）：无法处理「跳过设计直接改 bug」这类真实诉求；
- **继续只靠正则解析**：目标校验缺失、无法回灌修正。

## 影响

- `turn:end.mentions` 始终表示**调度器实际入队结果**（design.md §6.4）；
- 文本 `user` 恒为交还用户（行首判定见 ADR 4）。
