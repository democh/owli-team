# ADR 0165：签收收尾——核心交付签收区与本地签收态（AF-5）

- 状态：Accepted
- 引入：M44 核心交付锚点范式（2026-09-19）
- 相关：[design.md §101](../design.md)、[docs/scene-chat-design.md §12](../scene-chat-design.md)（M44 原案 AF-5 落位）、ADR 0123（交付清单分层）、ADR 0163（锚点选择——pickFocusPath 复用）、ADR 0164（闭环统计来源）、[client/src/components/chat/CloseoutCard.tsx](../../client/src/components/chat/CloseoutCard.tsx)

## 背景

- M44 原案 AF-5：签收收尾卡（DEV-3 变体）——「收尾波」触发；「锚点存在且 Run 完成」；呈现「交付件 + 版本 + 闭环统计 +『签收』（本地态 + 回填『已签收 <名> vN』）」；无锚点 → 普通验收单；
- M39 已交付 DEV-3 验收单（收尾卡验收区 + 未决项）；M44 本项为「验收之后的一步」：用户对核心交付给出签收确认。

## 决策

1. **落位**：收尾卡（CloseoutCard / DeliveryManifest）内追加**签收行**（不新起卡片）——development 场景且锚点存在时渲染；`data-signoff` 携锚点路径。
2. **读数**：锚点名（含扩展名，截断展示 + title 全路径）+ `vN`（锚点最新版本，`useArtifactVersions` 懒加载；未就绪时按钮禁用「等待版本信息」）+ 闭环统计「已回应 N · 未闭环 M」（`closureOf` 会话级派生，与 AF-4 同源）。
3. **本地签收态**：sessionStorage `ma:signoff:<sessionId>`，标识 `<path>@v<version>`（**按版本**：新版本到来即回到未签收）；签收 = toggle（再点取消）；**签收时回填草稿** `已签收《<名>》vN。`（ADR 0064 只写草稿不直发）；不进导出、不落库。
4. **降级链**：无锚点（无交付件——收尾卡本身不渲染）/ 非 development 场景 → 签收行不渲染（普通验收单）；版本未就绪 → 行在、按钮禁用。

## 理由

- **签收挂在收尾卡**：签收语义 = 「本轮交付我认可了」——与交付清单同容器最准确；独立卡片会与验收区/清单三卡并排（信息架构冗余，M39 已否决同族方案）；
- **按版本签收（path@vN）**：v1 签收后作者又改出 v2，等于签收失效——版本入签名使「签了什么」无歧义；
- **回填而非直发**：保持 ADR 0064 统一语义；「已签收」作为一条用户消息进入会话流（对成员可见、可触发后续动作如发布），比纯本地勾选更有协作价值；
- **本地态**：签收与否是个人视图确认（无多用户会话语义前不落库——与钉选/已满意同族）；要审计级签收需另立服务端实体。

## 被否决的方案

- **独立签收卡（与验收区/清单并列）**：三卡并排冗余；签收与「本轮交付」强关联，同容器呈现；
- **签收不按版本（path 即签名）**：版本更新后签收自动失效的逻辑无法表达；
- **签收落库（会话字段 / 新表）**：当前无「谁签收 / 审计」需求（ADR 0082 条件性纪律同族）；本地态 + 回填消息已覆盖协作可见性；
- **签收直发消息**：绕过用户确认（ADR 0064）；
- **把签收并入 NOT 已满意语义**：已满意针对单条意见、签收针对整件交付——语义层级不同，不可合并计数。

## 边界与失效条件

- 签收行依赖 development 场景判定（与 DEV-3 验收区同门控）；其他场景若需要，按场景表扩展（同 MK-1 常量表思路）；
- `data-signoff / data-signoff-version / data-signoff-btn` 为测试锚点；
- 版本列表接口失败 → 按钮常禁（降级明确，不假装可签）；
- 若未来引入服务端签收（审计 / 多用户可见性），本地口径退役、回填文案可保留。
