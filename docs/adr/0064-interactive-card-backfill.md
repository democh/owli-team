# ADR 0064：交互卡片回填语义 = 生成草稿（Interactive Card Backfill: Draft, Not Send）

- 状态：Accepted
- 引入：M37
- 相关：[design.md §52](../design.md)、ADR 9（流式纪律）、ADR 20（会话级互斥 + 插话）、ADR 25（前端性能架构）、ADR 39（业务 Markdown 卡：option 容器）、ADR 62（场景差异化限定于视图层派生）、ADR 65（波次分隔与定位）

## 背景

- M37 引入可交互的 markdown 容器（`::: checklist` / `::: choice`）并增强既有 option 卡：勾选 / 点选产生的「用户意图」需要一个回到协作主干的通道；
- 通道候选面临三类语义问题：① 直接发消息会绕过 Run 互斥与用户确认（静默开工）；② 落库持久化交互态会把「渲染选择」变成「数据事实」，级联触碰导出 / 回放 / fork 语义（ADR 62 边界）；③ 每类卡片自建提交通道会形成 N 条回填路径，文案与行为漂移；
- 硬约束：
  1. **一切交互输出走 Composer**：由用户确认后发送——回填是「写草稿」而非「替用户发送」；
  2. **流式纪律（ADR 9）**：流式期间卡片静态 / 禁用，完成态才可交互；
  3. **本地互动态**：勾选 / 点选状态存 sessionStorage（`ma:*` 键），不落库、不进导出（ADR 62）；
  4. **fail-safe**：解析失败一律回退原文，交互不出现、不报错。

## 决策

1. **统一回填通道**：全部交互卡片经 `ui-store.insertToComposer(text)` → `composerInsert`（nonce 递增）→ Composer 消费时 append 草稿 + focus；不直发、不落库、不经新 API；
2. **文案契约**：checklist → 「完成情况回填 · 《标题》（x/y）」+ 任务清单 markdown（`- [x]` / `- [ ]` 行，用户可编辑）；choice → 「拍板：<选项>」；option 增强 → 「拍板：<标题>」；
3. **交互态存储**：checklist 勾选用覆盖表（`Map<index, boolean>`——用户未触碰条目跟随内容初始 `checked`）；键 `ma:check:<sessionId>:<messageId>` / `ma:choice:<sessionId>:<messageId>`；无消息上下文（如未挂载场景）仅即时态、不落存储；
4. **流式期降级**：卡片在流式期间整卡禁用（行 / 按钮不可点），完成态才挂载交互（ChecklistCard / ChoiceCard 遵守 ADR 9）；
5. **上下文注入**：`MessageContext.Provider` 提供 `{messageId, sessionId}`；完成态渲染缓存（LRU 200）按挂载位置求值——同一内容在不同消息下互不串态。

## 理由

- **「生成草稿」保留用户最后决定权**：勾选 ≠ 发送意图的完整表达（用户可能只回填部分、补充说明再发）；草稿模式让回填可编辑、可撤销，且天然复用 Composer 的全部既有能力（附件 / 命令 / 插话）；
- **发送必经消息管道**：Run 互斥（ADR 20）、插话、上下文装配、流式输出全部由既有单一管线处理，无需为第二通道论证正确性；
- **交互态本地化**：勾选 / 点选是「用户与视图的临时对话」，不是协作事实；落库会引入同步 / 冲突 / 迁移成本，且破坏「消息序列 = 唯一事实源」的导出语义（ADR 62）；
- **覆盖表语义**：内容驱动初始态（`- [x]` 是模型输出的现状），用户触碰才产生本地覆盖；完成态内容不再变化，避免合并冲突。

## 被否决的方案

- **点选即直发消息**：静默发起新 Run，绕过互斥与用户确认（且用户不可撤销已发消息）；与「交还与确认」的协作哲学相悖；
- **独立回填 API / 服务端交互表**：为本地视图互动引入后端状态与同步协议，收益（跨端 / 审计）在本地单用户形态下为零；M45 若互动统计被证实需要持久化再单独评估（ADR 62 失效条件）；
- **localStorage / 会话级 JSON 持久化勾选态**：交互态与消息 id 绑定、生命周期随消息；sessionStorage 的「会话即焚」语义恰好匹配；
- **每类卡片各自直发 / 各自草稿通道**：文案与行为漂移不可控；统一 `composerInsert` 是唯一入口；
- **勾选打点上报（埋点即发送）**：同样绕过用户确认；统计需求按需另评。

## 适用与失效条件

- 适用：本地单用户部署；交互为「用户 → 视图」的即时互动（勾选 / 点选）；消息序列为唯一事实源（ADR 62）；
- 失效条件：
  - **多端同步**（同一会话手机 / 桌面并开）：sessionStorage 本地态不共享，需改服务端 / 账号级存储；
  - **互动统计或审计落库**（M45 条件性）：需评估 `interactions` 表并重审「交互态不进导出」边界；
  - **回填需承载交互结果导出**（导出附带勾选态快照）：边界失效，需把交互态纳入导出格式版本化讨论。
