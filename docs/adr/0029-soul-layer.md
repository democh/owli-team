# ADR 0029：Agent 灵魂层——可选人格变体与优先级护栏

- 状态：Accepted
- 引入：M16
- 相关：[design.md §26](../design.md)、ADR 19、ADR 28

## 背景

同一角色在不同场合需要不同表达风格（头脑风暴的「狂野发散」与「禅意收敛」），但职责、事实与协作规则必须稳定。备选：为每种风格复制一个完整角色（角色数爆炸、职责漂移），或在人设里堆砌风格分支（职责与风格耦合、不可复用）。

## 决策

**引入可选的「灵魂层」（Soul）——与职责解耦、可插拔、可多套的纯风格定义**：

- **载体**：`agents/<场景>/<id>/souls/<soul-id>.md`（front-matter：id / name / tagline / icon / traits / tone / quirks + 正文示例）；无 `souls/` 目录 = 无灵魂，**行为与现状完全一致**（非必配）；
- **分层模型**：协议层（怎么协作，最高约束）> 职责层（你是谁、干什么）> 灵魂层（怎么说、什么性格）；
- **装配优先级**：会话覆盖（`memberSouls`）> 角色默认 `soul` > `souls/default.md` > 无灵魂；灵魂段追加在 L0 尾部（会话内稳定，prompt cache 友好）；
- **双保险护栏**：装配顺序（灵魂段靠后、明确从属）+ 灵魂段固定护栏句「灵魂只影响表达风格与互动方式；职责边界、事实准确性与协作规则的优先级更高，不得因风格牺牲准确性」；
- **会话级换装（不改文件）**：`PATCH /api/sessions/:id/members/:agentId` `{ soul?: string | null }` 切换 / 恢复默认（null），落 system 消息；邀请时也可带 `souls` 选风格。

## 理由

- 风格与职责解耦：职责稳定、风格可玩，且同一角色换装不改变工具权限、调度语义、会话互斥等硬约束；
- 复用最大化：N 个角色 × M 套灵魂零复制成本；「固化风格」只需复制角色目录并设默认 soul（升级路径明确）；
- 非必配 + 优先级护栏让存量角色与存量会话行为零变化，风险可控；
- 会话级而非文件级换装，让「可玩性」不污染资产目录，也支持随时对照演示。

## 被否决的方案

- **每风格一个独立角色**：角色列表爆炸，职责文案多处漂移，维护成本线性增长；
- **灵魂覆盖/替换人设**：风格与职责耦合，模型容易因风格牺牲准确性（护栏无法兜底）；
- **必配灵魂（所有角色都要写 souls/）**：改造成本大、存量行为改变，违背最小变更原则；
- **把灵魂作为运行时 prompt 片段存在数据库**：不可评审、不可 diff、不可迁移，资产化收益全失。

## 影响

- `GET /api/agents` 附 `souls` / `defaultSoul` 元数据；`check:agents` 校验 soul id 唯一与默认引用；
- sessions 表新增 `member_souls` JSON 列（追加迁移，空 = 默认）；
- 前端 SoulPicker / 灵魂徽标 / 名录页对比视图；mock 提供风格化文案变体供 E2E 断言。
