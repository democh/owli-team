# ADR 0232：正在输入（typing）临时帧

- 状态：Accepted
- 引入：M90
- 相关：[ADR 0188](0188-user-topic-and-inbox.md)（用户主题）、[ADR 0193](0193-presence-by-connection-refcount.md)（在线状态）、[ADR 0228](0228-im-message-reliability.md)（通知代际与游标）

## 背景

在线状态解决「在不在」，但没有「正在写」的即时反馈。私聊与群聊中，用户需要一个低成本信号判断对方是否在回应，而不是反复看空输入框。

typing 与普通消息/通知的本质差异：

- **过期即无意义**：3 秒前的「正在输入」不该在重连后补发；
- **高频**：按键级别上报会产生帧风暴；
- **无持久事实**：不需要落库、不需要未读、不需要审计；
- **有权限边界**：只能让当前会话的可见成员看到。

## 决策

1. **临时帧（ephemeral）**
   - `NotifyEnvelope` 增 `ephemeral?: boolean`；typing 帧 `seq = 0`、带 `epoch`，**不写重放缓冲、不推进会话 seq、不参与游标去重与断线补发**。
   - `NotifyHub.fanoutEphemeral` 只向当前订阅了该会话的连接扇出，不进入 `publishToUser` / 跨实例总线。
2. **客户端 → 服务端**
   - WS 客户端帧 `{ type: 'typing', sessionId }`。
   - 客户端在输入非空时**3s 节流**上报；空内容、只读（viewer）、连接未开不上报。
   - 服务端再次兜底：同一连接 + 同一会话 **1.5s 节流**，并按 `access.canAccessSession` 校验权限；未登录 / 无权限静默丢弃。
3. **服务端 → 客户端**
   - 帧 `notify:typing`，payload `{ userId, name? }`；**排除发送者当前连接**。
   - 客户端按 `(sessionId, userId)` 维护临时表，**6s 无新帧自动过期**；本人其他标签页收到后按 userId 过滤，不回显自己。
   - 收到该用户的消息（`notify:turn-end`）立即清除其输入态；不再额外发「停止输入」帧（节省一次往返，过期兜底足够）。
4. **UI**
   - 会话头部显示「X 正在输入」/「X、Y 正在输入」/「N 人正在输入」+ 动画点；
   - 仅当前会话渲染；切换会话不清理其他会话的临时态（各自过期）。

## 理由

- **不占 seq**：typing 若走普通 `publish`，会推进会话游标、污染未读与重放缓冲；重连补发一串过期的「正在输入」既无意义又浪费带宽。
- **双层节流**：客户端节流降低上行；服务端节流防恶意 / 多标签页叠加；1.5s 小于 3s，正常输入不会被误杀。
- **排除发送者连接**：自己的输入不需要回显；同账号其他标签页由客户端按 userId 过滤，避免误伤。
- **消息到达即清除**：用户发出消息后继续显示「正在输入」是明显错误；用已有的 `turn-end` 帧清理，不新增协议。
- **无持久化**：typing 是瞬时状态，落库只会制造清理与隐私负担。

## 被否决的方案

- **普通 `notify` + 重放缓冲**：会产生过期回放、推进未读游标、增加 seq 噪声。
- **typing 表 + REST 查询**：高频写库、需要 TTL 清理，收益不成立。
- **跨实例总线广播 typing**：typing 生命周期短于总线轮询间隔，跨实例传输只会放大过期帧；多实例部署下 typing 仅本实例可见（已知边界）。
- **每次按键上报**：帧风暴；客户端 3s 节流已足够。
- **显式 `typing-stop` 帧**：多一次往返，且断线时仍要过期兜底；消息到达 + 6s 过期已覆盖。
- **把 typing 混入 `notify:presence`**：presence 是连接级、跨会话可见域；typing 是会话级、内容相关，语义不同。
- **服务端生成展示名快照**：当前直接用 `displayName`；若未来允许匿名 / 昵称可见性策略，需改为按会话投影。

## 适用与失效条件

- 适用：多用户模式（需要账号识别）；私聊 / 群聊 / 团队会话；单实例部署的实时通道。
- 失效条件：
  - 多实例部署且要求 typing 跨实例可见时，需要低频总线或按实例亲和路由；
  - 若引入端到端加密，typing 帧不能携带明文展示名，需改为 userId + 客户端本地解析；
  - 若增加「输入中」的附件 / 语音录制状态，应扩展 payload 并重新评估节流窗口；
  - 若产品要求「停止输入」即时消失，需补 `typing-stop` 帧或缩短过期时间。
