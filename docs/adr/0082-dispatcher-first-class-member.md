# ADR 0082：调度官为显式一等成员（Dispatcher as Explicit First-Class Member）

- 状态：Accepted
- 引入：M46
- 相关：[design.md §54](../design.md)、[docs/harness-dispatch-design.md](../harness-dispatch-design.md)、ADR 30（会话动态成员：members API + system 消息）、ADR 33（Run 内并行波次）、ADR 83（`dispatch` 资产标记）、ADR 84（空选择创建语义）、ADR 91（事件与广播复用）

## 背景

- 会话的「前台接待」有三个断点：① 建会话强制选成员（`createSessionSchema` 约束 ≥1，UI 三步流拦截 0 人提交）——用户须先在 70+ 角色里做选择才能说第一句话；② 无 @ 消息盲投编制链首位（engine「首发队列」`participantIds.slice(0, 1)`），不做任何意图识别；③ 没有跨场景总调度——需求跨场景（如「修 bug 顺便发个公告」）只能用户自己挑人或首位成员手工接力；
- 候选形态三类：① **显式成员**（资产角色 + 进入 `participantIds`）；② **隐藏路由器**（编排层预调度 LLM 分类，用户不可见）；③ **幽灵成员**（会话表之外的参与者实体）；
- 硬约束（持久化与编排层不变量，不允许为调度引入例外分支）：`queue ⊆ participants`、会话至少 1 名成员、handoff 目标必须在场。

## 决策

1. 调度官 = `agents/harness/` 场景单角色（id `harness`，展示名「知舟 · 总调度」），经既有资产链进入系统：zod 校验 → mtime 热更新 → `check:agents` → `/api/agents` 投影；
2. 建会话时作为普通成员写入会话成员表（空选择创建由服务端填充，ADR 84）；成员面板、协作图谱、记忆归属、头像体系、波次编排、审批挂起**全部原样适用**；
3. 调度官消息 = 普通 Agent 消息（普通流式渲染、普通持久化）；召集动作落 system 事件条 + `notify:members-changed` + trace `dispatch:invited`（ADR 91）——不做静默路由换人；
4. 调度与业务分离：调度官只做意图识别 / 召集 / 派发 / 收口，不写交付件、不越权干活（工具白名单为最小协作集，ADR 86）。

## 理由

- **不变量零破坏**：成员身份让全部既有校验（handoff 在场、队列过滤、循环检测、并行波次规划、成员 API 移出护栏）逐条原样成立——零编排特例；
- **可审计可回放**：调度官每个决策都是一条可回放的消息 / 工具记录 / trace，符合「一切皆回合」纪律；用户可 @ 纠正、可在成员面板直接移出；
- **复用最大化**：数据模型 0 变更、迁移 0、新端点 0；资产体系让调度官可热更、可停用（移出会话 = 关闭智能调度，无 @ 回退首位成员）。

## 被否决的方案

- **隐藏路由器（预调度 LLM 分类）**：不可见、不可审计、另起提示词体系；分类失败态不可解释，用户无法在会话内纠正；
- **幽灵成员（会话表外参与者）**：破坏 `queue ⊆ participants` 与会话持久化模型——图谱 / 成员面板 / 记忆归属全部出现表外实体，fork / 导出 / 计数镜像面逐处特判；
- **会话外接管（编排层旁路发言）**：绕过审批、循环检测与波次护栏，且消息流出现「无主发言」。

## 适用与失效条件

- 适用：全部基于「会话成员表」的编排语义（ADR 30）；调度官全局唯一（ADR 83）；
- 失效条件：
  - **引入非成员参与通道**（外部 bot / webhook 成员 / 跨会话路由）——「可见成员 = 参与者全集」前提需重新评估；
  - **多调度官分区**（按场景 / 项目路由）——唯一性语义与路由分支（ADR 85）需扩展。
