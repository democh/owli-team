# ADR 0135：成员条统一常驻——输入条成员条全场景一致展示 · 撤销席位让位判定（修订 ADR 0126）

- 状态：Accepted
- 引入：成员条统一批（2026-09-19）
- 相关：[design.md §86](../design.md)、ADR 0126（本 ADR 修订其「输入条成员条席位让位」判定；标题栏头像组移除维持不变）、[client/src/components/chat/Composer.tsx](../../client/src/components/chat/Composer.tsx)、[client/tests/composer.test.tsx](../../client/tests/composer.test.tsx)

## 背景

- 用户实测双会话截图对比（谈判 arena 会话 vs 投资研究 dock 会话）红框标注 Composer 上沿成员条区域并追问「为什么有的会话里面有，有的会话里面没有」，随后明确诉求「请统一下 / 所有的对话都需要统一」；
- M52-G（ADR 0126）的让位判定按场景条件生效（roundtable 恒隐藏 / arena 全员入席才隐藏），对用户呈现为「成员条时有时无」——判定条件（首参与者场景组 + 席位覆盖并集）不可见、跨会话不可预期；运行期编制变化（新成员入队 / 未入席）还会导致成员条动态显隐；
- 边界：dock / stream / 纯列表场景成员条恒展示（ADR 0126 已明确否决「有 stage 即隐藏（含 dock）」——「隐藏将失去唯一常驻成员入口」）；本轮统一方向确认为「全场景恒展示」。

## 决策

1. **撤销 `poolHidden` 让位判定**：`Composer` 删除该 useMemo 与 `resolveStage` / `useSceneStore.listMode` 两处依赖引入；渲染条件回归 `{!disabled && poolSorted.length > 0}`——全部会话（含 arena 全员入席 / roundtable）在 Composer 上沿常驻成员条（@ 召唤 / 状态点 / 排队序号 / 新成员高亮）；
2. **席位组件零改动**：arena 席位卡 / roundtable 席位环的交互与状态保留，与成员条同屏并存；
3. **标题栏头像组移除维持**：ADR 0126 第 1 条不变（纯装饰冗余收口成果保留）；
4. **纯前端批次**：零协议 / 零服务端 / 零 agents 资产。

## 理由

- **一致性优先于局部去重**：让位判定对用户不可见，同一会话还会随编制 / 席位覆盖变化动态显隐——「全场景恒展示」是唯一可预期的口径（用户原话「所有的对话都需要统一」）；
- **成员条 ≠ 席位的替代物**：席位随消息流滚动离场；成员条是 Composer 常驻入口，承载席位不具备或不全的直接可操作信息（排队序号角标 / 全场状态点 / 新成员高亮）；
- **信息增量正交**：席位回答「谁在哪个席」（结构可视化），成员条回答「随时召唤谁 / 谁在发言 / 谁在排队」（操作面）——并存是操作面 + 结构面双表达而非冗余；
- **实现最简**：删除一个 useMemo 与两处依赖，判定面归零；测试覆盖收敛为「恒展示」单口径。

## 被否决的方案

- **统一为全场景隐藏（含 dock / stream）**：删除唯一常驻成员入口（@ 菜单仅打字时可用，排队 / 状态不再常驻可见），功能倒退——ADR 0126 已否决同构方案（「有 stage 即隐藏（含 dock）」）；
- **保留让位判定仅调参数（如 roundtable 也不隐藏）**：未消解「判定不可见、跨会话不一致」的根因，用户感知的时有时无依旧存在；
- **成员条并入席位（完全收口单入口）**：stream / dock / 纯列表无席位载体——ADR 0126 已否决（收口过猛）；
- **让位时增加解释性提示（保留判定的折衷）**：为不可见判定增加解释成本，问题本体（跨会话不一致）未解。

## 适用与失效条件

- 适用：全部会话形态的 Composer 上沿成员条（arena / roundtable / dock / stream / 纯列表 / 空编制回退）；
- 失效条件：若未来重新引入「席位覆盖时让位」类判定，须重新评估「跨会话一致性 vs 局部去重」的优先级并同步修订本 ADR；
- 已知边界：arena / roundtable 会话中成员条与席位同屏并存（刻意保留的操作面 + 结构面双表达）；`poolHidden` 判定代码整体删除、无残留。
