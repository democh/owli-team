# ADR 0015：Skill 机制——文档驱动 + 渐进式披露

- 状态：Accepted
- 引入：v1
- 相关：[design.md §23](../design.md)、ADR 7

## 背景

角色需要领域知识（如代码评审清单 / API 设计规范 / 测试计划模板）。备选：全部塞进系统提示（上下文浪费），或按需加载。

## 决策

**Skill = 文档 + 渐进式披露**：

- `skills/<name>.md`：front-matter 元数据（`name` / `description` / `triggers`）+ 正文方法论；
- **元数据常驻**：系统提示中只注入 Skill 索引（名字 + 一句描述 + 触发场景）；
- **正文按需加载**：模型判断需要时调用 `load_skill(name)` 工具取回全文；
- 角色 front-matter `skills: [...]` 声明预载清单，引擎按清单过滤可用技能（最小权限）；
- `npm run check:skills` 校验文档合法性。

## 理由

- 上下文预算是稀缺资源（ADR 19）：7 个角色各预载 3 份技能全文会吃掉数万 token；
- 渐进式披露把成本降到「只在使用时付费」：索引约几十 token，正文按需注入；
- 文档驱动与 ADR 7 一致：技能迭代不需要改代码。

## 被否决的方案

- **全量预注入**：上下文浪费 + 稀释注意力（无关技能干扰模型判断）；
- **技能硬编码在工具实现里**：无法沉淀方法论文本，迭代成本高。

## 影响

- 系统提示装配含 Skill 索引层（design.md §21.4）；
- 工具集含 `load_skill`（仅已注册且角色声明可用的技能名可加载）。
