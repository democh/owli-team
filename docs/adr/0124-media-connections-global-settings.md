# ADR 0124：媒体生成迁入设置——全局连接 · IA 收口

- 状态：Accepted
- 引入：M56
- 相关：[design.md §76](../design.md)、ADR 0059（无限画布与媒体创作工作台）、ADR 0061（画布输入平权、设置主区页与媒体配置专业化）、ADR 0047（向量记忆 · 嵌入连接全局先例）、ADR 0042（连接中心与 CDP 浏览器接入）、[client/src/components/settings/MediaConnectionsSection.tsx](../../client/src/components/settings/MediaConnectionsSection.tsx)、[server/src/media/service.ts](../../server/src/media/service.ts)

## 背景

- 用户实测反馈（截图）：「连接管理 → 新建连接」出现媒体生成类型（ComfyUI / SD WebUI / OpenAI 兼容 / 任务模板）不成立——「这些应该放在设置里面，而不是连接管理」。连接管理的心智是「Agent 与用户共同操作外部系统的**凭据载体**、会话绑定后工具方可使用」（ADR 0042）；而媒体生成配置（提供方 / 地址 / 模型 / 工作流 / 能力）是**全局能力开关**——配置一次、全场景可用，不是按会话授予的资源；
- 现状错位：M31 起媒体连接沿用**会话绑定**语义——「连接管理建连接 → 会话绑定 → 才能生成」三跳，且未绑定时生成面板引导去连接管理，与「媒体生成本就是全局能力」的直觉持续冲突（用户截图实锤）；
- 先例已存在：embedding 连接（M25，ADR 0047）即「全局共享、不参与会话绑定，在「设置 → 向量记忆」中启用」（绑定接口对其返回 `400`）——媒体连接对齐该纪律即可消除 IA 矛盾，无需发明新机制；
- 沉淀已就绪：`/api/media/providers` 路由挂 `/api` 之下（不受会话路径约束），`MediaService.providersOf()` 只需从全局连接清单派生。

## 决策

1. **媒体连接全局共享**（服务端去会话绑定）：
   - `MediaService.providersOf()` 无参——启用中的媒体连接清单由全局 `connections.list()` 派生；`resolveConnection(connectionId?, capability)` 在**全局启用连接**中解析（缺省取首个启用连接），未配置引导「尚未配置媒体生成连接：请到「设置 → 媒体生成」创建并启用连接」；
   - 绑定守卫：`POST /api/sessions/:id/connections` 对 media 返回 `400`（「媒体连接不参与会话绑定（在「设置 → 媒体生成」中配置启用）」——与 embedding 守卫同构相邻）；
   - `GET /api/media/providers` 不再接受 `sessionId`；`GET /api/sessions/:id/canvas` 的 `mediaBound` 改为「全局是否有启用中的媒体连接」（生成面板引导共用）；
   - Agent 工具（media_generate / media_video）未配置引导文案同步指向「设置 → 媒体生成」。
2. **配置入口迁入「设置 → 媒体生成」**（客户端）：
   - 新建设置分组 `MediaConnectionsSection`（连接清单 + 新建 / 编辑 / 测试 / 删除 + 启用开关；计数文案「已配置 N 个连接 · 启用即全场景可用（无需会话绑定）」）；
   - 连接管理不再呈现媒体类型（清单过滤 / 新建类型移除 / 绑定按钮不出现）；
   - 画布生成面板空态引导与「编辑当前提供方」铅笔改跳「设置 → 媒体生成」（`requestSettingsFocus('media')` 聚焦分组 + `setAppView('settings')`）；`pendingEditId` 直达编辑机制沿用（ADR 0061），消费点随表单迁至本分组。
3. **「启用」即总开关**：设置页卡片的启用开关 = 全场景生效 / 失效（画布生成面板 + Agent 媒体工具），toast 文案明示。

## 理由

- **能力配置与凭据授予是两个心智**：媒体生成是「我要开哪种生成能力」（一次配置、全局复用）；db / ssh / chrome 是「这个会话允许操作什么」（最小权限授予）——混在一处必然产生「为什么生图还要绑定会话」的困惑，用户反馈即此；
- **对齐既有先例、零新机制**：embedding 的「全局 + 设置中启用 + 绑定 `400`」纪律（M25）直接复用，服务端两组守卫同构相邻，心智一致；
- **操作从三跳到两跳**：「设置建并启用 → 画布生成」；另配「去设置」（空态）与「编辑提供方」（铅笔）双直达路径，引导闭环；
- **数据模型零迁移**：连接表结构不变（`kind='media'` 照旧）；旧会话绑定记录不再被媒体链路读取（providersOf / resolveConnection 均走全局清单），守卫拒绝新绑定。

## 被否决的方案

- **保留会话绑定、只搬 UI**：迁移后仍需绑定才能用——IA 矛盾只搬走一半；「设置」分组语义本就是全局配置（对齐「向量记忆」）；
- **留在连接管理（仅改文案引导）**：媒体类型混在按会话授予的凭据列表中，心智冲突持续存在；用户明确要求迁入设置；
- **embedding 一并搬 / 媒体独立导航页**：embedding 已在「设置 → 向量记忆」有专组（M25 决策），无需移动；媒体生成为低频配置项，设置分组（与模型 / 向量记忆同层）足够，无需独立入口。

## 适用与失效条件

- 适用：媒体连接（`kind='media'`）的配置入口 = 「设置 → 媒体生成」；服务端全局语义 = `providersOf` / `resolveConnection` / `mediaBound`；
- 失效条件：若未来引入「工作区 / 团队」多租户维度、媒体能力需按租户隔离，则需重新引入作用域（当前单机单租户模型下全局语义正确）。
