# ADR 0204：画布并发保存合流——409 三方合并替代「本地优先覆盖」（M79-AG）

- 状态：Accepted
- 引入：M79-AG（2026-09-20）
- 相关：[client/src/stores/canvas-store.ts](../../client/src/stores/canvas-store.ts)、[client/tests/m31-canvas.test.tsx](../../client/tests/m31-canvas.test.tsx)、[server/src/routes/canvas.ts](../../server/src/routes/canvas.ts)、[e2e/m31-canvas-agent.spec.ts](../../e2e/m31-canvas-agent.spec.ts)

## 背景

M31 画布保存协议为「PUT + baseVersion 乐观锁；冲突（409）本地优先」——原注释假设「单机单用户语义下用户正在编辑的副本即最新意图」。该假设在 **agent 并发写画布**（以及多用户同会话）场景下不成立：

- E2E `m31-canvas-agent`「落位与写入反馈」在 main 长套件两次全量中失败（单跑必过），trace 定性出完整缺陷链：
  1. agent/媒体任务在服务端落位节点（PUT 服务端 doc v→v+1）并广播 `notify:canvas-changed`；
  2. 客户端本地处于 dirty/保存中 → `pullRemote` 仅置 `remotePending` 排队（不打断编辑）；
  3. 本地自动保存（debounce 到期）携带**旧 doc** PUT → 409；
  4. 原「本地优先」策略采纳服务端版本号后**原样重 PUT 本地旧内容 → 200 覆盖**——服务端刚写入的节点被静默清掉；
  5. 随后补拉得到的是被自己覆盖后的 doc，节点永久丢失（E2E 断言失败）。

教训：**409 = 真的并发写**，「本地副本即最新意图」不成立；agent 是画布的一等写入者（M31 落位/写入/自愈语义），其写入不得被用户保存静默丢弃。

## 决策

1. **409 改为「合流重放」（三方合并）**：以 `lastSyncedDoc`（上次与服务端同步的文档快照）为 base，`mine` = 本地待保存 doc，`theirs` = 409 返回的服务端最新 doc，按**节点/边 id** 合并后以 `theirs.version` 重 PUT：
   - **远端新增**（base 无 + theirs 有）→ 保留 —— agent 落位/写入不丢（本修复核心）；
   - **本地新增**（base 无 + mine 有）→ 保留；
   - 一端缺席且 base 有：缺席方未改 = 该方删除生效；改过方存在 = 保留在场方（本地未碰且远端已删 → 删；本地删除且远端未改 → 删）；
   - 双方都有：远端未改 → 本地；本地未改 → 远端；**双方都改 → 位置/尺寸取本地、其余字段取远端**（用户布局 + agent 状态机更新各取所需）；
   - 顺序：本地顺序优先，远端新增追加尾部；边同构（无字段级）。
2. **同步锚点 `lastSyncedDoc` 维护**：`load` 成功 / `pullRemote` 成功 / `save` 成功三处更新；`load` 开头置空（跨会话防串）。快照持不可变引用，合并时以引用/结构等价判定「是否改过」。
3. **二次冲突**（合并结果 PUT 又 409，并发极罕见）保持原兜底：保留本地内容（dirty 恢复）等下次编辑重试；错误提示不变。
4. **服务端零改动**：409 已返回 `{ error, doc: current }`（既有协议），合流在客户端完成。

## 被否决的方案

- **维持「本地优先覆盖」**：丢失 agent 写入（本缺陷本体）；多用户场景还会丢他人编辑；
- **改为「服务端优先」**：用户本地编辑被静默丢弃（反向问题）；
- **节点级 LWW（时间戳）无 base**：无法区分「本地删除」与「远端新增」，删除语义错误；
- **服务端做合并**：服务端没有「用户上次同步的 base」，三方合并缺角；且会把合并策略耦合进无状态存储层。

## 边界与后续

- `sameShape` 用 JSON 字符串比较（409 低频，换取确定性）；节点量大时可换引用短路（已内置 `a === b` 快路径）；
- 「双方都改」字段级规则为「位置/尺寸（本地）+ 其余（远端）」——若未来出现「双方都改数据字段」的重要场景（如协同富文本），需升级为字段级三方合并；
- 该修复不改变无冲突路径（首次 PUT 成功即返回），单机单用户行为零变化。
