# ADR 0216：Agent Studio——AI 生成 Agent / Skill 草稿（生成与落盘分离）

- 状态：已采纳（2026-09-23）
- 相关：`docs/agent-studio-design.md`（详细设计）· M26 资产控制台 · `check:agents` 六段骨架门禁

## 背景

M26 资产控制台已具备手填式创建 / 编辑 / 校验 / 热生效全链，但「新建 Agent」需用户手写六段人设正文
（职责 / 专业判断 / 工作方式 / 质量与自检 / 交付契约 / 协作接口），门槛高、易产出空壳；Skill 同样需手写手册。
用户诉求：**一句话描述 → AI 生成结构合规、可直接使用的 Agent / Skill 草稿**，且「新建 Agent」链路整体补全优化。

## 决策

1. **生成与落盘分离**：生成端点只产草稿（内存流转）；落盘一律复用既有 `createAgent` / `createSkill`——
   校验 / 409 冲突 / `notify:assets-changed` 播报单点收口，**不新增写盘路径**。
2. **严格 JSON 契约**：`AgentDraft` = front-matter 字段 + 六段 `sections`（段名与 `check-agents.ts` 同源），
   服务端组装 `body = 六段按序拼接`；`SkillDraft` = name / description / tags / body。
3. **生成后校验回环**：解析失败 / 六段缺失 / 段过短 / 正文不足 / id 冲突 / 引用越界 → `issues` 回注提示词重试
   （≤3 轮）；终轮**带 issues 返回**（不阻断——由用户决定重生成或手改）。
4. **上下文注入**：现有场景清单（含成员链）+ 技能名单；`handoff` / `skills` 只允许真实 id（越界过滤并提示）。
5. **服务端一次性调用范式**：复用 `resilientStream` + `extractJson`（与摘要压缩同族），temperature 0.4 +
   `json_schema` 轻量约束；模型 = `cfg.llmModel`。
6. **未装配 503**：`ApiDeps.assetGen` 可选——测试夹具行为与现状零差异（与 MCP / 媒体 / 仪式订阅同惯例）。

## 被否决的备选

- **前端直连 LLM**：绕过服务端上下文与校验，且扩大密钥暴露面；
- **生成即落盘**：未审草稿直接写仓库资产，污染与回滚成本高；
- **复用会话引擎跑生成**：需临时会话 / 运行，重且污染会话列表与用量口径；
- **全量 JSON Schema 约束嵌套结构**：提示词 + 轻量 schema + 服务端后校验已足够，维护成本更低。

## 后果

- 新建角色从「手写六段」降为「描述 → 生成 → 编辑 → 提交」；Skill 可一键生成并直接进编辑器；
- 生成质量与六段门禁同频（生成即验），资产底线不依赖模型自觉；
- 后续（v2 候选）：AI 生图头像、生成角色自动 eval 自评、整套生成（新场景 + 角色 + 技能包）。
