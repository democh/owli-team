# ADR 0119：裁决回填遵循统一回填语义——只写草稿 · 运行中禁用 · 计分派生（M43）

- 状态：Accepted
- 引入：M43
- 相关：[design.md §72.3 / §72.5](../design.md)、[docs/scene-chat-design.md §11](../scene-chat-design.md)、ADR 0064（交互卡片回填 = 草稿）、ADR 0112（场景工作区体系）、ADR 0118（对决布局与裁决卡挂载）、[client/src/components/chat/WaveGroup.tsx](../../client/src/components/chat/WaveGroup.tsx)、[client/src/components/scene/ArenaStage.tsx](../../client/src/components/scene/ArenaStage.tsx)、[client/src/lib/pk.ts](../../client/src/lib/pk.ts)

## 背景

- PK-4 规划「裁决卡 = 对决组尾部 → composerInsert 模板」；PK-5 规划「计分板 = 派生（立论 / 被响应 / 轮次）→ quiet 下仅静态文本」——需要明确：裁决动作的语义（直发还是草稿）、运行中的可用性、以及计分 / 裁决流派生的数据边界；
- 既有先例：ADR 0064 已确立「交互卡片回填 = 草稿」的统一语义（checklist / 议程 / 议题 / 派活全部只写草稿不直发）；裁决的四种动作（采纳正方 / 采纳反方 / 两案并保留 / 再来一轮）都是**对会话的指令**，与派活同构；
- 风险点：「再来一轮」模板含 `@双方`——若直发会立即把双方重新召唤入队（对运行中的会话是二次触发）；且裁决发生在运行收束后，直发会绕过用户对「是否收口」的最终编辑权。

## 决策

1. **裁决四动作只写草稿（composerInsert），不直发、不落库**：`verdictTemplates(left, right)` 返回四模板——采纳「正」（收口指令：列出胜方要点与败方风险提示）/ 采纳「反」（同构）/ 两案并保留（适用条件 + 切换信号 + 共同底线）/ 再来一轮（`@左 @右 请再交锋一轮：针对上一轮未回应到的分歧点逐一回应`）；点击 → 写入 Composer 草稿（可编辑 / 可放弃）；
2. **裁决卡仅挂载于最新波且运行中禁用**：`isLatestWave`（order 尾部向前取最后一条 agent 消息 === 本组成员末尾）判定「当前对决」；运行中（busy.streaming）按钮禁用（title「运行中不可裁决：等待本波完成」——运行中插话与裁决语义混淆）；
3. **计分板（PK-5）与裁决流为纯前端派生**：DuelMeter 由 `duelTally`（两侧发言数 / 被响应数）投影；ArenaStage 裁决流由 `::: verdict` 容器消息按时间投影（标题兜底 `duelVerdictLabel`）；论断树 / 报价流面板由 claim / offer 容器消息投影（`claimNodesOfContent` / `offersOfContent` + `offerAmount` 数值化 + 相邻 delta）；全部不落库、不走服务端接口（ADR 0112 / 0117 同口径）。

## 理由

- **与 ADR 0064 统一**：裁决是「用户对会话的裁定意图」——把发送权留给用户（草稿可编辑成更精确的收口指令）避免「点一下就把双方召唤入队」的意外；四动作中「再来一轮」尤其如此（直发等价于自动续战）；
- **运行中禁用防歧义**：运行中的 Composer 输入有插话语义（插话进当前波）；裁决按钮若同时可用，两条路径的后果不同（裁决是收口意图、插话是介入当前波）却长得一样——禁用到本波完成使语义单一；
- **「仅最新波」是裁决范围的界定**：历史波次的裁决卡已过时（后续波可能已消化分歧）——重挂历史裁决按钮会让用户「裁决一个已经继续了的对决」；最新波判定用派生口径（不新增状态）；
- **计分 / 裁决流零接口成本**：数据已在前端消息流（`useSceneMessages`），投影为纯函数（可单测）；落库需要协议、编排、存档三侧扩字段与迁移，收益为零。

## 被否决的方案

- **直发裁决消息**（点击即发送模板）：绕过用户确认；「再来一轮」直发等价于自动续战（可能形成循环对决）；与 ADR 0064 的既有全部交互卡（checklist / 议程 / 会议派活）冲突；
- **裁决落库为会话状态位**（`session.verdict = 'left'`）：会话语义位需要三侧同步维护；裁决的实际效果是「生成一条收口指令」而非「记录一个状态」——指令进入消息流后自带记录（用户可见 / 可追问）；
- **运行中也允许裁决**（按钮可用，随消息进入下一波）：与插话路径并发产生双重意图，编排侧行为不可预期（两条消息同波？裁决优先？）；禁用是零歧义的表达；
- **历史波次保留裁决卡**：过时裁决误导用户对「已继续的对决」重复收口；最新波判定为派生成本最低的正确口径；
- **计分板 / 裁决流走服务端聚合接口**：数据已在前端，聚合为纯函数投影；接口化只增不减（ADR 0112 / 0115 同口径）。

## 适用与失效条件

- 适用：`verdictTemplates` / `duelTally` / `duelVerdictLabel` 为纯函数，与 WaveGroup、ArenaStage 共用；ADR 0064 的回填语义是全站交互卡统一契约（本决策是其在对决场景的实例化）；
- 失效条件：ADR 0064 若被推翻（某类卡片改为直发语义），须同步重审本决策的适用范围；「再来一轮」模板的措辞若调整须复核其 `@双方`（含召唤语义——草稿态安全，直发态危险）；运行中禁用依赖 busy 组件的 streaming 口径，若 busy 语义调整（如区分「可插话 / 不可插话」）须复核禁用条件；最新波判定依赖 order（消息有序数组），若消息流改为增量游标须复核。
