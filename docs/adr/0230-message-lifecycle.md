# ADR 0230：消息生命周期（撤回 · 编辑标记 · 仅自己删除）

- 状态：Accepted
- 引入：M90
- 相关：[ADR 0228](0228-im-message-reliability.md)（消息可靠性）、[ADR 0229](0229-quote-reply-and-session-prefs.md)（引用快照）、[ADR 0198](0198-blocked-dm-message-semantics.md)（拉黑消息面）

## 背景

此前的「删除」是**硬删除且对所有人生效**：作者点删除会连同他人视图一起消失；没有撤回占位、编辑不可见，也没有「只从我这里删掉」。这带来三个问题：

1. **误删不可逆**：一条消息从所有成员、引用卡片、列表预览里同时消失，且锚点丢失。
2. **编辑无痕**：正文被改后，接收方无法知道内容已变化。
3. **无法个人清理**：被刷屏或敏感内容只能让所有人一起删，或自己忍受。

## 决策

1. **撤回（recall）**
   - 新端点 `POST /sessions/:id/messages/:messageId/recall`。
   - 仅**作者本人**（`role='user'` 且 `userId` 匹配；兼容模式无 userId 视为本人）。
   - 窗口 **2 分钟**（服务端按 `createdAt` 判定；客户端只做入口显隐，服务端权威）。
   - 会话运行中禁止撤回（避免撤回正在被处理的输入）。
   - 撤回保留消息行：清空 `content`、`attachments`、`mentions`、`humanMentions`、`reasoning`、`toolCalls`，写入 `recalled_at` / `recalled_by`；广播 `notify:turn-end` 让多端 upsert 为占位。
   - 引用快照投影为 `recalled: true`；客户端显示「原消息已撤回」，不可跳转。
   - **不删除磁盘附件 / 交付件**：文件有独立生命周期，撤回只撤销「消息内的呈现」；需要彻底删除文件应走交付件管理。
2. **编辑标记（edit）**
   - 沿用 `PATCH /sessions/:id/messages/:messageId`，仅作者、仅用户消息、运行中禁止。
   - 写 `edited_at`；客户端在时间旁显示「已编辑」并给出编辑时间。
   - 已撤回消息禁止编辑（`400`）。
   - 引用快照仍保留发送时的原文，**不随编辑改变**（引用是「当时回复了什么」）。
3. **仅自己删除（hide-self）**
   - 新表 `message_hides(user_id, message_id, session_id, hidden_at)`（迁移 v41），不删消息行、不影响他人。
   - `DELETE /sessions/:id/messages/:messageId?scope=self`：任何可见成员（含 viewer）都可执行；用户主题广播 `notify:message-deleted`（payload 带真实 `sessionId` 与 `scope`）供本人多端同步。
   - 读取侧统一排除：会话详情（分页前过滤 / `totalCount`）、未读聚合、会话列表最后一条预览。
   - 移除后不可恢复；消息仍参与其他成员的事实与统计。
4. **删除（所有人）**
   - 保留既有 `DELETE` 无 `scope` 行为：作者本人或会话属主可硬删除，运行中禁止；UI 文案明确为「删除（所有人）」。
   - 与撤回的区别：撤回是作者在时限内的可解释动作（留占位），硬删除是治理动作（不留占位）。

## 理由

- **撤回必须保留占位**：引用、锚点、审计与「这里发生过什么」都需要行存在；硬删除会让引用变成死链。
- **编辑必须留痕**：聊天是协作记录，静默改写会破坏信任；`edited_at` 是最小成本的可审计信号。
- **个人删除不能只做客户端过滤**：刷新、多端、列表预览与未读都会暴露；必须服务端按用户过滤。
- **列表预览与未读同源排除**：只过滤详情会出现「会话列表还显示被自己删掉的内容」的隐私回退。
- **运行中禁止撤回 / 删除**：避免与引擎正在消费的消息产生竞态；宁可让用户等一轮。

## 被否决的方案

- **撤回即硬删除**：丢失引用、锚点与占位语义，且无法解释「消息去哪了」。
- **撤回无时限 / 属主可撤回他人消息**：撤回会改变对方的表达记录；时限与作者限制是必要边界。
- **撤回时删除磁盘文件**：附件可能被其他消息 / 交付件引用；文件生命周期应由交付件管理，不应由消息撤回连带删除。
- **编辑时同步改写引用摘要**：引用应表达「我当时回复的内容」，随编辑漂移会产生历史不一致。
- **仅客户端隐藏**：多端 / 刷新 / 列表预览 / 未读全部泄露；不可接受。
- **仅自己删除同时减少服务端未读总数**：未读是个人游标推导，已通过聚合排除实现；不需要改全局计数语义。
- **把「删除所有人」直接改成撤回**：治理场景仍需要硬删除（违规内容），必须显式区分两种动作。

## 适用与失效条件

- 适用：当前单进程 / SQLite 部署；人物会话与团队会话；兼容模式（无账号时撤回按无 userId 视为本人，自删返回 400）。
- 失效条件：
  - 若引入「管理员内容治理 / 合规留痕」，硬删除需改为软删 + 审计表，且撤回与删除的审计字段需扩展；
  - 若撤回时限需要按会话 / 组织配置，`RECALL_WINDOW_MS` 应从常量迁到配置；
  - 若消息支持多版本正文（编辑历史），`edited_at` 需升级为版本表，引用可选择性跟随版本；
  - 若引入服务端离线推送，自删与撤回需要同步到推送网关，避免已撤回内容出现在通知正文。
