# ADR 0131：可玩盘面——四张排盘卡的交互化与参与式游戏化（M54）

- 状态：Accepted
- 引入：M54
- 相关：[design.md §83](../design.md)、[docs/pan-interactive-design.md](../pan-interactive-design.md)（设计基线）、ADR 0113（M53 四张专业盘面卡——派生格式与契约测试来源）、ADR 0112（场景工作区 chartboard——面板接入）、ADR 0064（回填 = 草稿，用户确认后发送——本 ADR 全量复用）、[client/src/components/chat/md-ext/pan/](../../client/src/components/chat/md-ext/pan/)（派生层与四盘板）、[client/src/components/chat/md-ext/PanCard.tsx](../../client/src/components/chat/md-ext/PanCard.tsx)、[client/src/components/scene/panels/ChartboardPanel.tsx](../../client/src/components/scene/panels/ChartboardPanel.tsx)、[agents/metaphysics/_protocol.md](../../agents/metaphysics/_protocol.md)（协议 #14）

## 背景

- 用户原话「不要只是简单的表格，可以增加交互和游戏性，让用户参与感更强」——M53 交付后四张盘（八字 / 紫微 / 星盘 / 卦）信息已专业化，但呈现仍是静态行渲染（`PanCard` 字段行、`PanBoard` 静态行），阅读单向零交互；
- 关键机会：盘面数据已**全量在卡内**（黄经与度数、干支、大限年龄、世应动变、六爻数……），且卡格式已被契约测试（`m53-pan-card`）锁定——交互化可做到纯前端派生、零工具、零协议变更；
- 设计基线 `docs/pan-interactive-design.md` v2（947 行）：四盘交互详设 + 参与层（摇卦台 / 报数 / 档案 / 合参 / 足迹）+ 合规红线（不得吉凶评分 / 签到 / 成就墙）；
- 参与层引入一项诚实边界问题：前端摇卦 / 报数若本地预测卦名，可能与工具复算结果不一致（信任崩塌）——须定断言纪律。

## 决策

1. **交互化 = 纯前端派生（零契约 / 零工具 / 零服务端）**：`model.ts` + `derive.ts` 从 `::: pan` 容器卡文本派生交互模型（全量数据取自卡内）；必需门（八字 = 四柱 + 五行 + 日主 + ≥1 大运；紫微 = 12 宫全项）不过 → `null` → 回退静态表格。表格为回退终点：`PanCard` 不替换为盘面，明细与 Agent 复制原文形态恒可达。
2. **默认盘面 + 视图切换记忆 + 流式冻结**：可派生卡默认盘面（`PanView` 懒加载 + ErrorBoundary + Suspense——pan 目录单 chunk，失败回退表格）；切换记忆 `ma:pn:view:<sid>:<mid>`（session）；流式期一律回退表格（半截卡不派生）。
3. **回填一律草稿（ADR 0064 复用）**：全部交互产出（柱详情请教 / 摇卦请解 / 报数起卦）只写 Composer 草稿，不自动发送、不落库；板内不直接触达 Composer（外壳注入 `onAsk`——单一回填入口）。
4. **摇卦台种子可复现**：公开仪式种子（crypto 随机）+ `mulberry32(seed)` 现推六爻，与 `gua_pan`（method=coin）同源表逐位一致（单测断言）；`ma:pn:toss` 只存 `{seed, question, done, startedAt}`（结果恒由种子现推）；请解草稿携种子与 `gua_pan（method=coin，seed=…）` 参数供复算。**报数起卦不本地预测卦名**——只生成参数草稿，卦名由工具复算（诚实边界）。
5. **档案本地 session 作用域**：`ma:pn:archive:<sessionId>`（聊天卡与面板同键共享），上限 20 FIFO（溢出提示），本地私密不落库；同型盘对照差异高亮（`diff.ts`）；异类盘只并排（`.pn-arch-mix`「异类盘仅并排」，不虚构可比性）。
6. **合参年龄轴口径**：统一年龄轴（0 → 两盘最晚终限）；出生年已知（盘内「命造」公历日期）同轴双标年份，缺失只显年龄绝不虚构；泳道一 = 八字大运（当前段 ● + 当前大运内流年点）、泳道二 = 紫微大限（当前段 ●）；点选任一段双泳道联动高亮 + 只读详情行；只呈现盘内行运数据，不推测应期。
7. **研习足迹只读无成瘾**：`ma:pn:trail:<sessionId>` 去重计数（看过 N 张盘 · 十二宫已游历 N/12 · 摇卦 N 次 · 请教 N 次），页脚只读小字；无连击 / 签到 / 成就墙等任何成瘾机制（合规红线）。
8. **协议 #14 断言纪律**：metaphysics `_protocol.md` 第 14 条——用户以摇卦台 / 报数起卦发来的草稿（含种子 / 两数）必须先经 `gua_pan` 复算，禁止直接采信草稿中的卦名与动爻结论；解读前复述本卦 / 变卦 / 动爻 / 世应并核对一致，不一致以工具结果纠正并说明。
9. **面板接入（chartboard）**：`PanBoard` 多盘 tabs 接盘面（M54-A/B）；面板补合参 toggle（同人双盘时头部 → 双泳道）与档案抽屉（⭐ 入口经 `PanCard` 与面板统一，会话共享同一键）；「看解读」→ 消息定位语义不变。

## 理由

- **纯前端可行**：盘面数据全量在卡内 + 格式契约（`m53-pan-card`）稳定——交互化零边际成本（无新工具 / 协议 / 服务端）；
- **三段回退兜底**：不可派生（必需门）/ 加载失败（Boundary）/ 流式期（冻结）皆回退表格，既有断言面零回归；
- **种子公开复现**：占卜的可验证性——用户手里的卦与工具复算的卦必然同一卦（解卦可信度基石）；
- **不预测卦名**：卦名唯一事实来源在工具（前端只提供参数），避免「前端说 A 卦、工具排 B 卦」的信任崩塌；
- **草稿纪律**：占卜场景回填误触尤其敏感，全量经用户确认（与 ADR 0064 一致）；
- **档案 / 足迹本地**：占卜数据敏感（私密）+ 零服务端成本；FIFO 20 防膨胀；
- **年龄轴对齐**：大运 / 大限天然为年龄区间——同轴可比性最高，缺出生年降级不虚构。

## 被否决的方案

- **服务端新增交互接口或新工具**：零协议优先，种子复现机制已足够（设计 §9）；
- **引入图表库 / three.js**：自绘 SVG、零新依赖（与项目体量一致）；
- **吉凶评分条 / 运势卡 / 签到 / 成就墙**：合规红线（§5.6）；
- **PanCard 直接替换为盘面**：表格必须保留——回退终点 + Agent 复制原文形态；
- **客户端本地预测报数卦名**：映射规则不在卡格式内，交工具复算（诚实边界）；
- **档案 / 足迹入服务端（跨会话持久）**：敏感数据 + 零成本原则，session 本地足矣；
- **全局悬浮摇卦入口**：入口收敛在卡与面板（无卡环境不上全局入口——开放点 v2 默认）。

## 适用与失效条件

- 适用：metaphysics 场景四盘（八字 / 紫微 / 卦 / 星盘）的聊天卡与 chartboard 面板；不可派生卡（旧卡 / 缺段 / 损坏）恒回退表格；
- 失效条件：① `::: pan` 卡格式演进（`m53-pan-card` 契约变更）须同步复核 derive 必需门与对照口径；② `gua_pan` 起卦算表或种子算法变更须重核对「同种子逐位一致」单测；③ ADR 0064 回填语义升级须重审决策 3；
- 已知边界：档案 / 足迹 session 作用域（跨会话不互通）；合参仅八字 × 紫微（星盘泳道待真实需求）；窄屏盘面横向滚动（`.pn-scroll`）。
