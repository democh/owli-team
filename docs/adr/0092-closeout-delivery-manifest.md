# ADR 0092：收尾交付清单化与消息内交付明细（Closeout Delivery Manifest & In-Message Delivery Rows）

- 状态：Accepted
- 引入：M37（M37-6 修订）
- 相关：[design.md §52](../design.md)、[docs/scene-chat-design.md](../scene-chat-design.md)、ADR 62（视图层派生）、ADR 64（交互回填语义）、ADR 65（波次分隔与定位：结构键 / 指纹隔离先例）

## 背景

- M37-6 初版收尾卡（`CloseoutCard`）无条件渲染「本轮已交还」仪式文案：每轮结束都出现固定内容（无交付件也出现），信息密度低、存在感冗余；
- 交付件在对话流内仅有 chips（`ArtifactChip`），清单与体量信息只在「交付件」主区 Tab 可见——「本轮产出了什么」需要在会话内直接可读；
- 约束：收尾卡必须纯前端派生（ADR 62，不动消息协议）；流式期消息不带 `artifacts`（`run:end` 时 `refreshMessages` 才从快照回填）；kind / size 元数据不在消息上（在 `GET /api/sessions/:id/artifacts`）。

## 决策

1. **无交付件不渲染**：删「本轮已交还」固定文案——收束语义由「你的回合」交接条承载（消息级派生，先于收尾卡出现）；收尾卡只在**本轮有交付件**时渲染为**本轮交付清单卡**；
2. **清单卡内容**：件数徽标 + 收束波次（最大 turnIndex+1）+ 交付者头像流（≤5 + 溢出计数）+「打开交付件面板」；明细行 = 类型图标（kind 色系与交付件浏览器 / 图谱同源）+ 目录 + 文件名 + 交付者 + 体积；≤8 行，超出引导至交付件面板；快捷继续 chips（草稿回填，ADR 64）；彩纸仅新近完成播放；
3. **消息内交付明细行**（`DeliveryList`：`ArtifactRow` / `DeliveryFiles`）：消息内 chips 升级为同族明细行；行点击打开交付件视图（`requestArtifact`），悬停浮现「送上画布」（`sendArtifact`）；
4. **元数据会话级共享缓存**（`lib/use-artifact-meta.ts`）：kind / size 按（sessionId + `artifactVersion`）单次拉取、并发去重（inflight 键）、失败静默回退（扩展名粗判图标）、切换会话清空；仅由可见组件挂载触发（隐藏态不拉取）；
5. **派生指纹含交付计数**：尾条指纹 = `id~role~status~user~targets~本轮交付件计数`——流式 delta 不改指纹（不触发重渲染）；`run:end` 快照回填使计数 0→N → 指纹变化 → 重派生（修复「回填后清单停在空态」的缓存失效时序）。

## 理由

- **信息就地**：「本轮产出了什么」在消息流尾部与消息内直接可读；交付件面板降级为「全量与历史版本」的深入入口（卡片与行均可一键直达）；
- **不新增协议**：全部从既有消息字段派生（ADR 62）；服务端零改动；
- **性能与降级**：指纹隔离保证流式期零重渲染；元数据单次共享拉取（N 条消息 1 个请求）；元数据缺失回退「扩展名图标 + 名称」——不阻塞消息渲染；
- **内容随轮次生长**：件数 / 波次 / 作者 / 体积替代千轮一面的固定文案；彩纸只在真实收束的新近轮次播放，收尾卡由「仪式」变为「产物目录」。

## 被否决的方案

- **保留固定文案但降存在感**（灰色细字）：仍是无信息量的每轮噪音，且与「你的回合」交接条语义重复；
- **消息协议扩展「轮次交付摘要」字段**：违反视图层派生纪律（ADR 62），需服务端 / 持久化 / 压缩 / eval 全链同步——为纯展示需求引入协议面；
- **逐消息独立请求交付件元数据**：N 条消息 N 次请求（虚拟列表滚动反复挂载）——共享缓存按会话维度一次拉齐；
- **无元数据时显示骨架**：静默降级（名称 + 粗判图标）体验优于骨架闪烁（收尾卡 / 交付行为非关键路径）；
- **清单并入「你的回合」交接条**：交接条是紧凑胶囊（一行），承载不了明细；两者分层——胶囊管收束、清单管产出。

## 适用与失效条件

- 适用：交付件均由 `write_file` / `edit_file` / `apply_patch` 等工具落工作区（`artifacts` 进消息字段）；收尾判定 = 尾条成员「完成」且仅 @用户、无运行中 Run；
- 失效条件：
  - **轮次无 artifacts 但确有产物**（如仅口头结论）——收尾卡不渲染（用户可从消息与面板查看）；若未来引入「轮次摘要消息」形态再重估；
  - **交付件数量常态化 > 8**——行数上限与引导文案需重估（当前 ≤8 行 + 面板引导）；
  - **消息协议引入逐消息元数据**——共享缓存 hook 可退役，改直读消息字段。
