# ADR 0033：Run 内并行波次——显式触发、默认串行（修订 3）

- 状态：Accepted（修订 ADR 3）
- 引入：M16
- 相关：[design.md §29](../design.md)、ADR 3、ADR 20、ADR 2

## 背景

ADR 3 定下「同会话同一时刻仅一个角色发言」，理由（上下文一致性 / 流式 UI 焦点 / 守卫可证明）今天仍成立。但研发 / 圆桌 / 调研场景存在真实的并行诉求：两位成员对同一议题独立出具意见再统一收敛，比串行接力更高效且信息更全（避免锚定效应）。全盘放开并行会破坏默认路径的确定性与成本可控性。

## 决策

**回合循环升级为波次（Wave）循环：每波 1..N 位成员，波内并行、波末 fan-in；并行必须显式触发，默认路径 = 串行（单波特例，行为与 v1 完全一致）**：

- **触发规则（并集；均不满足 = 串行）**：用户消息 @ ≥2 位在场成员 / handoff 工具给出多目标（`target: string | string[]`，≤4，`user` 仅允许单独）/ 队列头部连续成员同属 `parallel: true` 的场景（研发默认 false）；`PARALLEL_MAX` 默认 3（=1 关闭），场景可覆盖 `parallelMax`；
- **波内隔离**：全波先建消息（streaming 空消息共享 `turnIndex`=波次号）并统一登记 spoken；`prepareTurn` 排除波内全部消息（`excludeMessageIds`）——同波成员互相看不到对方当前输出，统一基于波前历史（**一致性优先于实时性**）；handoff 缓冲按消息 id 分组，回合末只消费本回合目标；
- **fan-in 收敛**：`planWave` / `decideHandoff` / `mergeWaveSchedule` 三个纯函数；交还用户仅当全员交还 / 被抑制；循环检测输入升级为波次签名序列（并行波带 `+`），`rounds` 场景交替阈值 4 → 6；
- **护栏与语义**：任一成员 stopped → 整波中止（共享 AbortController）；timeout/error → 终止 Run；审批按成员粒度挂起（多审批卡并排）；压缩入口会话级互斥 + 同水位幂等；`maxTurnsPerRun` = 最大波数；
- **已知限制（接受）**：波内共享 `record.todos`（最后写入生效）与工作区——以协议（分工提示、避免同波写同一文件）兜底，不做文件锁；
- **事件与兼容**：新增 `wave:start`（串行波也发、members 长度 1）；`turn:start/end` 保持成员粒度；旧串行数据 / resume / attach 天然兼容。

## 理由

- 默认串行保留 ADR 3 的全部收益（确定性成本、单焦点、守卫可证明），并行只在显式意图下开启——「并行是特性，不是默认」；
- 波内互不可见（统一基于波前历史）避免了「基于过期上下文」与「基于竞态上下文」两类不一致：每波成员看到的世界完全一致；
- 全波先建消息 + 共享 turnIndex 让消息流邻接、seq 单调，前端「并行组」只需「同 runId + 同 turnIndex 连续 ≥2 条」即可推导，渲染零新增协议；
- 三个纯函数替换单成员调度，判定逻辑可单测矩阵全覆盖（触发规则 / 合并 / fan-in / 循环签名）。

## 被否决的方案

- **默认并行（@ 多少人就是多少波并行）**：成本与竞态不可控，破坏默认路径确定性；
- **波内成员可见彼此实时输出**：上下文竞态（先见者的输出依赖对方半成品），且流式顺序不确定；
- **并行波占多个回合配额**：无谓耗尽 `maxTurnsPerRun`（语义定为最大波数）；
- **文件锁 / todos 合并（强一致写）**：工程复杂度高、收益低，协议分工已覆盖主要场景；
- **新开并行专用 API / 事件族**：与既有队列 / 事件重复，前端要维护两套归约。

## 影响

- `scheduler.ts` 拆出 `planWave / decideHandoff / mergeWaveSchedule`；`engine.ts` runLoop 波次化；`turnIndex` 语义 = 波次号（前端并行组 / 图谱同层高亮的推导依据）；
- handoff 工具 `target` 支持多目标（≤4）；mock 剧本天然交错输出供 E2E 断言；
- 前端：`wave:start` 归约、并行协作组容器、指挥台 / 状态条多流高亮；e2e 新增 @ 两人并行与圆桌两条主链路。
