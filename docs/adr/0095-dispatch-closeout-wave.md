# ADR 0095：调度收口波（Dispatch Closeout Wave）

- 状态：Accepted
- 引入：M46-2
- 相关：[design.md §55](../design.md)、[server/src/orchestration/engine.ts](../../server/src/orchestration/engine.ts)、[server/src/context/assembler.ts](../../server/src/context/assembler.ts)、ADR 82（调度官一等成员）、ADR 86（召集单一收口）、ADR 90（调度接手护栏）、ADR 92（收尾交付清单）

## 背景

- 调度官（知舟）派发成员后，链路的自然终点是「某位成员 @用户 交还」——调度官作为总调度却可能在收尾时**缺席**：用户看到的最后一条是业务成员的一句话，没有「谁做了什么、产出在哪、下一步」的汇总；
- 真实故障（头脑风暴会话，run_7b3fda05 / run_43713c38 / run_78ecb13b 连续三次）：调度官派发定稿任务后 Run 直接结束，最终交付件从未产出，用户反馈「没有汇总给我」——修复派发丢失（ADR 94）后，派发能执行了，但「执行完无人收口」的体验断裂依然存在；
- 调度官是唯一持跨成员视野的角色（roster_catalog + 交付件目录 + 全链发言），由其收口符合「总调度」语义；成员收口则只有局部视野，且串行下「最后一棒」随执行顺序漂移。

## 决策

1. **收口波由引擎追加**（`engine.ts` `maybeAppendDispatchCloseout`）：波合并判定 `merge.handedToUser` 且队列已空时，满足下列全部条件即把调度官追加进队列（每 Run 一次，`dispatchCloseoutAdded` 幂等）——本 Run 未追加过 / 未触发循环抑制（`loopSuppressed`）/ 调度官在场且本 Run 已发言（`spoken` 含调度官）/ 调度官不在本波（自己交还无需再收口）/ `dispatchTurns < DISPATCH_MAX_TURNS_PER_RUN`（护栏复用）；
2. **入队即续跑**：`record.queue.push(dispatcherId)` + `dispatchCloseoutPending = true` + `handedToUser = false`（清除交还标记，Run 继续）；trace `dispatch:closeout`（载荷 `dispatcherId`）；
3. **收口回合指令**（`assembler.ts`）：调度官波启动时消费 `dispatchCloseoutPending` → 装配【收口汇总】——核对成果（读关键交付件）→ ≤200 字收口摘要（完成了什么、产出在哪、下一步建议）→ 不再派发 / 不再召集 → 摘要末尾 `@用户` 交还；收口回合不注入 roster_catalog（无召集语义）。

## 理由

- **闭环 = 有产出 + 有汇总**：交付清单（ADR 92）解决「产出可见」，收口波解决「有人告诉你产出在哪」，两者合起来才是用户视角的完整收尾；
- **复用既有机制**：收口波是普通单成员波（波次循环 / 消息流 / 事件 / 护栏全部原样），零新事件类型、零新端点、前端零改动（调度官消息即普通成员消息）；
- **幂等与护栏叠加**：每 Run 一次 + 接手护栏 ≤3 次 + 循环抑制检查，收口不会制造新的调度循环；
- **纯增益边界**：无调度官会话 / 调度官未发言的 Run / 调度官自己交还的波，零变化。

## 被否决的方案

- **派发回合让调度官预告汇总**：此时成员尚未执行，无事可汇总，等于写空话；
- **由最后一棒成员汇总全链**：成员只有局部视野（波内互不可见、看不到他人交付件全文），且「最后一棒」在串行队列中随波次漂移，不可靠；
- **前端把最后一条消息包装成「汇总卡」**：表面功夫，无实际内容与核对行为（收口要读交付件）；
- **每次交还都收口**：同一 Run 内多次交还（如成员报备式交还）会重复收口，且与「调度官自己交还」重复；限定「全链交还且队列空」+ 每 Run 一次即收敛。

## 适用与失效条件

- 适用：会话含调度官资产且调度官在本 Run 已发言的全部场景（串行 / 并行 / rounds / plan / review 波型叠加无冲突）；
- 失效条件：无（若未来引入「用户显式关闭收口」会话选项，由该选项控制本机制；机制本身不退场——「无汇总」是默认体验缺陷）。
