# ADR 0085：无 @ 路由调度优先（No-Mention Messages Route to the Dispatcher First）

- 状态：Accepted
- 引入：M46
- 相关：[design.md §54](../design.md)、ADR 3 / 33（发言并发度：顺序执行 / Run 内并行波次）、ADR 48（回合范式与计划审批）、ADR 82（调度官为显式一等成员）、ADR 88（调度波恒 execute）

## 背景

- 现行首发队列：`mentioned.length > 0 ? mentioned : participantIds.slice(0, 1)`——无 @ 消息永远盲投编制链首位，不做意图识别；
- 调度官在场时，无 @ 消息应当由调度官接手（意图识别 → 召集 → 派发）；但两条既有语义必须零变化：@ 直达（用户显式点名）、消息级显式 `plan` / `review`（对具体工作的指令，规划 / 评审目标通常已明确）；
- 插话补位（runLoop「队列已空但仍有插话」分支）取「首位未发言者」，同样需要与首发同优先级。

## 决策

launch 首发队列改四分支（engine「首发队列」）：

```
① mentioned.length > 0                 → queue = mentioned            // @ 直达（零变化）
② opts.mode === 'plan' | 'review'      → queue = [首位业务成员]        // 消息级显式范式不走调度官
③ dispatcherId（调度官在场）            → queue = [dispatcherId]        // 调度官接手（新）
④ 兜底                                 → queue = participantIds.slice(0, 1)  // 与旧行为一致
```

- 分支 ② 取「首位**非调度官**成员」（`businessFirst`）：调度官按 `order: 1` 居编制首位，直接 `slice(0, 1)` 会把显式范式指令投给调度官并悬空（只读门控下无法执行规划 / 评审）；
- 会话级 `planFirst` **不走**分支 ②（消息级 `mode` 未显式指定）：调度官接手，规划顺延业务首波（ADR 88）；
- 插话补位同优先级：`mentioned → 调度官 → 首位未发言者 → 首位成员`；
- 兼容矩阵：含调度官 + 有 @ = 直达（零变化）；含调度官 + 无 @ + 消息级 plan/review = 首位业务成员（兼容）；含调度官 + 无 @ + 会话 planFirst = 调度官接手 + 规划顺延；无调度官（含全部旧会话）= 与现状完全一致。

## 理由

- **意图识别前移**：无 @ = 未定向需求，正是调度的职责域；@ = 用户显式点名，调度不介入（尊重显式，不猜测）；
- **显式范式优先**：消息级 plan/review 是「对具体工作的指令」——目标已明确时绕一圈调度只会降低确定性、增加一次调度回合成本；
- **逐条兼容**：分支 ①②④ 与旧行为逐条一致，仅 ③ 是新增；无调度官会话（含全部历史会话）走 ④ 零差异。

## 被否决的方案

- **所有无 @ 都先调度官**（含消息级 plan/review）：与显式范式语义冲突（ADR 48）——用户显式表达的计划 / 评审意图被调度吞掉一轮；
- **仅首条消息走调度官**（后续无 @ 回旧逻辑）：多轮追加需求（「再补个测试」「换成英文」）失管，体验割裂；
- **对 @调度官 特判直投**：@ 分支已天然覆盖（调度官是普通成员，可被 @）——无需特例。

## 适用与失效条件

- 适用：单调度官；M24 显式范式体系；
- 失效条件：
  - **多调度官 / 团队前置形态**——优先级表需扩展「选哪个调度官」维度；
  - **新增回合范式类型**——分支 ② 的范式集合需同步扩展（否则新范式会被调度接手，语义漂移）。
