# ADR 0234：群主转让

- 状态：Accepted
- 引入：M90
- 相关：[ADR 0134](0134-multi-user-foundation.md)（多用户基座）、[ADR 0142](README.md)（会话共享）、[ADR 0194](0194-people-sessions-kind-and-dm.md)（人物会话）、[ADR 0230](0230-message-lifecycle.md)（消息生命周期）

## 背景

会话属主（群主）是唯一的治理角色：改名、移出成员、解散群聊、转让前都只能由 owner 执行。此前 owner 只有两个出口：

- **解散 / 删除**：历史、成员关系、工作区引用一起消失；
- **继续持有**：owner 离职或转岗后，群聊无人可治理。

缺一个可逆、可审计的交接动作。私聊不需要该动作（两方对等，没有治理角色）。

## 决策

1. **API**
   - `POST /sessions/:id/transfer`，body `{ userId }`。
   - 仅当前 owner（`assertSessionOwner`）；`direct` 会话返回 `400`。
   - 目标必须是**现有共享成员**且账号为 `active`；不能转让给自己 / 非成员 / 停用账号。
2. **原子事务**
   - `sessions.owner_id = target`；
   - 旧 owner 写入 `session_members`（role = `editor`），保留读写访问；
   - 新 owner 从 `session_members` 移除（owner 由 `sessions.owner_id` 承载，不双写）。
   - 事务失败则整体回滚，不出现「无主」或「双 owner」中间态。
3. **可观测**
   - 审计 `session.owner-transfer`（detail `{ from, to }`）；
   - 群内系统事件条「A 将群主转让给 B」并广播 `notify:turn-end`；
   - 广播 `notify:share-changed`（action `owner`），成员面板与会话列表实时刷新；
   - 新 owner 收件箱收到「你已成为「X」的群主」。
4. **UI（首期仅群聊）**
   - 群成员弹窗中，owner 对每个成员行有「转让群主」入口（Crown 图标）+ 二次确认；
   - 转让成功后弹窗重新加载：新 owner 显示群主徽章，旧 owner 显示为成员（editor），治理按钮消失；
   - team 会话仍走共享弹窗，本批不新增转让入口（API 已支持，后续按需接入）。

## 理由

- **保留旧 owner 访问**：交接不是惩罚；直接降为无权限会让历史贡献者失去上下文，也容易导致误操作后无法回退。
- **只允许转给现有成员**：避免把会话「送」给一个没有上下文的外部账号，也绕开邀请 / 好友限制。
- **owner 不双写成员表**：既有模型明确 owner 由 `sessions.owner_id` 承载；新 owner 若同时留在 `session_members`，权限矩阵会出现双角色歧义。
- **事务 + 系统事件 + 审计**：治理动作必须可回放；单条 UPDATE 无法表达成员表同步，必须事务。
- **私聊拒绝**：私聊没有「群主」语义，转让会改变双方对等关系，且已有「隐藏」表达退出意图。

## 被否决的方案

- **解散后重建**：丢失消息、交付件与成员关系，不可接受。
- **转让给非成员**：绕过邀请与好友约束，且对方没有会话上下文。
- **旧 owner 直接失去访问**：交接后无法回看历史，操作不可逆。
- **新 owner 同时保留成员行**：owner 与 editor 双角色，权限与投影歧义。
- **admin 强制转让**：管理面旁路会破坏「owner 自治」；如未来需要合规治理，应单列管理员接管流程与审计。
- **私聊也支持转让**：语义不成立；私聊退出用隐藏，双方对等。
- **转让后自动退出旧 owner**：与「保留访问」目标冲突；退出仍可走 `/leave`。

## 适用与失效条件

- 适用：多用户模式的 `group` / `team` 会话；目标为现有活跃共享成员。兼容模式 / 私聊不适用。
- 失效条件：
  - 若引入「多管理员 / 群主轮值」，需扩展成员角色模型，不能只改 `owner_id`；
  - 若引入「组织级接管 / 合规转移」，需新增管理员流程、双人审批与独立审计，不可复用本接口的 owner 自助语义；
  - 若群主转让需要通知所有成员（站内信 / 推送），需扩展收件箱广播范围与推送网关；
  - 若 team 会话也需要 UI 入口，应在共享弹窗复用同一 API 与二次确认模式。
