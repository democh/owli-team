# ADR 0235：搜索筛选（我发的 / 时间范围 / 含附件）

- 状态：Accepted
- 引入：M90
- 相关：[ADR 0233](0233-search-visibility-and-context-jump.md)（搜索可见性与历史直达）、[ADR 0230](0230-message-lifecycle.md)（消息生命周期）

## 背景

搜索已经支持个人可见性过滤与命中直达，但在长会话里仍有明显噪声：

- 只想找自己说过的内容，却混入大量 Agent 发言；
- 只记得「最近几天」的讨论，却要翻很早的命中；
- 只想找带附件的消息，只能逐条看。

没有筛选时，用户只能靠关键词不断收窄，或者翻页人工过滤。筛选必须与「个人可见性」同一层执行，否则会先被 `limit` 截断再过滤，产生「筛完没结果但实际有」的假空。

## 决策

1. **服务端筛选参数**
   - `GET /api/search` 新增：
     - `mine=1`：仅当前登录用户发送（`m.user_id = 当前用户`）；
     - `from=ISO` / `to=ISO`：按消息 `created_at` 闭区间；
     - `hasAttachment=1`：`m.attachments IS NOT NULL`。
   - 非法时间返回 `400`；`to` 只做上界，不自动补齐到当天结束（客户端负责传当天 23:59:59 或直接用 ISO）。
   - 筛选在 `SessionStore.search` 的 SQL 层执行，与自删 / 撤回 / 会话可见性同一 `WHERE`，再 `ORDER BY` + `LIMIT`。
2. **客户端交互**
   - 只有输入关键词后才显示筛选条：`我发的` / `含附件` / 时间范围（全部 / 今天 / 近 7 天 / 近 30 天）/ `重置`。
   - 兼容模式无账号时不显示「我发的」。
   - `from` 由客户端按本地时区计算：今天 = 本地 0 点；近 N 天 = 当前时间往前 N 天，再转 ISO。
   - 筛选变化与关键词共用 250ms 防抖 + `AbortController`：旧请求被取消，避免竞态覆盖。
3. **边界**
   - `mine` 只匹配人类消息 `user_id`；Agent 发言不参与「我发的」。
   - `hasAttachment` 只看发送时落库的附件元数据；附件被后续清理不影响已落库消息的筛选结果。
   - 时间比较使用规范化 ISO 字符串（`Date.parse` → `toISOString`），避免不同时区格式导致字典序错误。

## 理由

- **必须在 SQL 层**：先 `LIMIT 30` 再客户端过滤，会把符合条件的更早命中截掉，用户看到「没有结果」但实际存在。
- **筛选与可见性同层**：自删、撤回、会话 ACL 与筛选同一条查询，避免组合条件出现绕过。
- **时间由客户端计算**：「今天 / 近 7 天」是本地时区概念；服务端只接受绝对时间，语义清晰且可测试。
- **不立即做发送者下拉**：全量 Agent 名单有上百项，下拉成本高；先覆盖最高频的「我发的」，Agent 维度等有明确诉求再加。
- **筛选条只在搜索时出现**：不搜索时显示筛选会占用左栏空间，也容易让用户误以为筛选作用于会话列表。

## 被否决的方案

- **客户端过滤**：受 `limit` 与分页截断影响，结果不完整。
- **服务端提供 `range=today/7d` 预设**：需要服务端知道用户时区；客户端算绝对时间更准确。
- **发送者下拉（全部 Agent）**：选项过多、左栏拥挤；`mine` 已覆盖最常见场景。
- **附件筛选解析 JSON**：`attachments` 是 JSON 文本，解析成本高且易错；列非空即代表有附件（发送时写入）。
- **时间默认补齐到当天结束**：会让 `to` 语义隐式变化；显式 ISO 更可预期。
- **把筛选混入会话列表筛选 chips**：两套筛选语义不同（搜索范围 vs 列表范围），合并会混淆。

## 适用与失效条件

- 适用：FTS5 + LIKE 回退；多用户与兼容模式（`mine` 仅多用户有效）；消息 `attachments` 以列非空表示有无附件。
- 失效条件：
  - 若附件改为独立表 / 多附件分表，`hasAttachment` 需改为 `EXISTS` 子查询；
  - 若搜索迁移到独立索引服务，筛选需下推到索引查询或查询后二次过滤（注意 limit 语义）；
  - 若需要按 Agent / 角色筛选，应补 `agentId`（成员键）参数与受控候选 UI，不宜直接暴露全量名单；
  - 若引入「消息归档 / 冷存储」，时间筛选需同时路由到冷存储。
