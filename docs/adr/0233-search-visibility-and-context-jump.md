# ADR 0233：搜索个人可见性与历史命中直达

- 状态：Accepted
- 引入：M90
- 相关：[ADR 0230](0230-message-lifecycle.md)（仅自己删除 / 撤回）、[ADR 0228](0228-im-message-reliability.md)（消息序号与分页）、[ADR 0231](0231-session-archive-and-mark-unread.md)（归档）

## 背景

全文搜索已存在（FTS5 trigram + LIKE 回退），但接入消息生命周期后暴露出两类问题：

1. **个人可见性被绕过**：`message_hides`（仅自己删除）已经接入会话详情、未读与列表预览，但 `SessionStore.search` 没有过滤——用户自己删掉的消息仍能被搜出来；撤回消息虽然有正文清空，但依赖落库刷新，显式过滤更稳。
2. **命中无法直达**：搜索结果只返回 `sessionId / messageId / content`。客户端 `focusMessage` 不知道目标 `seq`，只能从最新页开始逐页 `loadEarlier` 回翻；长会话定位最早命中可能加载几十页。

另外，搜索标题用 `sessions.list(ownerId)` 取，只覆盖「本人拥有」的会话，共享会话命中标题为空。

## 决策

1. **搜索查询与个人视图对齐**
   - `search(q, limit, ownerId)` 的 SQL 增加：
     - `m.recalled_at IS NULL`（撤回对所有人不可检索）；
     - `NOT EXISTS (message_hides ...)`（仅自己删除只影响本人搜索结果）。
   - `ownerId === null`（单用户兼容模式）不做自删过滤，因为没有账号与个人隐藏语义。
2. **命中携带定位元数据**
   - `MessageSearchHit` 增 `seq / createdAt / role / agentId / memberKey / userId`；路由再投影 `senderName`（agent 用资产名、user 用显示名、system = 系统）。
   - 路由标题改用 `listForUser(uid)`（无 uid 时 `list(null)`），覆盖共享会话。
3. **命中直达历史上下文**
   - 客户端搜索命中把 `seq` 传给 `focusMessage(id, seq)`；ChatArea 检测到 `focusRequest.seq` 时调用 `SessionStore.loadAtMessage(seq)`。
   - `loadAtMessage` 请求 `GET /sessions/:id?limit=100&before=seq+1`，**替换**当前消息窗口为目标附近一页；进入 `historyMode`。
   - 历史模式显示「正在查看历史消息 · 回到最新」；`BottomFollower` 关闭（不被新帧拽回底部）；新帧只更新窗口内已加载消息（编辑 / 撤回 / 回应），**不追加新消息**，避免与历史页尾形成虚假相邻；「回到最新」调用 `selectSession` 重新加载最新页并退出历史模式。
   - 历史模式下发消息：Composer 先 `selectSession` 回到最新页再发送，避免新消息落入窗口间隙。
   - 没有 `seq` 的旧定位入口（右侧接力、通知等）保留原有逐页回翻路径，行为不变。
4. **分页边界**
   - `loadAtMessage` 的 `hasMore` 仍表示「还有更早」；历史窗口可以继续上滑加载更早，但不会自动加载更新的消息，统一由「回到最新」退出。

## 理由

- **搜索不能成为隐私后门**：详情、未读、列表都排除了自删消息，搜索必须同口径；否则「删了还能搜到」是明显的信任破坏。
- **用 seq 直达而不是无限分页**：已有 `seq` 是会话内单调序号，`before=seq+1` 一次就能定位；逐页回翻在长会话中既慢又占内存。
- **替换窗口而不是拼接**：把「目标附近一页」与「最新页」硬拼会产生不可见间隙，滚动位置与 `hasMore` 语义都会混乱；显式历史模式 + 回到最新更可解释。
- **发送即回最新**：历史窗口内发送会让新消息、Run 状态与流式输出都落在窗口之外；先回最新是符合预期的收敛。
- **保留旧路径**：不是所有定位都带 seq（通知 / 接力视图），强制改造会扩大风险；带 seq 才优化。

## 被否决的方案

- **客户端过滤自删消息**：客户端不知道全部隐藏集合，分页下只能过滤已加载的命中；必须在 SQL 层。
- **新增 `/search/context` 端点**：现有会话分页已能表达 `before=seq+1`，新增端点会增加协议面与测试面。
- **把目标页拼接到最新页之后**：会产生消息间隙，虚拟列表、`hasMore`、未读与「回到最新」都会失真。
- **回退已读游标 / 修改分页游标以定位**：破坏单调推进与多端一致性。
- **搜索只返回最新一页命中的上下文**：目标在更早历史时仍然找不到。
- **历史模式继续自动跟随新消息**：用户正在看历史，被新帧拽到底部是打断；关闭跟随并显式提供「回到最新」。

## 适用与失效条件

- 适用：当前 FTS5 + LIKE 回退、会话内 `seq` 单调、消息分页 `before` 游标；单用户兼容模式（无个人隐藏）与多用户模式。
- 失效条件：
  - 若搜索改为独立索引服务（Elasticsearch 等），个人隐藏与撤回需要在索引侧过滤或查询后二次过滤；
  - 若会话消息改为服务端游标分页 / 无 `seq`，历史直达需要新的定位键（如消息时间 + id）；
  - 若引入「搜索结果上下文预览」而不是跳转会话，则需要独立上下文接口与新的 UI 模式；
  - 若允许「恢复自删消息」，`message_hides` 过滤需支持恢复后的重新可见。
