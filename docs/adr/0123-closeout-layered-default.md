# ADR 0123：交付清单分层默认——最终交付优先 · 过程产物折叠（M37-6 续修订）

- 状态：Accepted
- 引入：M37-6 续修订
- 相关：[design.md §52.4](../design.md)、[docs/scene-chat-design.md §5](../scene-chat-design.md)、ADR 0092（收尾交付清单化与消息内交付明细）、ADR 0062（场景差异化限定于视图层派生）、ADR 0064（交互卡片回填 = 草稿）、[client/src/lib/delivery.ts](../../client/src/lib/delivery.ts)、[client/src/components/chat/CloseoutCard.tsx](../../client/src/components/chat/CloseoutCard.tsx)

## 背景

- 用户实测反馈（截图）：投资研究会话收尾卡「本轮交付 14 件」中 12 件为 `charts/` 行情快照（量化成员落盘数据），两份结论性报告（`docs/基本面分析-增长主线.md` / `docs/技术面分析-增长主线.md`）被数据明细行淹没；原形态「≤8 行 + 还有 N 件 · 打开交付件面板查看全部」只做截断、不分主次——数据行占满默认视图、结论件排序不可控；
- 目录约定有据：`charts/` 是金融行情与博弈快照的落盘约定（`server/src/finance/snapshot.ts`、`server/src/finance/game`），其 `.json` 快照 kind 实测为 `code`（`classifyKind` 仅 `*.chart.json` 归 chart）——与源码不可分；各场景 AGENT.md 交付契约以 `docs/` 为主（122 处）——**路径首段是唯一稳定的「结论 / 中间态」信号**；
- 约束不变：收尾卡纯前端派生（ADR 0062）、零协议零服务端改动；kind / size 元数据不在消息上（异步补齐），分层与排序必须只看路径（先于元数据到达即稳定）。

## 决策

1. **分层判定下沉纯函数模块**（`client/src/lib/delivery.ts`）：`isProcessArtifact`（路径首段命中过程目录 `charts` / `data` / `raw` / `cache` / `tmp` / `temp` / `logs`）＋ `deliveryTier`（文档 md / office / pdf → 0 ＞ 图示与页面 html / mermaid → 1 ＞ 媒体 → 2 ＞ 源码文本 → 3 ＞ 数据 csv / json → 4）＋ `partitionDelivery(entries, limit)`；
2. **默认只展示最终交付**：非过程产物按重要度稳定排序取前 `DELIVERY_PRIMARY_LIMIT = 5`；过程产物与溢出项进「其他」组（保持原交付顺序）；头部「本轮交付 N 件」计数仍为全量；
3. **「其他」组默认折叠、箭头双向**：组头 `其他 · N 件` 即开关（ChevronRight 旋转 90°，`aria-expanded`），全展示 / 收起互切；主区为空的极端（全为过程产物）「其他」默认展开，卡片不空；
4. **撤销「≤8 行 + 还有 N 件 · 面板查看全部」形态**：面板入口由卡片头部 PackageOpen 按钮单独承载；新增锚点 `data-delivery-group="primary|others"` / `data-delivery-toggle`，`data-delivery-row` 不变（既有断言沿用）；
5. **折叠态为卡片本地态**：`null = 未操作`（默认口径），用户展开 / 收起后维持；新尾条（tailId 变化）重置回默认；
6. **整清单可整体收起隐藏**（同日用户二次反馈「是整个都可以收起隐藏」）：卡片头部左簇（图标 + 标题 + 件数 + 波次 + ChevronRight）即整体开关——收起后隐藏全部文件行（主区 + 「其他」组），仅留概要行与底部快捷继续；整体折叠与「其他」组相互独立（整体收起再展开，「其他」保持原状态）；默认展开，新尾条重置；锚点 `data-delivery-collapse`。

## 理由

- **默认视图 = 结论**：收尾卡是「本轮产出了什么」的就地目录（ADR 0092），结论性交付件应当占据默认视图；快照数据是成员过程材料，降为一次点击可达；
- **路径首段是唯一稳定信号**：kind 不可用（charts 快照 `.json` 实测 `code`）、文件名自由度高（关键词启发式易误伤）、元数据异步到达（排序需即时稳定）；
- **全量仍可达**：箭头全展示（组内）＋ 头部面板入口（全量与历史版本），信息无损；
- **层层可收起**：默认视图（结论前 5）→「其他」组（过程产物）→ 整清单（仅留概要）——卡片占位与信息密度逐级可控，长会话回看不被交付明细挤占；
- **零协议零服务端**：纯前端派生（ADR 0062 延续）；lib 纯函数 + 卡片交互可单测全覆盖。

## 被否决的方案

- **按 kind 判过程产物**：`charts/*.json` 实测 kind=code，与源码不可分；`.chart.json` 才归 chart——不足以支撑分层；
- **文件名关键词启发式**（day / week / min60 / backtest / snapshot 等）：真实模型命名自由度高，易误伤结论件（如「回测报告.md」），规则不可枚举；
- **服务端新增「重要性 / 类别」字段或交付清单模型**：违反视图层派生纪律（ADR 0062），需存储 / 压缩 / eval 全链同步——为纯展示需求引入协议面；
- **仅截断不折叠**（原 ≤8 形态延伸）：数据行仍占默认视图，且结论件排序不可控；
- **默认全部展开**（保持原平铺）：截图实测即「结论被数据淹没」的根因；
- **默认折叠但主区为空时留在折叠态**：只剩一个折叠开关的收尾卡观感如残卡——空主区自动展开是无成本兜底；
- **整体折叠与「其他」组共用一个开关**（一键全藏 / 全展）：两种程度诉求不同（组内全展示 vs 整卡隐藏），共用开关会互相覆盖状态、行为不可预期——两个独立开关（头部整体 + 组头其他）。

## 适用与失效条件

- 适用：交付件为工作区相对路径；过程目录集合为唯一判定源（新增数据落盘目录时在 `lib/delivery` 登记）；E2E `m37-scene-chat` 清单断言（`data-delivery-row` 首个可见）在 mock 研发链（全 `docs/` 交付）下不受影响；
- 失效条件：
  - **交付协议引入显式类别 / 重要性字段**——改用显式字段，过程目录集合退役；
  - **`charts/` 开始承载结论性交付**（如落盘图表 HTML）——须重估过程目录口径；
  - **主区上限与场景事实冲突**（某场景常态化只交付文档且 > 5）——上限为常量（`DELIVERY_PRIMARY_LIMIT`），按实测再估。
