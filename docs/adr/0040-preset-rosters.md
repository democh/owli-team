# ADR 0040：快速组队预设——_presets.yaml 资产化与建会话交互

- 状态：Accepted
- 引入：M21
- 相关：[design.md §34](../design.md)、ADR 28（Agent 包化与场景分组）、ADR 30（会话动态成员）、ADR 37（OPC 业务场景编制）

## 背景

OPC 场景下最高频的协作形态是**跨场景组队**：周经营例会（幕僚长 + 财务 + 增长 + 销售）、内容营销战役（增长 + 内容 + 搜索 + 品牌）、报税合规（财务 + 税务 + 法务）、融资冲刺（融资 + 财务 + IR + 法务）。这些编制横跨多个场景目录，手动在既有「按场景组队」流程里逐个挑人繁琐且易漏人；且每次建会后还需手打同一段开场指令（谁先说什么）。

既有原则：资产即数据（编制模板属「角色编制知识」，应与 agents/ 资产同源、可热更新、零代码扩展）。

## 决策

**以 `agents/_presets.yaml` 资产化编制模板，并将建会话入口升级为「快速组队优先」**：

- 数据文件：6 条跨场景编制，每条含 `id / name / description / icon / theme / members / prompt（开场指令模板）/ order`；`prompt` 内含 `@角色` 引用（≥2 人）以复用既有的并行波次触发语义；
- 数据链路：loader 解析（文件缺失 → 空数组）+ zod 校验（成员必须存在、id 全局唯一、members 非空）→ 纳入 `collectFiles` 热更新清单 → `validate()` 跨引用校验 → `GET /api/agents` 响应增加 `presets` → `client/src/stores/agent-store.ts`；`check:agents` 打印预设清单兜底；
- 建会话对话框（三步流 Step 0）：顶部「快速组队」区（preset 卡片：icon + 名称 + 一句话 + 成员头像堆叠 + N 人）→ 点击进 Step 1（成员按 preset 预选、可微调，显示来源与「开场指令将预填」折叠预览）；下方保留「按场景组队」（9 张场景卡，按钮语义与文案不变）与「自由组合」入口；
- 创建成功后把 `preset.prompt` 写入 Composer 草稿键 `ma:draft:<sessionId>`（与 Composer draftKey 一致，避免会话切换竞态）→ toast「已预填开场指令」；
- Command Palette 新增「新建会话」分组（6 条 preset + 9 条场景），经 `ui-store` 的 `pendingCreate` 状态预选并打开对话框。

## 理由

- **预设即资产**：编辑一个 YAML 文件即可新增 / 调整编制，无需发版；与「新增角色只改 agents/」的资产哲学一致；成员校验复用 `check:agents` 与 loader 的既有跨引用机制（id 全局唯一使跨场景引用天然成立）；
- **复用 `/api/agents` 而非新端点**：预设与角色 / 场景同属「编制元数据」，同源返回避免两次往返与前端状态分叉；缺失文件时字段为空数组，前端整体降级隐藏，无兼容负担；
- **草稿预填而非自动发送**：开场指令是模板不是命令，用户需要按当周情况编辑（换主题、改数字口径），因此落 Composer 草稿而非直接发消息；草稿键与 Composer 的 `ma:draft:<sessionId>` 机制复用，天然获得「切换会话不丢草稿」行为；
- **palette 与对话框共用 pendingCreate**：命令面板「新建会话」与侧栏按钮走同一状态机（打开对话框 + 预选来源），避免两套入口两套逻辑。

## 被否决的方案

- **预设写死在前端代码**：违反资产即数据，新增编制要发版；
- **新增 `GET /api/presets` 端点**：与 /api/agents 数据源相同（同一次扫描），徒增往返与缓存一致性问题；
- **自动发送开场指令**：剥夺用户编辑机会，且与「用户消息驱动 Run」的既有语义冲突；
- **把 preset 实现为「不可见的预建会话」**：会话资产化会让模板与实例生命周期混淆，无法热更新；
- **仅做 Command Palette 入口**：palette 是新用户感知最弱的入口，建会话对话框才是主路径。
