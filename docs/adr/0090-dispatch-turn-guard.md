# ADR 0090：调度接手护栏（Dispatcher Turn Guard: ≤3 Dispatch Turns per Run plus Existing Loop Detection）

- 状态：Accepted
- 引入：M46
- 相关：[design.md §54](../design.md)、ADR 33（Run 内并行波次）、ADR 82（调度官为显式一等成员）、ADR 85（无 @ 路由调度优先）

## 背景

- 调度官接手是新增的循环节点：无 @ 消息 → 调度官召集派发 → 成员完成后 `handoff` 回调度官（二次召集 / 收口）→ 调度官再派发……极端情况下「成员 ↔ 调度官」可反复（模型行为不可完全预测）；
- 既有护栏：波签名 + 内容相似循环检测（同内容重播触发）、回合上限（`MAX_TURNS_PER_RUN`）——但调度官每次发言内容不同（合法）时签名检测不触发，可消耗大量回合；
- 候选：① 调度接手次数专用上限 + 既有检测叠加；② 无专用护栏（依赖既有）。

## 决策

1. 新增常量 `DISPATCH_MAX_TURNS_PER_RUN = 3`（engine.ts）：同一 Run 内调度官接手 ≤3 次；
2. 计数：波规划时本波含调度官 → `record.dispatchTurns += 1`（Run 级状态，不持久化）；
3. 波前护栏：达上限且队列含调度官 → 将调度官移出队列；若移出后队列为空 → 取首位未发言成员兜底（与「调度官缺席」路径同语义）；
4. **不中断 Run**：超限走常规 fallback，用户无感（无错误提示、无状态异常）；
5. 既有循环检测与回合上限原样生效（护栏叠加，不替换）。

## 理由

- **护栏叠加而非替换**：专用上限管「调度官反复接手」这一类循环，既有检测管「任意成员内容重播」——职责正交，叠加覆盖两类失败模式；
- **3 次的量级依据**：正常收束路径调度官 1–2 次接手（首波召集派发 + 可能的二次增援）；收口复用至多 +1；3 次即异常信号（正常会话极少触发）；
- **自然降级**：超出走「无调度官」路径（首位未发言者）——与「用户手动移出调度官」的既有语义逐字一致，无新失败态；
- **计数成本零**：Run 级内存字段，无持久化、无迁移、无广播。

## 被否决的方案

- **无专用护栏**：调度官发言每次内容不同时既有签名检测不触发——极端下可吃掉整个回合上限，把「调度循环」暴露为「回合耗尽」（用户可见的坏体验）；
- **硬中断 Run**（超限即停）：把护栏问题暴露为错误态；且中断语义与「会话级互斥 / 停止」的既有模型冲突（用户以为是自己的停止）；
- **首波后禁止调度官**（一次性）：误伤合法路径——成员请求增援的二次召集（需求变更 / 增派角色）是协议明确允许的；
- **按消息数而非接手次数计数**：无 @ 消息连续多条会快速耗尽配额（用户连续追问是正常行为）。

## 适用与失效条件

- 适用：单调度官；Run 生命周期内的调度计数（`dispatchTurns` 随 Run 消亡）；
- 失效条件：
  - **多调度官**——需改为按角色 / 按调度身份分别计数，护栏语义变为「单调度官上限」；
  - **调度官承担更多合法职责**（如每波强制收口、多轮评审调度）——上限值 3 需重估（可能需配置化）；
  - **长任务形态**（跨多个 Run 的持续调度）——Run 级计数不覆盖，需会话级配额（届时单独评审）。
