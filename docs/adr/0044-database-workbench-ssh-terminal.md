# ADR 0044：数据库工作台（Navicat 式）与 SSH 交互终端（M23）

- 状态：Accepted
- 引入：M23
- 相关：[design.md §36](../design.md)、ADR 42（连接中心与 CDP 浏览器接入）、ADR 43（操作直播窗与双视图联动）、ADR 11（SSE + WS 双通道）

## 背景

M22 的连接中心让 Agent 能操作数据库与浏览器，但用户侧的操作面仍只有右栏 26% 窄栏的面板，真实使用暴露三个问题：

1. **数据库只能「看」不能「用」**：右栏面板展示的是 Agent 操作的 `notify:op` 流水，用户自己无法浏览表数据 / 写 SQL——Navicat 式（对象树 + 数据网格 + SQL 编辑器）的日常操作完全缺失；
2. **SSH 是空壳**：连接表单只有「名称」，提示「SSH 连接器将在后续版本提供」；没有主机 / 端口 / 认证方式字段，没有真实测试连接，更没有交互终端——用户想手动登上跳板机没有任何入口；且既有表单把「名称」当唯一输入，用户指出「SSH 输入的内容好像不对」；
3. **手工操作不可见**：即使补上面板，用户在面板里的写操作也应与 Agent 操作一样进入操作流 / 直播窗（同一审计口径）。

用户明确要求「学习 Navicat 的交互和 UI」「SSH 使用开源好用的库」，并确认三项决策：数据库 = **主区新 Tab「数据库」**；SSH = **完整终端**（开源库 ssh2 + xterm.js）；写操作 = **执行前确认对话框**。

## 决策

**一、数据库工作台：主区「数据库」Tab，Navicat 式三栏心智**

- 布局：左窄栏对象树（连接选择 + 刷新 + 过滤 + schema 分组 + 表 / 列两级，双击开表）+ 右侧多标签（「查询」常驻第一 + 每表一个数据 Tab，可关闭）；
- 表数据浏览：服务端 `manager.tableData` 统一出口——表名 / 列名白名单校验（标识符正则 + `quoteIdent`）防注入、`limit+1` 探测 hasMore、offset/limit 服务端钳制（1–500）；
- 共享 DataGrid：列排序三态循环（升 → 降 → 取消）、分页（每页行数可选）、行数范围徽章、刷新；
- SQL 面板：`POST /api/connections/:id/sql` 单一入口；**读写判定在服务端**（复用 guard.ts 纯函数护栏），前端不做语句分类；
- 写确认流（两段式）：`dryRun: true` 预检返回 `{ mode }` → 写语句弹确认对话框（SQL 全文 + 目标连接 + 写入开关状态）→ 确认后 `confirmed` 直发；只读语句自动两步直发；连接未开「允许写入」时对话框内直接禁用确认；
- 与 Agent 同流：面板操作成功 / 失败均发 `notify:op`（`actor: 'user'`、`preview` 前 5 行），直播窗与右栏操作流可见手工操作。

**二、SSH：完整连接表单 + 真实测试 + 交互终端（ssh2 / xterm.js）**

- 连接表单：主机 / 端口（默认 22）/ 用户名 / 认证方式三选一（password | key | agent）；key 支持文件路径 + 内容粘贴 + passphrase；agent 模式提示 `SSH_AUTH_SOCK`；「允许 Agent 执行命令（ssh_exec）」独立开关（默认关闭）；「保存并测试」= 保存后立即真实 SSH 连接验证；
- 终端通道：`GET /connections/:id/ssh/terminal-token`（一次性 token，scope `ssh:<id>`，takeover 语义）→ `WS /ws/ssh?connectionId=&token=` 升级；**二进制帧 = 终端字节流**（原样透传，防多字节字符被 JSON 切断）、JSON 帧 = 控制消息（ready / exit / error / pong；resize / ping）；每终端一条独立 SSH 连接（不与缓存句柄共享），ws 关闭即断开；
- 前端终端：xterm.js + fit-addon（懒加载分包，约 300KB 不进首屏）；多会话 Tab + 状态徽章（connecting 脉冲 / open / closed / error + 终端尺寸）；断线手动重连；同连接二次 open = 聚焦已有会话；SessionPane 隐藏保留 DOM（切 Tab 不丢历史输出）；
- Agent 侧对称面 `ssh_exec`：requireBinding + 连接 `allowExec` 显式开启 + **每次调用审批门**（与 db_execute 同级最高危）+ `opNotify` 实时事件；非交互一次性命令，交互需求引导用户去终端页签。

## 理由

- **对象树 + 查询常驻 Tab**：与 Navicat 一致的心智模型，用户零学习成本；「查询」常驻避免每次写 SQL 都要先找入口；
- **读写判定在服务端而非前端**：只读白名单已是 guard.ts 纯函数（M22 建成、db_query/db_execute 共用），面板复用同一判定，杜绝前后端分类漂移；`dryRun` 只跑护栏不执行，成本一次本地解析；
- **确认对话框而非二次点击**：写 SQL 不可逆，「在哪个库上执行什么」需要展示全文 + 连接名 + 写开关状态做最后人工确认；「允许写入」是连接级持续授权，不等于「这一条 SQL 现在执行」的即时意图；
- **xterm.js + ssh2 而非自研**：两者是各自领域的社区标准（xterm.js = VS Code 终端内核；ssh2 = Node 生态事实标准），PTY / 真彩色 / Unicode / bracketed paste 零自研成本；
- **二进制帧而非 JSON/base64**：终端输出是高吞吐字节流，base64 有 33% 膨胀且多字节 UTF-8 会被帧边界切断渲染乱码；二进制进二进制出（键盘输入同走二进制帧）是 xterm 生态惯例；
- **每终端独立 SSH 连接**：交互终端会改 shell 状态（cd / export），与 Agent 缓存句柄（无状态一次性 exec）语义不同，混用互相污染；独立连接代价仅一条 TCP；
- **一次性 token 而非裸连接 id**：与 `/ws/stream` 同一分权纪律（M22 建成），token 握手即消费防重放；升级鉴权同 `/ws`（`BIND_ALL` 场景）；
- **隐藏保留 DOM 而非重建终端**：xterm 实例持有全部滚动缓冲（回看 / 选择 / 复制），重建即丢历史；`display:none` 成本可忽略；
- **ssh_exec 双闸（连接开关 + 每次审批）**：远程命令是「任意代码执行」级权限——连接开关表达「这个主机我允许 Agent 动」（显式、持久），每次审批让命令内容逐次可见（不因授权过一次就永久放行）；
- **懒加载分包**：xterm 不进首屏，用户不打开终端页签就不下载。

## 被否决的方案

- **右栏面板增强而非主区工作台**：26% 宽度塞对象树 + 数据网格是二维压缩，Navicat 式浏览需要主区空间；
- **iframe 嵌外部 DB 客户端 / 终端**：跨域受限、凭据无法与连接中心共用加密存储；
- **自研终端渲染（div + 光标）**：ANSI 转义序列（颜色 / 光标移动 / 备用屏）工作量巨大且永远追不上 xterm；
- **顺带做本地 shell 终端（node-pty）**：本地 shell 等同远程高权限能力，本里程碑只要求远程 SSH，留待明确需求时单独立项；
- **JSON 帧承载终端流**：多字节切断 + base64 膨胀（见上）；
- **前端正则判定 SQL 读写**：与护栏重复实现、必然漂移（新增语句类型漏一处即安全洞）；
- **写语句「连接允许即直发」**：写操作不可逆，确认框是最后一道人工闸；
- **SSH 表单仅提供 agent 模式**：Windows / 无 agent 环境（大量生产跳板机）走不通；密码与私钥是 SSH 两条主干路径，必须支持；
- **同连接允许终端多开**：收益（并行操作同一主机）极低，代价（N 倍 SSH 连接、重复 Tab 迷失）明显；二次 open 聚焦已有会话；
- **终端会话持久化（刷新后自动重连）**：终端是交互瞬时态，重连后 shell 状态已丢；状态徽章 + 手动重连已给出明确路径。
