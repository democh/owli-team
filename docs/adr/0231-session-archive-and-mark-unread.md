# ADR 0231：会话归档与「标记未读」

- 状态：Accepted
- 引入：M90
- 相关：[ADR 0229](0229-quote-reply-and-session-prefs.md)（会话个人偏好）、[ADR 0189](0189-server-authoritative-unread.md)（服务端权威未读）、[ADR 0230](0230-message-lifecycle.md)（消息生命周期）

## 背景

置顶与免打扰解决「重要会话靠前、别打断」，但还有两个日常动作没有承载：

1. **暂时不看的会话**只能隐藏（新消息复现）或删除（破坏性），缺少可逆的「收纳」。
2. **想稍后回看**的会话无法主动制造未读；用户只能依赖别人发消息来提醒自己。

两者都是**个人视图**，不能改会话 ACL、未读事实或他人的列表。

## 决策

1. **偏好字段扩展（迁移 v42）**
   - `session_prefs` 增 `archived`、`marked_unread`；`SessionPrefs` 变为 `{ pinned, muted, archived, markedUnread }`。
   - `PATCH /sessions/:id/prefs` 接受四个字段的任意子集（至少一个）；仍仅本人、仍走用户主题 `notify:session-prefs` 多端同步。
2. **归档是视图，不是删除**
   - 服务端列表**仍返回**归档会话及其 `prefs`（多端一致、归档视图需要数据）。
   - 客户端 `filterSessions` 默认排除 `archived`；归档视图以 `{ archived: true }` 单独读取。
   - 归档视图不受团队 / 聊天筛选影响，避免「归档里有但当前筛选看不到」。
   - 归档不改变会话、消息、成员与未读；新消息不会自动取消归档（与「隐藏」语义区分）。
   - 当前打开会话被归档时保持打开，列表下次刷新时移出主列表。
3. **标记未读是提醒，不是游标回退**
   - 不修改 `session_reads.last_read_seq`（保持单调推进不变量）。
   - 列表投影：`unreadCount = max(真实未读, markedUnread ? 1 : 0)`。
   - 用户真正读到消息（`POST /sessions/:id/read` 生效且 `lastReadSeq > 0`）后自动清除 `markedUnread`，并广播偏好帧；不是永久红点。
   - 客户端收到 `notify:session-prefs` 且 `markedUnread=true` 时，把本地徽章抬到至少 1。
4. **归档与免打扰/置顶正交**
   - 可同时置顶 + 归档？UI 不允许从归档视图置顶，但服务端不禁止；客户端按 `pinned` 只在当前视图内排序。
   - 归档不抑制未读与收件箱；免打扰仍只抑制普通消息提示。

## 理由

- **游标不可回退** 是 M79 的核心不变量（乱序 / 多端覆盖防线）；「标记未读」若靠回退游标会制造重复未读与竞态。
- **归档不落删除**：用户需要可逆收纳；删除会话会丢历史与工作区，代价不可接受。
- **服务端返回归档**：归档视图、跨设备取消归档、未读统计都需要同一份数据；在服务端过滤会让客户端无法在本地切换视图。
- **读到才解除**：标记未读若靠定时或打开列表清除，会变成假提醒；以实际已读上报为准最诚实。
- **与隐藏语义分开**：隐藏是「暂时移出列表，新消息复现」，归档是「主动收纳，保持归档」，两者不能合并。

## 被否决的方案

- **回退 `last_read_seq` 实现未读**：破坏单调推进，多端会互相覆盖；且自己最后一条消息不计未读，回退也点不亮。
- **归档 = 隐藏**：隐藏会被新消息自动复现，归档不会；合并会让「收纳」失效。
- **归档 = 删除**：不可逆，丢失历史与工作区引用。
- **服务端只返回未归档会话**：归档视图与跨设备恢复都要额外接口；列表过滤成本低，交给客户端更稳。
- **客户端本地保存归档 / 未读标记**：刷新与多端不一致；必须服务端事实源。
- **归档时清零未读**：会让用户错过收纳会话里的新消息。
- **标记未读永久保留**：红点失去意义；必须由真实已读解除。

## 适用与失效条件

- 适用：多用户模式（偏好需要账号；兼容模式不投影 `prefs`，归档/标记入口隐藏）。
- 失效条件：
  - 若引入「工作区 / 空间级归档策略」（全员生效），需要区分个人偏好与空间策略；
  - 若列表改为服务端分页 / 游标，归档过滤需要进入查询条件与游标计算；
  - 若「标记未读」需要指定某条消息为起点（而非整体红点），应改为「未读锚点」模型并重评已读游标语义；
  - 若引入离线推送，归档与免打扰都需要同步到推送网关。
