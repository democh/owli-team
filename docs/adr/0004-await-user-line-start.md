# ADR 0004：交还判定——仅行首 `@用户`

- 状态：Accepted
- 引入：v1
- 相关：[design.md §5.3](../design.md)

## 背景

Agent 在回复中提及用户（`@用户`）的场景有两类：结尾交还控制权（「请你确认……」），或正文中顺带提到用户。若任意位置的 `@用户` 都触发交还，正常讨论会被频繁打断。

## 决策

**仅当 `@用户` 出现在行首时才判定为交还**：引擎逐行扫描模型输出，行首匹配 `@用户` 才把 `'user'` 加入交还候选；句中提及一律不触发。交还时 `turn:end.mentions` 恒为 `['user']`。

## 理由

- 交还是强语义动作（结束本轮接力、等待人类输入），需要与「提及」区分开；
- 行首是模型输出中最容易遵守、也最容易人工核对的约定；
- v1 实践中误判率最低——句中出现用户称谓（如「供用户参考」）不会中断接力。

## 被否决的方案

- **任意位置 `@用户` 均交还**：误触发频繁，接力链被打断；
- **独立交还工具**：v1 未引入；M3 的 handoff 工具（ADR 2）可显式 `target='user'`，但行首规则仍作为文本回退路径保留。

## 影响

- Prompt 协议（`prompts/_protocol.md`）把「行首 @用户」写入输出契约；
- 引擎在调度前先从候选里剔除句中 `user`，保证「显示的事件 = 实际发生的调度」。
