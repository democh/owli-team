# ADR 0143：快捷键帮助 Tab 分组重设计——四组页签 · 说明块归位 · 键位表补齐

- 状态：Accepted
- 引入：快捷键帮助 Tab 化批（2026-09-19）
- 相关：[design.md §20.3](../design.md)（交互清单——本 ADR 修订其「快捷键帮助（M12）」行）、[design.md §91](../design.md)、ADR 0033（并行波次：页签交互同族）、[client/src/components/layout/ShortcutHelp.tsx](../../client/src/components/layout/ShortcutHelp.tsx)、[client/tests/shortcut-help.test.tsx](../../client/tests/shortcut-help.test.tsx)、[e2e/m12-interactions.spec.ts](../../e2e/m12-interactions.spec.ts)

## 背景

- 用户实测截图反馈（红框：顶栏键盘按钮与弹出的「键盘快捷键」长列表）：「优化下，使用tab进行分组管理，重新设计优化下」；
- 原实现（M12）四个分组（通用 / 输入框 / 审批卡 / 画布）纵向通铺于一屏：画布组 7 行超出视口即整层滚动，定位一组需扫读全部；行标签单行截断（`truncate`），如「临时平移（按住拖动；滚轮 / 双指直接平移，⌘+滚轮缩放）」的关键信息被截掉；
- 同一行内「可替代组合」以相邻键帽平铺（如 `⌘/Ctrl Z ⇧Z`、`⇧0 ⇧1 ⇧2`），与「同组合多键」（如 `⌘/Ctrl` + `K`）语义混淆；
- 「指派语义」说明块挂在弹层底部常驻——与它所属的输入语境（@ 语义）脱节，且为其余分组被动占用高度。

## 决策

1. **分组页签化**：通用 / 输入框 / 审批卡 / 画布 四组各占等宽页签（图标 + 标签；Radix Tabs，方向键 / Home / End 键盘可达）——一次只呈现一组，长列表消失；非当前页签内容不挂载。
2. **短组不塌陷、长组组内滚动**：内容区 `min-h-[232px]` + `max-h-[52vh]` + 内部滚动——短组（审批卡）不留大片空白的塌陷感，长组（画布 9 行）在内容区内滚动而非整层滚动。
3. **行结构升级**：快捷键数据由 `keys: string[]` 改为 `combos: string[][]`（外层 = 可替代组合，内层 = 组合键）——可替代组合以「/」分隔（`⌘Z / ⌘⇧Z / ⌘Y`）、组合键相邻并列；行支持次行小字 `note`（适用条件），取代原单行 `truncate` 截断。
4. **说明块随页签归位**：「指派语义」迁入「输入框」页签（主色强调块）；「审批卡」页签补审批流语义块（批准 → 成员继续执行；拒绝 → 改换方案；附反馈提交 → 模型据此调整——以 ApprovalPanel 实际回执文案为准）。
5. **键位表补齐**（一律以代码实际绑定为准）：画布组新增「删除选中节点 / 连线」（Backspace · Delete，React Flow `deleteKeyCode`）与「保存并提交画布文档」（⌘S，`store.flush()`）、「撤销 / 重做」补 ⌘Y 备选；输入框组新增「关闭候选 / 清空命令」（Esc）与候选补全的适用说明（候选弹层打开时 Enter 为补全而非发送）；通用组「快捷键帮助」补 ⌘⇧/ 备选。
6. **头部信息带**：图标徽章 + 标题 + 副题（「⌘ = Ctrl（非 macOS）· ? 键随时呼出，Esc 关闭」）——跨平台按键口径前置；补 `DialogDescription`（a11y：Radix Dialog 描述缺失告警消除）。
7. **页签会话内记忆**：页签选择存组件 state（弹层关闭重开停留上次分组；与 TeamPanel `lastOf` 记忆同族，不落 localStorage）。

## 理由

- **四组是天然互斥的场景面**（全局 / 打字 / 审批 / 画布）——单组内容 ≤9 行，一屏读全，替代原「按组扫读全部条目」；
- **组合键数据模型升级消除语义双关**：原 `keys` 数组混排「可替代」（⇧0 ⇧1 ⇧2）与「同组合」（⌘/Ctrl Z）两种语义，可视化时读者需自行猜测；拆为 `combos` 后渲染即语义；
- **说明块与页签绑定**在信息架构上更准确：@ 语义只在输入语境出现，审批流语义只在审批页签出现——原「底部常驻」既割裂又占高；
- **短组填充 + 长组内滚动**兼顾稳定与紧凑：弹层不因短组塌陷成小卡片，也不因画布组把整层拉长到滚动；
- **纯前端批次**：零服务端 / 零资产 / 零协议改动；入口（`?` / ⌘⇧/ / HeaderBar 按钮 / 命令面板）与 `ui-store.helpOpen` 契约零变化。

## 被否决的方案

- **保留通铺 + 分组折叠（accordion）**：仍是单列长表——展开一组需收起另一组或继续滚动，未消除「扫读全部」的定位成本；
- **保留通铺 + 组内两列网格**：弹层宽度（max-w-lg）下，每列不足以容纳「标签 + 键帽」同行，长标签必然换行溢出；
- **页签 + 搜索框过滤**：快捷键总量约 22 条、用户按场景记忆（输入 / 画布），搜索是额外输入成本；
- **三页签（审批并入输入框）**：审批卡是独立交互面（仅挂起卡出现时相关，且作用于卡片而非输入框），并入后语义混杂；
- **「指派语义」保留在弹层底部常驻**：为所有页签占用约 40px 高度，且与「输入框」页签上下文割裂；
- **页签选择持久化 localStorage**：帮助面板属低频参考面，会话内记忆足够；跨会话记忆收益低而全局存储键成本高；
- **固定弹层高度（如 h-[520px] 全组等高）**：短组（审批卡 2 行）将出现大片空白，长组内滚动成为常态——与「紧凑布局为唯一基线」的全局口径相悖。

## 适用与失效条件

- 适用：快捷键帮助面板（四组页签：通用 / 输入框 / 审批卡 / 画布）；新增分组 = 在 `GROUPS` 追加一项（`id / label / icon / items`，可选 `hint` / `note`），页签行按 `flex-1` 自动等宽扩展；
- 失效条件：① 某组条目数超过约 12 行时需重估（考虑组内分段或再分层），否则组内滚动成为主导交互；② 弹层内容区口径依赖 `min-h-[232px]` 与行高（`py-2` + 12.5px 正文 + 键帽行）——行结构 / 字号变更需同步复核最小高度；
- 已知边界：非当前页签内容不挂载（Radix Tabs 默认）——组内文案的全局文本断言（E2E / 单测）需先切到对应页签；本批已将「指派语义」断言迁移至「输入框」页签（`e2e/m12-interactions.spec.ts` 与 `client/tests/shortcut-help.test.tsx` 同步）。
