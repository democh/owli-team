# ADR 0122：裁决条目多空侧归因——翻盘条件归败方 · 阵营词归各方 · 方向兜底

- 状态：Accepted
- 引入：M52-F
- 相关：[design.md §74](../design.md)、ADR 0121（裁决状态容错与局面头）、ADR 0112（场景工作区体系）、[client/src/lib/verdict.ts](../../client/src/lib/verdict.ts)、[client/src/components/scene/panels/VersusPanel.tsx](../../client/src/components/scene/panels/VersusPanel.tsx)

## 背景

- 用户实测追问：多空对弈会话（真实裁决 `::: verdict 空方领先`）局势面板空方列有数据、**多方列恒「暂无信号」**；
- 根因：信号列归因是「按裁决方向**整列倾泻**」——裁决 status=short 时全部非元条目（核心依据 / 翻盘条件 / 空方失效条件）进空方列；多方列只有「多方胜裁决」出现才会有数据。而条目本身是**有方向的**：「翻盘条件」的语义是**败方的翻盘路径**（真实会话实锤：空方领先裁决的翻盘条件全为多方条件——「周线收盘站上 1355」「日线站上 1292 放量」「底背离确认」「公告利好且被放量定价」；mock 对称：多方领先裁决的翻盘条件为「放量跌破密集区支撑 → 裁决翻转空方」）；「空方失效条件」等条目名已冠名阵营；
- 边界：`::: verdict` 协议与裁决卡渲染（ADR 0119）不改动——只收敛「条目 → 信号列」的归因口径（面板展示层，纯前端批次）。

## 决策

1. **条目级归因**（`lib/verdict.verdictItemSide(label, status)` → `long | short | draw | meta`）：
   - 元信息（`胜负 / 置信度 / 声明` 前缀）→ meta（不进信号列，ADR 0121 口径延续）；
   - 显式阵营词（多方 / 多头 / 正方 / 看多 ↔ long；空方 / 空头 / 反方 / 看空 ↔ short）；
   - 「翻盘条件」（含「翻盘」）→ **败方**：空方领先时归多方、多方领先时归空方、僵持归中立区；
   - 其余条目 → 裁决方向侧（胜方）；none（无法判向）→ meta（裁决卡全量兜底）。
2. **面板逐条分列**（VersusPanel.buildModel）：替代「按裁决方向整列倾泻」；跨轮累计口径不变（每轮裁决按各自方向归因）。
3. **显示口径**：列计数（cap-count）为条目数；局势条仍为「方向 × 置信度」加权（ADR 0121，不变）。

## 理由

- **「翻盘条件」的语义主语是败方**：它是「推翻当前领先所需的条件」= 落后方的翻盘路径与观察点——放败方列回答用户「落后方还有没有机会、条件是什么」；放胜方列（风险视角）虽可辩护，但正是「多方无数据」观感的来源；
- **显式阵营词优先级最高**：条目名已冠名的（「空方失效条件」）按冠名归位，最不惊讶；无冠名词条才走方向兜底；
- **归因集中一处**：versus 面板与后续消费方（其它面板 / 徽章）共用同一函数；lib 语义与面板集成双层测试覆盖；
- **零协议变更**：真实模型与 mock 的现有输出形态（裁决四要素 + 失效条件 + 声明）直接可获得正确分列；协议层无需新增结构化信号容器。

## 被否决的方案

- **翻盘条件留胜方列（风险视角）**：语义可辩护但正是「多方无数据」缺陷的来源；用户视角的「各方信号」优先；
- **翻盘条件双侧镜像展示**：同一内容两列重复，信噪比下降（与 ADR 0121 元条目剔除同理由）；
- **只做空态文案软化**（「暂无信号」→ 引导语）：不解决归因缺陷——数据本就存在于条目中；
- **从双方立论消息派生信号**（扫描对弈过程消息）：真实立论为自由 markdown（无稳定结构），启发式提取可靠性低；主管「局势记录」表逐轮异形（同一会话三种表头），解析脆弱；留待协议层产出结构化信号（未来批次）——本决策先让**裁决条目**的既有数据正确归位；
- **按条目内容 NLP 判向**（如「核心依据」内文提到多方即归多方）：内容常同时涉及双方，词级判向误报率高。

## 适用与失效条件

- 适用：versus 面板及正反同构场景的裁决条目分列；阵营词表（`/空方|空头|反方|看空/` 等）若协议扩词须同步注册表；
- 失效条件：协议若引入结构化信号容器（多空条目显式分侧）则归因函数降级为兜底；「翻盘条件」若被协议改名（与「失效条件」语义合并）须重审归因词。
