# ADR 0012：运行生命周期与连接解耦

- 状态：Accepted
- 引入：v1
- 相关：[design.md §18](../design.md)、ADR 5、ADR 11

## 背景

Run（一次完整的多角色接力执行）可能持续数分钟。若 Run 绑定发起它的 HTTP/SSE 连接（连接断开即中止），用户关标签页 / 刷新 / 网络抖动都会毁掉进行中的协作。

## 决策

**Run 与连接解耦**：

- Run 由引擎持有并后台推进，SSE 连接仅是其「观察窗口」——断开不中止执行（`RUN_DETACH_ON_DISCONNECT=true`，默认）；
- 新建 SSE 连接时先重放 Run 快照（至今全部事件）再续流；
- 完成 / 交还 / 出错经 WS 通知（ADR 11），未读角标 + 系统通知提示；
- 后台并发 Run 数受 `ASYNC_RUN_MAX` 限制。

## 理由

- 多人（或单人多标签）会从不同页面观察同一 Run——解耦后多连接可同时订阅；
- 「发送后关页面，完成后收通知」是明确的用户体验目标，要求执行不依赖观察者；
- 与重放机制（ADR 5）配合，刷新零损失。

## 被否决的方案

- **连接驱动生命周期**（`req.on('close') → abort run`）：误杀长任务；刷新页面即中断不可接受。

## 影响

- 引擎维护 `Map<runId, RunState>` 与订阅者集合；`GET /api/runs/active` 供刷新后定位；
- Run 状态落 `runs` 表（M3），崩溃后 `interrupted` 可断点继续（ADR 20）。
