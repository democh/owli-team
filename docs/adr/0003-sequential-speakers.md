# ADR 0003：发言并发度——顺序执行

- 状态：Amended（M16 起为波次特例：显式触发的波内并行，见 [ADR 0033](0033-parallel-waves.md)；默认路径仍为单成员串行）
- 引入：v1
- 相关：[design.md §5](../design.md)、ADR 20、ADR 33

## 背景

会话中有多个在队角色时，同一时刻允许几个角色发言？备选：顺序执行（一次一个）或并行执行（多角色同时流式）。

## 决策

**同会话同一时刻仅一个角色发言**：调度器维护队列，每回合消费队首，回合结束后按 `turn:end.mentions` 入队下一批候选。

## 理由

- 共享上下文要求「后发言者能看到先发言者的完整输出」——并行会让各角色基于过期上下文工作，产出互相矛盾；
- 流式 UI 只有一个焦点：并行流会让消息流乱序、自动滚动不可用；
- 顺序执行让守卫规则（防自转交 / 防循环 / 回合上限）简单且可证明。

## 被否决的方案

- **并行发言**（`Promise.all` 多角色同时生成）：上下文竞争 + 消息乱序 + 工具副作用可能冲突，且成本不可控。

## 影响

- 引擎回合循环为串行状态机（`turn:start → 流式输出 → 工具循环 → turn:end`）；M16 起升级为波次循环（每波 1..N 成员，N=1 即本文的串行语义）；
- M3 的插话机制（ADR 20）在回合边界注入，不打破顺序语义。
