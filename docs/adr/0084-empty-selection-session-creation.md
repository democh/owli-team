# ADR 0084：空选择创建语义（Empty Participant Selection Resolves to the Dispatcher on the Server）

- 状态：Accepted
- 引入：M46
- 相关：[design.md §54](../design.md)、ADR 18（SQLite 持久化与迁移）、ADR 30（会话动态成员）、ADR 82（调度官为显式一等成员）

## 背景

- 零选择开聊要求 `POST /sessions` 接受空 `participantIds`；但「会话至少 1 名成员」是持久化与编排层的硬不变量（成员 API 移出护栏、引擎 launch「会话没有成员」报错、`queue ⊆ participants` 前提全部依赖它）；
- 候选方案三类：① 服务端填充 `[调度官]`；② 客户端自行填充后提交 `[调度官id]`；③ 允许真空会话（0 成员临时态）；
- 附加约束：「谁是调度官」的唯一权威判定在服务端（资产校验链）；客户端判定与资产热更新存在时序缝隙（前端可能持有过期 agents 列表）。

## 决策

1. `createSessionSchema.participantIds` 放宽为允许空数组（缺省 `[]`）；
2. `POST /sessions`：`ids.length === 0` → 全局唯一 `dispatch: true` 角色存在则填充 `[调度官]` 后走既有创建链；资产缺失 → `400`「未选择成员且调度官资产缺失（agents/ 需有且仅有一个 dispatch: true 角色）」；
3. 其余语义不变：已知角色校验 / 按 `list()` 链序排序 / 灵魂校验 / 项目关联——调度官按 `order: 1` 天然居落库编制首位；
4. 客户端**不自行填充**：0 人提交按钮文案「交给调度官 · 0 位成员」（按钮文案即显式同意），仍发送 `participantIds: []` 由服务端解析。

## 理由

- **单一收口**：缺省填充逻辑只有服务端一份——客户端不做第二份判定，防双实现漂移；资产的权威校验（唯一性 / 存在性）天然在服务端；
- **不变量保持**：落库即显式成员数组（至少 1 位），`queue ⊆ participants`、成员 API 护栏、fork 复制、计数镜像面全部无特例；
- **显式安全**：资产缺失时 400 明确提示（而非静默创建 / 静默失败），错误信息即修复指引；
- **前端可回退**：无调度官资产时前端 0 人提交维持旧拦截（「至少选择一位成员」），与旧行为逐字一致。

## 被否决的方案

- **客户端填充**（前端发 `[调度官id]`）：双份逻辑；客户端需自行判定 dispatch，与资产热更新存在时序缝隙（新装调度官前端未刷新时创建失败）；
- **允许真空会话**：破坏「至少 1 成员」不变量——编排 / 成员 API / 队列 / 图谱全部需新增空态分支，收益仅为省一次填充；
- **新增专用端点**（如 `POST /sessions/quick`）：语义与既有创建端 95% 重叠，双端点必然漂移。

## 适用与失效条件

- 适用：调度官资产存在（当前默认形态）；空数组合法值仅表示「交给调度官」；
- 失效条件：
  - **调度官资产被移出**（用户全自定义资产）——空创建回归 400（显式引导），「零选择」体验即不可用；
  - **多缺省模板**（如「空 = 调度官 / 指定场景 = 该场景默认编制」）——填充语义需升级为策略对象，schema 与文案同步扩展。
