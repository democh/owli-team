# ADR 0031：场景协议分层与技能包绑定

- 状态：Accepted
- 引入：M18
- 相关：[design.md §25.4](../design.md)、ADR 15、ADR 28

## 背景

新增的头脑风暴 / 深度研究场景各有独特的协作规范（圆桌纪律：先求量禁评判；研究规范：来源可追溯、区分事实与推断、必须给反面证据）。备选：全部塞进全局协议（研发规则与非研发规则互相干扰、长度膨胀），或每个角色人设各自重复（多处漂移、不可维护）。

## 决策

**协议分层：全局协议（怎么协作，所有角色）+ 场景协议（可选，追加在全局之后）+ 角色人设**，同时把场景默认技能纳入 `_group.yaml`：

- `agents/<场景>/_protocol.md`：场景级协作规范，**追加**语义——全局约束（交还判定 / 防循环 / 工具纪律 / 并行约定）永远生效，场景协议只做领域补充；
- L0 装配顺序：全局协议 → 场景协议 → 人设 → 灵魂段（稳定有序，prompt cache 友好）；
- `_group.yaml` 的 `defaultSkills: [...]` 声明场景默认技能（如 `brainstorm-facilitation` / `deep-research`），创建会话时并入成员的技能索引；
- 场景协议同时补充本场景的**并行轮次规范**（如圆桌：每人至少三个点子、不重复他人、先补充再挑战）。

## 理由

- 分层让「研发纪律」与「创意 / 研究纪律」互不污染，各自演进；单文件职责单一、可评审；
- 追加而非覆盖保证全局安全线（防循环、交还、审批）不能被场景协议意外放松；
- 技能包与场景绑定，让「创建头脑风暴会话」默认获得发散引导工作流，无需用户手动配置；
- 与 ADR 28 的目录模型天然对齐：协议与技能都是场景目录的一部分，随包迁移 / 校验。

## 被否决的方案

- **全部并入全局协议**：相互干扰（圆桌「禁止过早评判」与研发「验收标准先行」张力大），协议长度膨胀且无法按场景裁剪；
- **场景协议覆盖全局协议**：存在放松全局安全约束的风险，不可审计；
- **技能靠角色逐个声明不设场景默认**：新建场景会话时易漏配，体验不一致。

## 影响

- 两个新场景交付 `_protocol.md`（头脑风暴 / 深度研究）与技能包 `skills/brainstorm-facilitation/`、`skills/deep-research/`；
- `check:agents` 校验协议文件存在性与场景技能引用（缺省技能优雅降级）；
- 装配器 L0 增加一个可选段位；全局 `_protocol.md` 补充并行协作约定与灵魂优先级说明。
