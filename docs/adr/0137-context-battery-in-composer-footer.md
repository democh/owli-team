# ADR 0137：上下文用量条收编 Composer 底栏——电池容量可视化（纯前端批次）

- 状态：Accepted
- 引入：上下文电池批（2026-09-19）
- 相关：[design.md §88](../design.md)、ADR 0019（上下文工程：五层装配 + 压缩 + 记忆）、ADR 0047（L1.5 语义召回——上下文抽屉承载其明细）、[client/src/components/context/ContextBar.tsx](../../client/src/components/context/ContextBar.tsx)、[client/src/components/chat/Composer.tsx](../../client/src/components/chat/Composer.tsx)

## 背景

- 用户实测截图（谈判 arena 会话）红框标注主区顶部的「上下文 8% 15.7k / 200.0k tokens」横贯用量条，明确诉求「上下文不在 header 中展示，放到下方使用像电池容量的效果进行展示，优化设计下」；
- 既有形态：ContextBar 为主区头部（对话 / 画布页签行）之下的独立通栏（h-7，Layers 图标 + 文字 + 进度条 + 百分比 + tokens + 降级徽标 + 本 Run 费用 + 轨迹入口），永久占用垂直空间，视觉权重高于其信息价值；
- 差距：上下文用量属「低频查看、长期监视」类信息，横贯条持续挤压消息区；而电池容量隐喻在底栏小尺寸下即可传达同样的水位语义；
- **形态迭代**：初版实现为「电池壳体 + 连续填充 + 正极触点」，用户以参考图反馈「不是完全按照电池展示，像这种」——参考图为 5 段等宽横条纵向堆叠的分段格条（自下而上逐格点亮、无壳体无触点），同日修订为本形态。

## 决策

1. **位置迁移**：ContextBar 从主区头部收编至 Composer 底栏提示行右侧（`ml-auto` 右对齐），随输入区常驻；`AppLayout` 不再渲染该通栏（`mainTab === 'chat'` 分支与 import 一并删除）；
2. **形态改为电池格条（参考图样式）**：5 段等宽横条纵向堆叠（每段 20×2px、间距 1.5px、微圆角），自下而上逐格点亮、无壳体无触点；点亮段数 = ⌈水位 × 5⌉（非零水位至少 1 格，对应参考图「底部亮 1 格」的低水位态）；另有百分比数字 + token 数值（`sm` 以下隐藏数值，保留百分比）；
3. **颜色分级与水位提示**：点亮段 < 70% emerald / 70–90% amber + 百分比变色 / ≥ 90% rose + 整组呼吸提示（`animate-pulse`）；未点亮段低对比灰（hover 微提亮）、点亮段颜色 300ms 过渡；
4. **信息与入口不丢失**：
   - title 工具提示给出精确 `上下文 {pct}%（{estimated} / {budget} tokens）· 查看上下文分层与摘要`（保留原「查看上下文分层与摘要」子串，E2E 选择器零改动）；
   - 点击电池仍打开上下文抽屉（L0–L5 分层 / L1.5 召回明细 / 滚动摘要 / 记忆摘要 / 降级提示）——⌘K 命令与 `/context` 斜杠命令入口不变；
   - 「本 Run 费用」与「轨迹」入口同排保留在电池右侧；「已降级」徽标随电池显示；
5. **取数时机不变**：会话切换 / 运行结束 / 压缩事件（`compressionCount`）/ 点击时刷新——仅位置与形态变化，数据链路零改动（纯前端批次）。

## 理由

- **回收垂直空间**：消息区获得完整高度；底栏本就常驻，信息落位于此不新增占用；
- **操作 / 状态分侧**：底栏左侧为「操作」语义（范式 chips / 快捷键提示），右侧为「状态」语义（用量 / 费用 / 轨迹）——电池右对齐使状态聚拢、可扫读；
- **电池隐喻降低理解成本**：填充比例 + 颜色即水位分级，无需阅读数值即可感知剩余空间；≥90% 呼吸提示强化预算告警；
- **零协议 / 零服务端**：快照接口与数据流（`/api/sessions/:id/context`、`/api/runs/:id/usage`）完全复用。

## 被否决的方案

- **保留顶部条、仅换视觉（更细的条 / 更低调配色）**：仍占用垂直空间，与「不在 header 展示」诉求不符；
- **电池壳体 + 连续填充 + 正极触点（本 ADR 初稿实现）**：与用户参考图（5 段格条、无壳体无触点）不符，同日修订弃用；
- **电池放在输入框角落（上传 / 发送按钮旁）**：操作与状态混杂且空间不足；
- **环形进度（ring）替代电池**：小尺寸下比例辨识度低于电池（充电隐喻需阅读弧长）；
- **hover 自绘浮层显示详细数值（替代原生 title）**：需新增浮层组件与定位逻辑，收益低于 title；
- **只显示百分比不显示 tokens**：丢失「预算规模」上下文（不同会话预算可不同）；
- **移除「本 Run 费用」与「轨迹」入口**：隐式功能回退，用户未提出该诉求。

## 影响

- 前端：`ContextBar.tsx`（重写为电池格条 + 费用 + 轨迹按钮组；`batteryFill` → `litSegments` / `segmentOn` / `levelText`）、`AppLayout.tsx`（通栏渲染与 import 移除）、`Composer.tsx`（底栏右侧挂载）；
- 测试：`composer.test.tsx` / `m33-attachments.test.tsx`（fetch stub 常挂起——电池挂载即取数，避免真实网络与 act 警告）、`m24-plan.test.tsx`（`mockApi` 对 context / usage 端点挂起）；`m25-memory-panel` / `m25-frontend` 断言口径不变（渲染 ContextBar 的抽屉路径零改动）；client 全量 888/888 ✅；
- E2E：`m25-memory.spec.ts` 的 `getByTitle('查看上下文分层与摘要')` 子串匹配维持通过；无位置依赖断言；
- 文档：本 ADR、`docs/adr/README.md` 索引、`design.md §88`；`server/src/routes/runs.ts` 注释同步（顶部用量条 → 底栏上下文电池）。

## 适用与失效条件

- 适用：全部会话的对话视图（Composer 常驻场景）；画布 / 深度工作台等其他主区视图原本即不渲染该条，行为不变；
- 失效条件：若引入多预算档位 / 分层常驻可视化等新诉求，重新评估电池的信息密度与位置；
- 已知边界：电池格条不显示 L0–L5 分层明细（仍收口于上下文抽屉）；窄屏（< 640px）隐藏 token 数值仅保留百分比与格条。
