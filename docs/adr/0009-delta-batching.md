# ADR 0009：delta 渲染——40ms 批量合并

- 状态：Amended（M8 起叠加 150ms 渲染层节流）
- 引入：v1 决策，M8 修订
- 相关：[design.md §10](../design.md)、ADR 25

## 背景

流式输出每秒产生几十个 token 增量（`message:delta`）。若每个增量直接触发一次 React setState，渲染次数与增量数同级，流式期间整页卡顿。

## 决策

**数据层 40ms 批量合并**：run-store（v1 为 session-store 内逻辑）维护增量缓冲，每 40ms flush 一次合并进消息内容，`setState` 频率上限 25 次/秒。

**M8 修订**：数据层 40ms 合并保留；**渲染层再叠加 150ms 节流**（流式消息内容），二者职责分离——数据层控制状态更新频率，渲染层控制重绘频率；同时引入 Markdown 渲染 LRU 缓存与虚拟列表（ADR 25）。

## 理由

- 40ms 接近人眼可感知下限（25fps）：再快无收益，再慢有卡顿感；
- 合并是幂等的（纯文本拼接），不会丢内容；
- M8 的 150ms 渲染节流把「重 Markdown 解析」从每次 flush 降到每秒约 6 次，配合 memo 化让流式长文不再拖垮页面。

## 被否决的方案

- **每 delta 直接 setState**：500 条消息 + 流式时帧率崩塌；
- **加大数据层合并窗口到 150ms**：事件粒度变粗，工具卡 / 状态点等非文本 UI 反馈变迟钝；两层分离可以各取所需。

## 影响

- `run-store` 的 flush 定时器是流式管线核心参数（常量可调）；
- 完成态消息与流式消息走不同渲染路径（完成态全量高亮 + 缓存，流式态纯文本 + 节流）。
