# NL2SQL 取数手册

核心原则：**先对齐口径，再写第一行 SQL；不可复现的数字不进结论。**

## 使用步骤

1. **口径澄清**：落笔前对齐五要素——指标定义（分子 / 分母）、时间窗（左闭右开）、粒度（日 / 周 / 人 / 单）、过滤条件（状态 / 渠道 / 地区）、对比基准（环比 / 同比 / 目标）。不明确时问用户或显式列假设标注「待确认」。
2. **库表探索**：`db_list_connections` 看连接（未绑定时提醒用户在右侧面板「连接」页签绑定）→ `db_schema` 摸清表与列（类型 / 主键 / 可空）→ 小样本 `SELECT ... LIMIT` 抽查（枚举值 / 格式 / 空值率 / 量级）。
3. **SQL 生成**：过一遍下方规范清单再执行。
4. **执行校验**：`db_query` 执行（结果默认展示前 30 行，大表自带 `LIMIT` / `WHERE`）；执行后过校验清单，不通过先查数据再改结论。
5. **解读呈现**：结论先行（一句话含方向与幅度），按 data-visualization 技能选图，每个数字就近标注口径。
6. **口径沉淀**：SQL 原文与执行信息（连接名 / 日期）写入交付件附录；跨任务口径用 `remember` 固化。

## SQL 生成规范

- **显式列名**：禁止 `SELECT *`（列顺序 / 新增列会让下游结论失真）。
- **别名**：表别名 + 指标列别名对齐口径名（如 `SUM(amount) AS 成交金额`）。
- **JOIN**：显式 `ON`；先确认关联键粒度与唯一性（一对多会放大金额与计数）。
- **聚合**：`GROUP BY` 包含全部非聚合列；`COUNT(DISTINCT user_id)` 与 `COUNT(*)` 口径区分并标注。
- **时间**：窗边界显式写死（避免 `NOW()` 漂移）；时区显式；`BETWEEN` 注意双闭区间语义。
- **LIMIT**：探索查询必带；聚合查询先估行数再决定。
- **只读单语句**：`SELECT` / `WITH` / `SHOW` / `EXPLAIN`；写操作不在取数范围（转交数据工程）。

## 执行校验清单

- [ ] 行数 sanity：与预期量级对比（偏差 ±10 倍先停下排查）
- [ ] 总量交叉：分组合计 = 总计；库侧结果与文件侧对账（`csv_analyze`），不一致不得静默取一
- [ ] NULL 影响：关键列空值率；NULL 是否该计入分母已确认
- [ ] 去重：`COUNT(*)` vs `COUNT(DISTINCT)` 已在口径中说明
- [ ] 单位与量级：分 / 元、千 / 万、百分比 ×100 已核对
- [ ] 时间边界：首尾日期收发已核对（左闭右开）

## 常见陷阱

| 陷阱 | 症状 | 规避 |
| --- | --- | --- |
| 口径漂移 | 同指标两次取数对不上 | 五要素随结论标注；关键口径 remember |
| JOIN 放大 | 金额随关联表行数翻倍 | 关联前先验键唯一性 |
| 计数混用 | 订单数与人头数混谈 | `COUNT` 与 `COUNT(DISTINCT)` 分列并标注 |
| 时区偏移 | 日边界差一天 | 时间函数显式时区；窗边界写死 |
| 样本偏差 | 只看最近一周下结论 | 样本量写明；小样本（<5）不给个体结论 |

## 工具衔接

- `db_*` 工具默认按需加载：先 `tool_search` 检索「数据库 / SQL / schema」激活，再按 `db_list_connections` → `db_schema` → `db_query` 顺序使用。
- 文件侧数据用 `csv_analyze` 汇总（groupby / sort / filter），计算用 `calc`，日期推算用 `date_calc`。
- 结果呈现用 `chart` / `mermaid` 代码块（ECharts 直渲染），图题即结论句。

## 输出约定

- 交付件 `docs/BI分析-<主题>.md`：结论、口径、SQL 原文三者互相对得上。
- 每个数字可追溯三要素：SQL + 口径 + 连接；缺一不写进结论。
- 明细脱敏：客户名 → 客户 A、订单号 → \*\*\*1234；未脱敏明细不落盘。
