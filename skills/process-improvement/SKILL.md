# 流程改进手册

两个信念：**能写成 SOP 的事不靠记忆**；**流程要越用越薄**（每轮改进先问「这步能不能删」）。

## SOP 写法（一页一个流程）

    流程名：<动作 + 对象，如「新客户开通」>
    触发条件：<什么时候启动（事件 / 时点）>
    步骤表：| 步 | 动作 | 责任人 | 时限 | 产出/检查点 |
    异常分支：<出错 / 超时 / 特殊情形怎么走>
    完成标准：<什么算完成（可观测）>

- 每步必须有责任人与产出物；「配合一下」不是步骤。
- 检查点设在不可逆动作之前（如付款前、发布前）。
- 时限写具体（「当日 18 点前」），不写「尽快」。

## 流程梳理与优化（五步）

1. **画现状**：把现有流程逐步画出（mermaid 流程图），标注每步耗时与等待时间。
2. **找浪费**：逐类核对——等待（等审批 / 等信息）、返工、多余审批、重复录入、搬运（系统间倒数据）、过量（做多了）、库存（积压的任务）。
3. **提假设**：每个改进点写成「若 <改什么>，则 <量化收益>」；收益用周期时间 / 错误率 / 人工步骤数度量。
4. **小步试点**：先一个团队 / 两周；试点前记录基线（当前耗时与错误率），试点后对比。
5. **固化或回退**：验证有效 → 更新 SOP + 通知（走 comms-writing）；无效 → 回退并记录为什么。

## 度量口径（改进前后用同一把尺）

- **周期时间**：从触发到完成的自然时间（含等待）。
- **处理时间**：实际动手时间。两者差值 = 等待浪费。
- **错误率**：每百次执行中的返工次数。
- **人工步骤数**：需要人手动操作的步骤总数（自动化收益指标）。

## Kaizen 原则（日常改进）

- 小步快跑：一次只改一处，验证后再改下一处。
- 现场主义：去执行的人那里看真实做法（SOP 写的 ≠ 实际做的），先记录「实际流程」再优化。
- 询问执行者：他们最清楚哪一步最烦——改进方案让执行者参与写。
- 不可逆动作前加检查点；可逆动作允许先做后报。

## 检查清单

- [ ] SOP 有触发条件 / 步骤表 / 异常分支 / 完成标准
- [ ] 现状流程有耗时与等待标注；浪费分类核对过
- [ ] 每个改进点有量化假设（度量口径统一）
- [ ] 试点有基线与对照；周期 ≤ 2 周
- [ ] 固化：SOP 更新 + 通知；或回退 + 原因记录
- [ ] 每轮改进先检查「能不能删一步」

## 工具用法

- 流程图用 mermaid 代码块；SOP 落盘 `docs/sop/<流程名>.md`；改进记录落 `docs/流程改进-<主题>.md`。
- 步骤耗时 / 错误率数据用 `csv_analyze` 汇总（如可用）；周期用 `date_calc` 核算。
- 改进通知走 `comms-writing`；新流程相关的正式制度走 `formal-document`。

## 输出约定

- 交付：`docs/sop/<流程名>.md`（含版本与修订记录）+ 改进报告（基线 / 试点 / 结论 / 是否固化）。
