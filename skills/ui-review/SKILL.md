# 界面质量审查手册

走查的产出不是「感受」，而是**可应用清单**：每条发现 = 严重度 + 位置 + 违反的规则 + 修法。不给「提升体验」类空话。

## 输入：优先审渲染后的界面

- 有浏览器接入时：打开真实页面，在 360 / 768 / 1280 三档宽度截图——审渲染态，不只审源码。
- 无浏览器工具时：读代码（`read_file` / `search_text` / `grep`）按同一清单审查，报告开头注明「基于源码审查」。

## 七类检查（按严重度优先级）

1. **交互可达**
   - 所有可交互元素 Tab 可达、顺序合理；focus 环可见（`outline: none` 而无替代 = 阻断）。
   - 触控目标 ≥ 44×44px（移动端）。
   - 导航用 `<a href>`、动作用 `<button>`——语义错用即问题。
2. **无障碍测量**（用数字说话）
   - 对比度：正文 ≥ 4.5:1；大字（≥ 24px 或 ≥ 18.66px 粗体）与 UI 边界 ≥ 3:1。公式 `(L1+0.05)/(L2+0.05)`；`calc`（如可用）核算，否则对照 token 已核准值并标注估算方式。
   - 图标按钮有可读名称（aria-label / 可见文本）；装饰图 `alt=""`，信息图有 alt。
   - 唯一 `<h1>`，标题层级不跳级。
3. **表单**
   - 每个输入有绑定 `<label>`；`type` 与 `autocomplete` 正确。
   - 错误就地展示（字段旁），不能只弹 toast；Enter 能提交。
4. **布局与排版**
   - 间距节奏一致（同层级同间距）；行宽 45–90 字符。
   - 移动端正文字号 ≥ 16px（防 iOS 自动缩放）；图片有宽高防布局位移。
5. **状态走查**：核心组件逐个核对 hover / focus / active / disabled / loading / empty / error——缺失即记问题。
6. **响应式**：三档宽度下无横向滚动、无重叠、无截断文字；触屏端可用（悬停才出现的操作必须有替代）。
7. **文案**：按钮动词 = 动作结果；报错说清「发生了什么 + 怎么修」；空态有行动入口；同一动作全流程同名（术语一致）。

## 严重度与报告

- 分级：**阻断**（键盘陷阱 / 未标注表单 / 对比度 < 3:1）/ 高 / 中 / 低；口味问题放「备注」，与规则违反分开。
- 每条发现格式：`严重度｜位置（选择器或 file:line）｜违反规则｜修法（给可应用的值 / 代码）`。
- 报告结构：结论（各级数量）→ 分类小节 → 5 条 quick wins（低成本高收益）。
- 纪律：不臆测——不确定渲染结果时标注「待渲染复核」；不把「我觉得」当规则。

## 检查清单

- [ ] 交互可达三项（Tab / focus / 44px）过
- [ ] 对比度均有数值或核准值对照
- [ ] 表单 label / 报错位置 / Enter 全过
- [ ] 状态矩阵无缺失
- [ ] 三档宽度无破版
- [ ] 文案四查（动词 / 报错 / 空态 / 术语）

## 工具用法

- `grep` 定向扫描：`outline:\s*none`、`#[0-9a-f]{3,6}`、`aria-`、`alt=`、`tabIndex`、`<div.*onClick`。
- 有浏览器接入时截图三档宽度（`browser_screenshot` 如可用）；动态页面先等稳定。
- 前端实测流程与复现证据走 `webapp-testing`；本手册专注界面质量清单本身。

## 输出约定

- 交付：`docs/界面走查-<模块>.md`（结论 + 分类发现 + quick wins）；发现问题回填给对应角色（frontend 修实现、designer 改稿、content 调文案）。
