# 长文档共创手册

长文档失败的原因通常不是文笔，而是**上下文缺口**与**结构失控**。用三段式流程解决，每段有明确的退出条件。

## 阶段一：上下文收集

先问五个元问题（一次发出，允许对方用速记回答）：

1. 文档类型与用途？（方案 / 规格 / 报告 / 决策记录）
2. 主要读者是谁？他们读完要做什么？
3. 期望的结论或行动是什么？
4. 有既定模板或格式要求吗？
5. 有哪些硬约束（期限 / 预算 / 已定事项）？

然后请对方倾倒一切相关素材（背景、讨论、被否决方案、数据），不要求组织。基于缺口生成 5–10 个澄清问题。

**退出条件**：能对边界与取舍提问，而不再需要对方解释基础概念。

## 阶段二：逐节打磨

对每一节循环四步：

1. **列要点**：这一节要回答的唯一问题 + 3–5 个支撑要点（先不写句子）。
2. **排序**：要点按「结论 → 论据 → 细节」排列；删掉不支撑结论的。
3. **起草**：按排序写出整段；每个数字标来源，每个主张可追溯。
4. **删减**：逐句问「删掉它读者会看不懂吗」，不会则删。

结构纪律：

- 全文骨架先落盘（`write_todos` 或大纲段，前者不可用则直接写大纲），经确认后再逐节填充——避免写完全文再动结构。
- 每节结尾有「所以怎样」句，否则该节缺失结论。
- 术语表：首次出现的缩写给全称；同一概念全文用同一个词。

## 阶段三：读者测试

- 用「零上下文读者」视角重读一遍：哪里需要回头翻、哪里产生「那又怎样」的疑问。
- 三问自测：读完能否复述结论？能否指出依据？能否说出下一步？
- 检查可粘贴性：文档单独被转发（不带对话上下文）时仍成立。

## 检查清单

- [ ] 元五问已有答案；素材与澄清问题均已覆盖
- [ ] 每个主张有依据；每个数字有来源与日期
- [ ] 每节以结论句收尾；无「然后呢」段落
- [ ] 术语一致；无未解释缩写
- [ ] 零上下文读者测试通过
- [ ] 版本表与变更记录完整（修订式文档）

## 工具用法

- `write_file` 落盘全文；`edit_file` 按节修订，不用整篇重写。
- 长文先列节级待办（`write_todos` 如可用），逐节完成并勾选。
- 需要核对事实时用 `web_fetch` / `web_search`（如可用）；引用格式：来源 + 日期。
- 交付呈现可选 `::: details`（冗长附录）、`::: cols`（方案对照）、`::: kpi`（关键数字）。

## 输出约定

- 落点 `docs/<文档名>.md`；文首给「一句话结论 + 读者与用途」。
- 文末附：开放问题清单（待确认事项 + 需要谁拍板）。
