# 正式文档手册

正式文档的要求只有三条：**结构统一、条款可引用、版本可追溯**。风格为「正式而简洁」——不口语化、不堆形容词、每句只表达一个意思。

## 文档骨架（按类型取用）

### 制度 / 规范

    一、目的与适用范围
    二、职责分工（角色 → 责任）
    三、流程与规则（分条，可引用编号）
    四、检查与考核（检查点 / 频率 / 责任人）
    五、附则（生效日期 / 修订记录）

### 会议纪要

    时间 / 地点 / 参会人 / 主持
    一、决议事项（结论 + 责任人 + 期限）
    二、待办清单（表格：事项 | 负责人 | 截止日 | 状态）
    三、下次会议（时间 / 议题）

### 对外函件 / 通知

    标题（事由 + 文种）
    称谓
    正文：背景一句 → 事项分条 → 期望行动与期限
    落款（单位 / 人名 + 日期）

## 写作纪律

- **条款可引用**：正文分条编号（一、1.1），后续文档引用编号而非复述原文。
- **一个句子一个意思**；金额、日期、期限全部写清口径与单位，日期用 YYYY-MM-DD。
- **称谓与语气**：内部「各位同事」、对外「尊敬的 XX」；命令式仅用于制度，通知类用「请于 X 前完成」。
- **不做承诺**：不确定的时限 / 金额写「以最终审批为准」；涉及法务表述先经 legal 会签。
- **可执行**：每条规则含「谁在何时做什么、不做如何」；缺任何一项视为未完成。
- **敏感与保密**：涉及合同、薪资、客户身份信息时，标注密级与知悉范围。

## 版本与修订

- 文首或文末固定「版本表」：版本号 | 日期 | 修订人 | 修订说明。
- 修订只增不删旧记录；重大修订升大版本并在正文标注变更处（如「（修订：…）」）。
- 交付件文件名含版本与日期：`docs/<文档名>-v2-2026-09-16.md`。

## 模板化与批量

- 同类文档（通知、纪要、报价附函）沉淀为模板：`templates/<类型>.md`，占位用 `{{点路径}}`（如 `{{客户.名称}}`、`{{事项.期限}}`）。
- 批量生成用 `template_fill`：缺失变量会汇总报错、不静默；先 `dry_run` 预览再落盘。

## 检查清单

- [ ] 五类要素齐全（目的 / 条款 / 责任 / 期限 / 生效或修订）
- [ ] 条款可编号引用；无模糊指代（「上面说的」）
- [ ] 日期、金额、单位口径一致
- [ ] 版本表已填写；文件名含版本
- [ ] 涉法务 / 财务表述已请相关同事会签

## 工具用法

- `write_file` / `edit_file` 落盘与修订；长文档先用大纲（`write_todos`）再逐节写。
- `template_fill` + `templates/` 做批量生成；期限与生效日用 `date_calc` 核算（两者如不在工具清单，改手算 + 复核并在交付说明标注）。
- 附录、变更对比用 Markdown 扩展：`::: details` 收纳长附录、`::: cols` 做对照排版。

## 输出约定

- 落点 `docs/`；文件名 = 文档名 + 版本 + 日期。
- 文末固定三行：生效日期 / 修订记录 / 会签人。
