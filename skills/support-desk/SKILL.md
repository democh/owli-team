# 客服运营手册

客服的标准不是「回复得快」，而是**每条回复都让用户获得确定的下一步**：问题被复述、现状被说清、动作与时限被写明。

## 工单分级（先分再答）

| 级别 | 判定 | 首响时限 | 升级 |
| --- | --- | --- | --- |
| P0 | 全量不可用 / 数据风险 | 立即 | 拉相关人 + 对外通报（走 comms-writing） |
| P1 | 核心功能不可用，无绕行 | ≤ 1h | KPI 声明升级 |
| P2 | 功能异常但有绕行 | ≤ 4h | 正常队列 |
| P3 | 体验 / 咨询类 | ≤ 1 天 | 知识库沉淀 |

定级只看影响面与有无绕行，不看用户情绪烈度。

## 首答模板（四段）

    复述问题：您遇到的是「<用自己的话复述>」，对吗？
    已知信息：我们查到 <事实：时间 / 影响范围 / 已有状态>
    动作与时限：现在为您 <具体动作>，将在 <具体时间> 前回复进展
    替代方案：在此之前，您可以先 <可用的绕行方式>

- 复述必须准确——复述错比不复述更伤信任。
- 不限时承诺：「尽快」「稍后」一律改为具体时间点。
- 不确定根因时给「已知 / 未知」两栏，不猜原因。

## FAQ 与知识库

- 一题一文：标题即用户的问题原话（用搜索词方式写）。
- 答案结构：结论 → 步骤（可照做）→ 兜底（还是不行找谁）。
- 每处理一个新问题：先想「这是否值得入库」；重复出现 ≥ 2 次的问题必须入库并回链工单。
- 入库时标注：适用版本、更新日期、相关工单号。

## 投诉与情绪处理

1. 先确认感受与事实（「这确实耽误了您的时间」——只确认事实，不过度道歉）。
2. 再给确定性：现状 + 我方动作 + 时限；不说「我们会重视」类空话。
3. 记录三要素：诉求（要什么）、底线（什么不可接受）、期望时间。
4. 涉及退款 / 赔偿 / 法律措辞：不自行承诺，转负责人确认后回复。

## 升级路径

- 技术疑难 → 研发（附复现步骤 + 影响面）；业务政策 → 对应负责人；法务风险 → legal。
- 升级必须带包：用户诉求 / 已核实事实 / 已做动作 / 需要对方做什么。不带包的升级会被打回。

## 检查清单

- [ ] 工单已定级；首响时限符合级别
- [ ] 首答四段齐全，含具体时间点
- [ ] 未承诺不确定事项；未猜根因
- [ ] 重复问题已入库 / 已回链
- [ ] 升级包完整；投诉记录三要素

## 工具用法

- 工单台账与 FAQ 清单落盘 CSV（`data/工单台账.csv`、`data/faq.csv`），用 `csv_analyze` 看 Top 问题（groupby 类型）。
- 回复模板用 `template_fill`（收件人 / 单号 / 时限占位）；邮件形态用 `::: mail`。
- 回复口径与用语纪律见 `comms-writing`。

## 输出约定

- 交付：`docs/客服-<主题>-回复包.md`（模板群）或单条回复 + 台账更新；知识库文章落 `docs/faq/<问题>.md`。
