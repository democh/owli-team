# Web 应用实测手册

目标：把「听说有问题」变成「可复现、有证据、带根因线索」的缺陷报告。原则：**先侦察页面现况，再动手操作**，禁止凭想象点。

工具可用性：本手册以 `browser_*` 工具族为执行手段。若工具清单未接入浏览器（以你的工具清单为准），改用**人工步骤单模式**：输出可照做的《测试步骤单》（步骤 + 预期结果 + 截图点）交用户执行并回收结果；文案 / 元素 / 路由等静态项改用 `read_file` / `search_text` 走查。

## 侦察-动作循环（核心工作法）

1. **打开与等待**：`browser_open` 打开目标地址；动态页面先等加载稳定再侦察（用 `browser_wait`）。
2. **侦察**：`browser_snapshot` 拿页面结构，确认元素与文案（读长文 / 列表加 `include_text: true`）；关键区域 `browser_screenshot` 截图；页面报错 / 按钮无反应时先 `browser_console` 看控制台错误与未捕获异常。
3. **定位**：从快照里挑选择器（文本 / 角色 / id），不要猜 CSS 路径。
4. **动作**：`browser_click` / `browser_fill` / `browser_press` / `browser_scroll`，每次动作后重新快照确认状态变化。
5. **取证**：预期与实际不符时，立即截图 + 记录快照片段；连续 2 次无法推进则停下报告，不要暴力重试。

## 用例设计（每个功能）

| 类别 | 覆盖 |
| --- | --- |
| 正常路径 | 主流程一步不跳，断言可见结果（文案 / 数字 / 跳转） |
| 边界 | 空值、超长输入、重复提交、0 与极值 |
| 错误路径 | 错误提示是否出现、是否可恢复、状态是否被污染 |
| 权限 / 状态 | 未登录、无权限、会话过期后的行为 |

- 每条用例写：前置状态 → 操作步骤 → 预期 → 实际。
- 一次运行只验证一条主链路，穿插验证会丢失因果。

## 缺陷报告格式（必须按此输出）

    缺陷标题：<一句话：在哪、做什么、出什么错>
    复现步骤：1-2-3（含输入值）
    预期：<按需求应发生什么>
    实际：<实际发生什么，含报错文案>
    证据：截图路径 + 快照片段
    频率：必现 / 偶现（若偶现，给尝试次数）
    初步定位线索：<可疑模块 / 控制台错误 / 网络请求>

## 纪律

- 不使用 `browser_eval` 绕过界面直接调接口「伪造」通过——测试要模拟真实用户路径。
- 涉及登录态 / 支付 / 数据删除等危险操作的验证：先请示（`request_approval` / 找人工接管），不做不可逆操作。
- 人工接管期间（页面被用户接走）暂停动作，等归还后再继续并重拍快照。
- 对生产环境只读验证，不做写操作；写操作只在测试环境进行。

## 检查清单

- [ ] 每条用例有前置状态与断言
- [ ] 每个缺陷有复现步骤 + 截图证据
- [ ] 未使用绕过手段伪造通过
- [ ] 危险操作已经过确认
- [ ] 收尾：关闭浏览器会话（`browser_close`）并汇总结果

## 工具用法

- 浏览器工具族：`browser_open` / `browser_navigate` / `browser_snapshot`（`include_text` 读正文）/ `browser_click` / `browser_fill` / `browser_press` / `browser_scroll` / `browser_wait` / `browser_screenshot` / `browser_console`（控制台日志）/ `browser_request_human` / `browser_close`（以你的工具清单为准）。
- 若浏览器未接入：输出「手工复现脚本」——按用例格式给步骤与断言，请用户执行并回报。
- 报告用 `write_file` 落盘；截图路径写进报告。

## 输出约定

- 测试报告：`docs/测试报告-<模块>-<日期>.md`（用例结果表 + 缺陷清单）。
- 缺陷单条独立成节，便于后续逐个修复后回归勾选。
