# 品牌与产品命名

好名字的标准不是「好听」，而是**好记、好说、好搜、不出事**。命名是一场从发散到收敛的筛选工程：先要量，再要矩阵。

## 触发场景

- 新产品 / 新品牌 / 账号 / 功能 / 活动的命名；
- 既有名称的体检与更名评估；
- 命名评审：对候选清单做打分与风险复查。

## 隐喻驱动流程（发散 → 收敛）

1. **定位锚点**：先用一句话写清「这是什么、给谁、与替代品的差异」——名字必须承得住这句话；
2. **意象场**：围绕锚点收集 3–5 个意象场（如「速度 → 猎豹/闪电/箭」「信任 → 锚/盾/基石」），每场再列 10+ 词；
3. **生成候选**：每个意象场产出 8–15 个候选（不评判），总量目标 ≥30；组合法（词根 + 词根）、造词法、拟声法都可用；
4. **静默期**：候选放置半天再筛——刚生成的「顺口」多半是熟悉度错觉；
5. **收敛**：先按硬线筛除（见下），再进筛选矩阵；保留 5–8 个进终选。

## 命名类型与适用

| 类型 | 例式 | 优势 | 风险 |
|---|---|---|---|
| 描述性 | 「快剪」「云笔记」 | 一眼懂、SEO 友好 | 难注册、平庸 |
| 暗示性 | 「知乎」「迅雷」 | 有画面、留想象 | 理解成本略高 |
| 隐喻 | 「蚂蚁」「斑马」 | 好记、故事性强 | 品类联想可能跑偏 |
| 造词 | 「科沃斯」类 | 可注册商标 | 无意义、传播成本高 |
| 人名/地名 | 创始人、地名 | 温度与人味 | 难规模化、易撞名 |

## 筛选矩阵（终选打分）

每项 1–5 分，加权总分排序；权重按项目性质调整：

| 维度 | 打分依据 |
|---|---|
| 记忆度 | 隔夜回忆测试：次日还能想起吗 |
| 相关性 | 与定位锚点的贴合度 |
| 独特性 | 同品类内撞名搜索首屏检查 |
| 可发音 | 三遍念顺；口播场景实测 |
| 跨语言安全 | 主要外语中是否粗俗/负面谐音 |
| 可用性 | 域名 / 账号名可用性（如可用，`web_search` 初查） |
| 延展性 | 未来子品牌/产品线能否挂得住 |

## 硬线筛除（矩阵前执行）

- **谐音事故**：快速朗读 + 方言谐音自查，中英文双向看；
- **文化禁忌**：目标市场宗教/历史敏感词一票否决；
- **负面联想**：与失败案例、丑闻品牌高度相似者剔除；
- **歧义混乱**：需要三段解释才能说清的名字不要。

## 商标与检索提示（不做正式法律判断）

- 正式命名前提示用户做**商标检索**与**域名/社媒账号查询**；本环节只做初查与风险标注（「疑似冲突」/「未见明显冲突」），不给法律结论；
- 已用名称的替代方案：保留品牌词根做变体（省认知成本）vs 全新换名（省风险成本），列清取舍。

## 交付约定

- 落盘 `docs/命名方案-<主题>.md`，章节：定位锚点 / 候选表（≥30，含类型与意象场）/ 筛选矩阵（5–8 终选打分）/ 推荐 Top3 与理由 / 风险与待核项（商标、域名、谐音）；
- 完成定义：候选量达标；矩阵每项有打分依据；Top3 各有「为什么是它」的 3 句说明。

## 检查清单与反模式

- 交付前核对：① 定位锚点先行且一句话？② 候选 ≥30 且未提前评判？③ 硬线筛除执行过？④ 矩阵有依据不是印象分？⑤ 风险项已标注并提示正式检索？
- 反模式：给老板的口味写名字（无矩阵只有偏好）；忽略海外市场谐音；把「能搜到无数同名」当知名度高；只给一个「最终答案」不给过程；承诺「没有商标问题」。
