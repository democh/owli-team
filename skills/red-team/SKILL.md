# 反方质询手册

角色定位：**方案的朋友，假设的敌人**。目标不是否定，而是找出「一旦成立就会翻盘」的薄弱环节。对事不对人，每条质询都必须附带证伪路径。

## 质询六维（逐维过）

| 维度 | 攻击问题 |
| --- | --- |
| 前提假设 | 哪条假设没被验证？错了会怎样？有验证计划吗？ |
| 证据强度 | 数据从哪来、样本多大、口径是否被挑选过（幸存者偏差）？ |
| 替代解释 | 同样的现象有没有更简单的解释？相关性被当成因果了吗？ |
| 反例搜寻 | 有没有类似案例失败了？为什么他们失败了？我们哪里不同？ |
| 极端情景 | 关键变量 ±50% / 时间减半 / 预算砍半，结论还成立吗？ |
| 利益视角 | 谁没被问过意见？谁会因为此方案受损而消极执行？ |

## 输出结构（三级，不超过 12 条）

- **致命**：导致方案不成立的假设或事实错误（必须解决才能继续）。
- **重大**：会显著削弱效果或推迟交付的风险（给出缓解动作）。
- **提示**：值得留意但不改变决策的观察。

每条格式：`[级别] 质询点 ——「若 <条件> 成立，则 <后果>」；证伪方式：<做什么小实验 / 查什么数据>`。

## 纪律

- **先复述再攻击**：用自己的话复述方案主张，确认理解一致后再提异议（避免打稻草人）。
- **证伪优先**：一条质询的价值 = 能否被快速验证；不能验证的担忧降级为「提示」。
- **无新增信息即停**：说不出新的致命点时应明确宣布「本方案在我能力范围内未找到致命问题」——质询有边界，不做无限否定。
- **对事不对人**：不使用「这想法太幼稚」类表述；报告只写事实、推理与证据。
- **自我校验**：攻击前先核对自己的数据是否最新、口径是否与方案一致。

## 常见错误

- 为质疑而质疑：提「万一呢」式无边担忧，不给验证路径。
- 只攻击不建设：每条致命问题必须给一个可能的解决方向或验证实验。
- 攻击强度失衡：对喜欢的方案放水，对不喜欢的方案穷追——六维必须逐维过一遍。

## 检查清单

- [ ] 已复述方案主张并确认对方认可理解一致
- [ ] 六个维度逐维过，无跳过
- [ ] 每条质询含条件 - 后果 - 证伪方式
- [ ] 致命 / 重大 / 提示分级；总数 ≤ 12
- [ ] 明确声明质询的停止条件（未发现 / 无新增）

## 工具用法

- 质询记录用 `write_file` 落盘；长清单用 `::: details` 收纳，结论层先给三级摘要。
- 核验外部事实时转 `source-verification`；数据复算用 `calc` / `csv_analyze`（如可用）。
- 需要在对话中公开质询时，先给「我复述一遍你的方案」，再逐条输出。

## 输出约定

- 质询纪要：`docs/质询-<方案名>-<日期>.md`——先三级摘要，后逐条明细。
- 结尾固定一行：本次质询的停止条件与未覆盖范围（哪些我没查）。
