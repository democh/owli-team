# 线上事故响应手册

响应总则：**先止血 → 再定位 → 后复盘**。恢复服务优先于根因分析；根因不因止血而免除。

## 事故分级（SEV）

| 级别 | 判定标准 | 响应节奏 |
| --- | --- | --- |
| SEV1 | 核心功能全挂 / 资损 / 数据风险 | 立即响应，每 15 分钟同步进展 |
| SEV2 | 部分功能降级 / 性能大幅劣化 | 30 分钟内响应，每小时同步 |
| SEV3 | 边缘功能异常 / 无用户感知 | 工作时间内处理 |

分级以**影响面**（多少用户 / 多少功能）与**趋势**（扩大 or 收敛）为准，不以噪声大小为准。

## 五步响应

1. **确认与分级**：影响面（谁受影响 / 范围）、开始时间（首个证据时点）、当前趋势；一句话同步给用户。
2. **止血**：回滚 / 降级 / 扩容 / 限流 / 切流——选**最快恢复**且**可逆**的手段；变更类操作先说明影响与回退方式并报批。
3. **定位**：按「变更 → 资源 → 依赖」顺序排查（见下节命令库）；假设写下来，用命令验证，冲突时改假设。
4. **修复与验证**：修复动作 + 服务恢复确认（健康检查 + 关键指标）+ 观察窗口（建议 ≥ 10 分钟）。
5. **复盘**：时间线 + 根因（5 Whys）+ 改进项表；见交付模板。

## SSH 诊断命令库（`ssh_exec` 只读优先）

| 目的 | 命令（示例） |
| --- | --- |
| 服务状态 | `systemctl status <svc> --no-pager` / `systemctl is-active <svc>` |
| 服务日志 | `journalctl -u <svc> --since "-30min" --no-pager \| tail -100` |
| 磁盘 | `df -h` / `du -sh /var/log/* 2>/dev/null \| sort -rh \| head` |
| 内存 / OOM | `free -m` / `dmesg \| tail -50 \| grep -i -E "oom\|kill"` |
| CPU / 负载 | `top -bn1 \| head -15` / `uptime` |
| 端口 / 连接 | `ss -tlnp \| grep <port>` / `ss -s` |
| 健康检查 | `curl -sf -m 5 http://localhost:<port>/healthz && echo OK` |
| 句柄 | `lsof -p <pid> 2>/dev/null \| wc -l` |
| 时间同步 | `date -u` / `timedatectl status` |

- 所有命令**单条非交互**，默认 30s 超时；大量输出加 `| tail -N` 控制体积。
- 长任务（`tail -f` / 大文件导出 / 循环探测）拆分为分段命令，或提示用户在「终端」页签操作。
- 变更类命令（restart / stop / rm / 改配置）先报批；执行前记录当前状态（便于回退）。

## 定位检查表

- [ ] 变更即可疑：最近发布 / 配置变更 / 证书轮换时间线（`git_log`、发布记录）
- [ ] 资源耗尽：磁盘满 / OOM / 句柄耗尽 / 连接数打满
- [ ] 依赖故障：下游超时 / DNS / 证书过期 / 限流触发
- [ ] 流量变化：突增（活动 / 爬虫）/ 突降（上游故障传导）
- [ ] 数据异常：表膨胀 / 队列堆积 / 时钟漂移

## 时间线与度量

- 关键时点：发现（Detect）/ 响应（Ack）/ 止血（Mitigate）/ 恢复（Recover）/ 复盘（Review）。
- 度量：MTTD（发现耗时）/ MTTA（响应耗时）/ MTTR（恢复耗时）——统一时区，用 `date_calc` 核算。
- 时间线每条记录标注**证据出处**（命令输出 / 日志行 / 工单号），无出处的时点不写。

## 复盘模板（无责）

1. **影响摘要**：用户影响 / 业务影响 / 时长（一句话讲清）。
2. **时间线**：表格（时点 / 事件 / 证据出处）。
3. **根因分析**：5 Whys 逐层追问到系统层（流程 / 设计 / 监控缺口），不归结到「某人疏忽」。
4. **处置过程**：止血动作 / 修复动作 / 验证结果（含走弯路的路径，不美化）。
5. **改进项表**：行动 / owner / 期限 / 验证方式——四要素缺一不可。

## 可靠性度量（SLO 基础）

- **SLI**：可测量的服务水平指标（成功率 / 延迟 / 可用性），必须是比率。
- **SLO**：SLI 的目标值（如 99.9% / 月），用 `calc` 核算。
- **错误预算**：1 − SLO；预算燃尽率 = 实际消耗 / 预算——燃尽过半时冻结高风险变更。
- **容量水位**：CPU / 内存 / 磁盘常规水位 < 70%，超阈值给扩容建议（附现有量与增长速率）。

## 反模式

- 未看证据先重启（掩盖根因，故障复发）；
- 止血后忘复盘；复盘变追责大会；
- 变更不留记录（时间线断链）；
- 行动项写「加强监控」但没有负责人和验收标准；
- 在事故现场做未经审批的高风险操作（抢修也需要纪律）。
