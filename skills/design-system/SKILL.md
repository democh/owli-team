# 设计系统手册

设计系统的价值在约束：让第 10 个页面和第 1 个页面看起来出自同一双手。做法是三层 token + 一份组件清单 + 一套治理规则。

## Token 三层（只有一个事实源）

| 层 | 内容 | 例 |
| --- | --- | --- |
| 原始值 primitive | 只定义一次的字面量 | `blue-600: #2563eb` |
| 语义 semantic | 按用途命名，界面只许用这层 | `color-action: blue-600`、`space-4` |
| 组件 component | 组件局部变量 | `button-bg: color-action` |

- 界面代码禁止裸值（`#2563eb`、`13px`、`7px` 这类奇数间距）——一律引用语义 token。
- 命名按「用途」不按「外观」：`color-danger` 而不是 `color-red`；换主题时语义名不动。

## 色彩基线

- 中性色阶梯（底 / 面 / 浮层 / 边框 / 主文 / 次文 / 弱文）+ 强调色 + 四状态色（success / warning / danger / info）。
- 每对「文字 × 底色」预先核准对比度：正文 ≥ 4.5:1，大字（≥ 24px，或 ≥ 18.66px 粗体）与 UI 边界 ≥ 3:1；核准结果写进规范表。
- 深 / 浅两套都要验证：边框在浅色下是否消失、浮层阴影在深色下是否还分得开。

## 排版与间距

- 字号阶梯 1.25 或 1.5 倍比，5–7 级封顶；每级写清用途（页面标题 / 区块标题 / 正文 / 辅助）。
- 行高：正文 1.5–1.7，标题 1.2–1.3；行宽 45–90 字符。
- 间距 4px 基准（4 / 8 栅格），组件内 ≤ 组件间 < 区块间；相邻层级间距至少差一档，层级靠留白不靠分割线。

## 组件清单与状态矩阵

每个组件入册需：用途一句话、变体列表、尺寸、8 状态核对（default / hover / focus / active / disabled / loading / empty / error）。状态缺失即记为待办，不默认「不需要」。

| 组件 | 变体 | 状态缺失 | 备注 |
| --- | --- | --- | --- |
| Button | primary / ghost / danger | loading | |

## 组件 API 反模式（入册前拦掉）

- 布尔 props 爆炸（`isCompact` `isRounded` `hasBorder`）→ 改显式变体：`<Alert.Destructive>` 而不是 `<Alert isDestructive>`。
- render props → 优先 children 组合；复合组件共享 context（`Select.Trigger` / `Select.Content` 式结构）。
- 一个组件同时管布局与样式两种职责 → 拆。

## 治理

- 单一事实源：MASTER 一份 + 页面级覆盖单独存放；覆盖必须写明理由与范围，不允许「就地改一版」。
- 新组件入册条件：被 ≥ 2 个页面复用，或承载核心流程；一次性样式不进系统。
- 变更留痕：token 改动记录「为什么」（对比度 / 品牌 / 一致性），并跑一遍全库引用检查。

## 检查清单

- [ ] 界面代码无裸值（色值 / 字号 / 间距）
- [ ] 语义 token 命名按用途；深浅两套均验证
- [ ] 对比度配对表已核准（含数值）
- [ ] 组件状态矩阵无空白
- [ ] 无布尔 props 反模式
- [ ] MASTER 与覆盖版本一致

## 工具用法

- `grep` 全库扫裸值（如 `#[0-9a-f]{3,6}`）；`search_text` / `read_file` 找既有 token 定义与组件，沿用而非新造。
- `calc`（如可用）复核对比度：`(L1+0.05)/(L2+0.05)`，L 为相对亮度；无 calc 时对照已核准配对表并标注估算方式。
- 规范落盘 `docs/设计系统-<产品>.md`；token 清单长表可用 `::: details` 折叠。

## 输出约定

- 交付：`docs/设计系统-<产品>.md`（token 表 + 组件清单 + 状态矩阵 + 反模式清单）；项目已有样式源文件时同步维护其中片段。
- 与 `visual-design`（视觉稿）、`frontend-design`（实现）、`ui-review`（走查）配套：规范先行，稿与代码都引用同一个 token 名。
