# 测试计划与报告手册

测试的目标是**发现真实缺陷**，不是证明「没问题」。核心原则：期望可判定、步骤可复现、风险驱动排序。

## 用例组织

按三组组织，每个用例包含：前置条件 / 步骤 / 期望结果。

1. **正常路径**：主流程成功场景。
2. **边界**：空值、最小值、最大值、超长、恰好临界。
3. **异常**：非法输入、依赖失败、重复提交、并发。

## 设计方法速查

- **等价类**：把输入划成等价区间，每类取代表值，不穷举；
- **边界值**：重点测「差一」——0 / 1 / 最大 / 超一位；
- **状态迁移**：列出对象状态与合法/非法迁移，非法迁移必测（如已取消的订单再支付）；
- **判定表**：多条件组合场景（权限 × 状态 × 数据归属），逐列生成用例；
- **场景法**：端到端串一遍用户旅程，校验各环节衔接与数据流转。

## 必测清单（五类）

- [ ] 空值 / 缺省：空字符串、未传字段、空列表；
- [ ] 超长 / 超量：字段超长、批量超上限、深层嵌套；
- [ ] 并发与幂等：重复提交、并发写同一资源、重试风暴；
- [ ] 权限边界：越权访问（返回 404 而非 403）、角色矩阵抽查；
- [ ] 超时与恢复：依赖超时、中断恢复、断线重连。

## 报告模板

```markdown
# 测试报告：<主题>
## 范围
- 被测对象与版本 / 依赖说明
## 用例
| # | 组 | 前置 | 步骤 | 期望 | 结果 |
## 缺陷
- 缺陷：复现步骤 / 期望 / 实际 / 严重度
## 遗留风险
- 未覆盖项及其影响面
## 结论
通过 / 有条件通过（遗留风险）/ 不通过
```

## 缺陷分级口径

- **阻塞**：核心流程不可用 / 数据损坏 / 越权——不修不发；
- **严重**：主要功能异常但有绕行 / 结果错误可追溯；
- **一般**：次要功能异常 / 体验受损；
- **轻微**：文案 / 样式等表面问题。

定级不靠感觉：`越权 > 数据损坏 > 核心流程不可用 > 体验问题`；争议时以需求文档与接口契约为准绳，均未定义则记为「规格缺口」回问产品。

## 常见的坑

- 只测 happy path 就宣布通过——最常漏的恰是边界与异常组；
- 期望写「正常显示」「无异常」类不可判定描述；
- 缺陷描述夹带猜测（「可能因为缓存问题」）——只写事实与证据；
- 把未验证项混入结论；同一缺陷改完不回归关联用例；
- 测试仅覆盖本次改动，不检查相邻调用方受影响的路径。

## 工具接入口径

- 回归执行：`run_command` 跑既有测试套件（记录命令与结果）；跑不了时给逐步人工清单；
- 界面验证：`browser_*` 实测主流程与异常态（截图取证）；
- 数据核验：`db_query` 只读校验数据一致性与权限类断言；
- 数据汇总：用例结果与缺陷分布用 `csv_analyze`；比例计算用 `calc`。

## 协作衔接

- 用例范围从需求文档与接口契约推导；验收口径与产品对齐；
- 缺陷回交实现者（附最小复现与严重度）；发布判定交运维/发布侧（附遗留风险与监控建议）；
- 与 `ui-review` 配合界面走查、与 `debugging` 配合定位复现、与 `webapp-testing` 配合真实浏览器实测。
