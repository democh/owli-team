# 交互与动效手册

两个问题定交互好坏：**操作后多快有回应**、**变化是否被看懂**。动效是回答第二个问题的工具，不是装饰。

## 反馈时机

- 100ms 内给即时反馈：按下态、输入回显、乐观更新；超过 1s 给进度指示；超过 10s 允许后台化 + 完成通知。
- 结果与预期不一致的动效最伤人：展开必须从触发处开始、关闭回到触发处，让用户追踪到「从哪来到哪去」。
- 等待态分两类：< 1s 用轻量指示（按钮内 spinner），> 1s 用骨架屏保住结构。

## 交互模式四条

1. **直接操纵**：能拖拽就别用上下按钮，能内联编辑就别另开表单；操作对象与手势一一对应。
2. **宽容设计**：预防（破坏性操作确认、草稿自动保留）+ 恢复（撤销优先于二次确认；删除进回收站）。
3. **渐进披露**：概览 → 细节 → 高级；默认只露高频 20%，高级项找得到但不干扰。
4. **状态可见**：系统当前状态（已保存 / 同步中 / 离线）随时可查，不靠用户猜。

## 状态机与转换

每个交互单元画一张状态表：default / hover / focus / active / disabled / loading / empty / error。

- 写明转换条件：什么操作进入 loading、失败回退到哪一态、成功去哪一态。
- 空态与错误态是设计态，不是意外：空态给行动入口，错误态给恢复路径。

## 动效规格表

| 场景 | 时长 | 缓动 | 说明 |
| --- | --- | --- | --- |
| 微交互（按下 / 勾选） | 100–150ms | ease-out | 快进快出 |
| 状态切换（展开 / 收起） | 150–250ms | ease-in-out | 原地变形 |
| 浮层 / 面板进出 | 200–300ms | 进 ease-out / 出 ease-in | 位移 + 淡入淡出 |
| 页面 / 大区块 | 250–350ms | ease-out | 超过 400ms 显拖沓 |

- 同一界面时长不超过 3 档；节奏靠编排（首屏错峰入场一次做足），不靠处处加动效。
- 位移与缩放克制（面板 ≤ 8–16px 起步位移）；位移避免 linear（机械感），透明度过渡可用。

## 键盘、焦点与可达

- 全流程可 Tab 完成；focus 环可见（禁止无替代的 `outline: none`）。
- 约定键：Esc 关闭浮层、Enter 提交、方向键在组内移动；弹层关闭后焦点回到触发元素。
- `prefers-reduced-motion` 必须处理：位移 / 缩放降级为淡入或立即切换，不取消状态可见性。

## 检查清单

- [ ] 每类操作 100ms 内有反馈
- [ ] 状态表无空白，失败有回退路径
- [ ] 破坏性操作有预防 + 恢复（撤销优先）
- [ ] 时长 / 缓动符合规格表，同屏 ≤ 3 档
- [ ] 键盘全流程可达，焦点归位正确
- [ ] reduced-motion 降级已实现

## 工具用法

- `read_file` / `search_text` 查现有 `transition` / `animation` 定义，沿用既有档位而非新造。
- 状态机用 `mermaid`（stateDiagram-v2）表达；时序用 `::: timeline`；交互取舍可用 `::: option` 对比。
- 落地验收配合 `ui-review` 走查 focus / 键盘路径。

## 输出约定

- 交付：`docs/交互规格-<模块>.md`（状态表 + 动效参数表 + 键盘映射 + reduced-motion 降级说明）。
- 与 `design-system`（时长 / 缓动档位应入册 token）、`frontend-design`（实现）配套。
