# 头脑风暴主持手册

风暴的目标是**先求量、再收敛**：发散轮不评判，批评集中在挑战轮，收敛必须有打分依据。主持人的职责是守住节奏与结构，不替任何一方干活。

## 轮次结构

1. **议题卡**（facilitator）：背景 / 目标 / 边界 / 成功标准，≤6 行。
2. **发散轮**（ideator 等，可同波并行）：每人 ≥3 个点子；SCAMPER / 跨界类比 / 反转假设交替使用。
3. **挑战轮**（challenger）：先复述点子最强版本，再攻击关键假设；每条缺陷配修补方向。
4. **收敛轮**（refiner）：ICE 打分 → 合并方案族 → Top 方案 + 最小可行范围。
5. **定稿轮**（facilitator）：落盘 `docs/创意方案-<议题>.md`，交还用户并给出 Top 3。

## 议题卡模板

```markdown
## 议题卡
- 背景：<一句话，为什么要讨论>
- 目标：<要达成的结果>
- 边界：<本轮不讨论什么>
- 成功标准：<可判定的验收口径>
```

议题卡先行：没有明确边界与成功标准，发散会跑向无边界的空想。

## 发散引导手法

- **SCAMPER 变形**：替代 / 组合 / 调整 / 修改 / 他用 / 消除 / 反转——对既有方案逐项变形；
- **跨界类比**：把问题抽象成本质（如「撮合」），到远域（游戏 / 物流 / 医疗）找成熟玩法再映射回来；
- **反转假设**：把约束 / 目标 / 角色反转（「如果没有预算限制会怎么做」「如果用户是老人会怎么做」）；
- **极端化**：把某个参数推到极限（10 倍 / 十分之一），看方案在哪先崩。

## ICE 打分口径

- 影响 Impact（1–10）：对成功标准的作用大小。
- 信心 Confidence（1–10）：有证据支持的程度；低于 5 必须写「需验证什么」。
- 易度 Ease（1–10）：以现有资源多快能做出来。
- 总分 = I × C × E；并列时优先信心高者；分歧大时保留 2–3 个并列方案。

## 发散禁忌

- 发散轮禁止说「不行 / 但是」；所有批评留到挑战轮。
- 不重复候选池已有的点子；只做「补充 / 变形 / 组合」。
- 不复述他人原话充数；每个点子必须包含至少一处新增信息。

## 圆桌并行约定

- 多人同波发散时各自独立输出，声明点子编号，收敛方按编号合并去重。
- 收敛波不要中途各自 @用户 要结论；由主持人统一交还。

## 常见失败模式

- **过早收敛**：发散轮出现「这个不可行」即打断——批评越早，点子越少；
- **假共识**：没人反对但也没人认领——收敛时逐项确认「谁来做 / 何时做」，无人认领的进停车场；
- **停车场失管**：收敛轮冒出的新点子不记录，散会即丢——当场记入报告章节，会后处理；
- **评分无依据**：ICE 分数不给理由，等于给直觉穿公式的外衣；
- **单人独舞**：多成员时变成某个角色的独角戏——主持人点名轮空成员补位。

## 收敛输出模板

```markdown
## 候选点子表
| 编号 | 点子 | 手法 | I | C | E | 总分 | 备注 |
## Top 方案
- 方案：<一句话> / 风险：<…> / 最小可行范围：<做什么·不做什么> / 下一步：<…>
## 停车场
- 收敛轮新增的点子（编号 / 一句话 / 处理建议）
```

## 工具接入口径

- 落盘与引用：点子池 / 评分矩阵 / 创意方案落 `docs/`（`write_file` / `apply_patch`）；
- 量化支撑：涉及数字的可行性估算用 `calc`，对比表用 `csv_analyze`；
- 排期：下一轮时间与里程碑用 `date_calc`；
- 作品化呈现：Top 方案可用 `chart` / `mermaid` 块辅助表达（如决策树 / 流程）。

## 协作衔接

- 成员分工：ideator 出量 / challenger 挑战 / refiner 收敛 / facilitator 主持——各守边界；
- 挑战暴露系统性盲区时，回发散轮做变形补充（基于原编号沿链追溯）；
- 收敛结论与用户拍板衔接：分歧大时并列 2–3 案与各自适用条件，由用户在 `::: choice` 类选项中拍板。
