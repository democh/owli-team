# 深模块设计词汇

设计**深模块**：大量行为藏在很小的接口后面，接口落在一处干净的接缝上，测试从这个接口穿过去。目标是调用方的**杠杆**、维护者的**局部性**、所有人的**可测试性**。

## 词汇表（照用，不要换词）

| 词 | 含义 | 不要写成 |
| --- | --- | --- |
| **模块** | 任何有「接口 + 实现」的东西：函数、类、包，或横跨多层的切片；刻意与尺度无关 | 单元、组件、服务 |
| **接口** | 调用方想正确使用它必须知道的一切：签名，还包括不变量、调用顺序、错误形态、必需配置、性能特征 | API、方法签名（只覆盖类型层面，太窄） |
| **实现** | 模块内部的代码体。当话题是接缝角色时用**适配器**，否则用实现 | — |
| **深度** | 接口处的杠杆：调用方（或测试）每学一单位接口，能驱动多少行为。行为多、接口小 = **深**；接口几乎和实现一样复杂 = **浅** | 代码行数比 |
| **接缝**（seam） | 不修改此处代码就能改变行为的位置；模块接口所在的地方。接缝放哪儿是独立的设计决策，与接缝后面放什么分开讨论 | 边界（与 DDD 的限界上下文混淆） |
| **适配器** | 满足某个接缝接口的具体东西；描述的是角色，不描述内部构成 | — |
| **杠杆** | 调用方从深度里得到的：一份实现回报给 N 个调用点、M 个测试 | 复用率 |
| **局部性** | 维护者从深度里得到的：改动、缺陷、知识、验证集中在一处，改一次到处生效 | 内聚 |

## 深与浅

**深模块** = 小接口 + 厚实现：

```
┌─────────────────────┐
│    小接口（少方法）   │
├─────────────────────┤
│                     │
│    厚实现（复杂逻辑） │
│                     │
└─────────────────────┘
```

**浅模块** = 大接口 + 薄实现（要避免）：

```
┌─────────────────────────────────┐
│        大接口（多方法、多参数）    │
├─────────────────────────────────┤
│        薄实现（只是转发）          │
└─────────────────────────────────┘
```

设计接口时问三句：

- 方法数量还能再减吗？
- 参数还能再简化吗？
- 还能把更多复杂度藏进去吗？

## 四条原则

- **深度是接口的属性，不是实现的属性**：深模块内部可以拆成一堆小的、可替换的部件，它们只是不进入接口。模块可以有**内部接缝**（实现私有，供自己的测试用），也可以有接口处的**外部接缝**。
- **删除测试**：假设把这个模块删掉——复杂度消失了，它只是直通；复杂度在 N 个调用方那里重新长出来，它在挣自己的位置。
- **接口就是测试面**：调用方和测试穿过同一道接缝。如果你需要绕过接口去测，说明模块形状不对。
- **一个适配器 = 假设的接缝，两个适配器 = 真实的接缝**：没有东西真的会变，就别开接缝。

## 为可测试性设计

**① 依赖由外部传入，不在内部新建**

```typescript
// 可测
function processOrder(order: Order, gateway: PaymentGateway) {}

// 难测
function processOrder(order: Order) {
  const gateway = new StripeGateway()
}
```

**② 返回结果，不制造副作用**

```typescript
// 可测
function calculateDiscount(cart: Cart): Discount {}

// 难测
function applyDiscount(cart: Cart): void {
  cart.total -= discount
}
```

**③ 接口面越小越好**：方法少，测试就少；参数少，准备就轻。

## 概念之间的关系

- 一个**模块**恰好有一个**接口**（呈现给调用方与测试的那一面）；
- **深度**是模块相对其接口的性质；
- **接缝**是模块接口所在的位置；
- **适配器**坐在接缝上，满足接口；
- **深度**为调用方产生**杠杆**，为维护者产生**局部性**。

## 拒绝的用法

- 把「深度」当成「实现行数 ÷ 接口行数」——这会奖励往实现里灌水；本仓用「深度 = 杠杆」的口径；
- 把「接口」等同于 TypeScript 的 `interface` 关键字或类的方法列表——太窄；
- 用「边界」指接缝——歧义太多，统一说**接缝**。

## 常见坑

- **为测试而抽纯函数**：函数抽出来了，真正的缺陷藏在调用方式里，局部性反而更差；
- **接缝开在没人变的地方**：一个适配器的接缝是纯负担；
- **接口替调用方做了决定**：把内部数据结构、内部错误码暴露到接口上，浅得没法测；
- **删不掉**：一个模块用删除测试通不过、又找不到它的杠杆，说明它只是转发的中间层。

## 输出约定

谈架构时用本词汇表的词，别混用同义词；给出改造建议时按这个形状写：

```
模块：<名字>（当前：浅 / 深）
摩擦：<哪里理解一个概念要跳好几个文件 / 接口与实现一样宽 / 耦合泄漏>
加深：<接口收缩成什么，实现吸收什么>
收益：杠杆（N 个调用点）/ 局部性（改一处）/ 测试面（一个接口）
```
