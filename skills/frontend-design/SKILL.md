# 前端界面设计手册

把每个界面当作一件委托作品：客户已经拒绝过「模板感」的方案，要求有意为之的选择。

## 设计计划（先想清楚再写代码）

写 4 项决策，各一句话：

1. **主题锚点**：这个界面服务谁、他们用它完成什么？行业与语境决定视觉方向。
2. **色板**：4–6 个命名色值（底 / 面 / 主文字 / 次文字 / 主强调 / 状态色），强调色只出现于需要引导的地方。
3. **字体**：一个家族承担标题、一个承担正文（或同一家族两种字重）；字号阶梯明确（1.25 或 1.5 倍比）。
4. **布局**：主对齐方式（左对齐为默认）、栅格（8px 基准）、首屏信息层级。

写完自问：把这份色板换到另一个无关产品上还成立吗？成立说明不够贴题，重做决策 1–2。

## 实现纪律

- **首屏第一眼**：展示该主题最典型的东西（核心数据 / 货品 / 关键动作），而不是「大数字 + 小标签」的默认组合——除非那确实最合适。
- **字排**：正文行宽 ≤ 80 字符；标题与正文对比拉开（≥ 2 倍字号）；不用全大写做标签、不给标题加装饰下划线。
- **结构即信息**：编号 / 分割线 / 边框只用于表达真实结构（序列、分组），不做装饰。
- **动效克制**：一个编排好的入场胜过满屏动效；只为「回应操作、说明变化」而动的动效保留。
- **状态齐全**：hover / focus / active / disabled / loading / empty / error 八个状态都要有定义；键盘 focus 可见。
- **可访问性底线**：对比度达标（正文 ≥ 4.5:1）；支持 reduced-motion；点击目标 ≥ 40px。
- **响应式**：至少覆盖移动 / 桌面两档，栅格与字号随之调整而非简单缩放。

## 「模板感」清单（命中即改）

- 奶油底 + 高对比衬线 + 陶土色点缀的组合（无差别套用）。
- 一切都做成等圆角卡片 + 同一柔影，层级消失。
- 标题上方一排字距拉开的全大写小标签；描述用「·」连接的元信息串。
- 每张卡片都有 hover 上浮；每节都有淡入上滑。
- 强调色同时出现三个以上；渐变当装饰。

## 文案（界面上的字）

- 用用户语言命名功能（「通知设置」而非「webhook 配置」）。
- 按钮动词 = 动作结果（「发布 / 已发布」而不是「提交」）；同一动作全流程同名。
- 报错说清楚「发生了什么 + 怎么修」，不道歉、不模糊；空状态给一个行动入口。

## 检查清单

- [ ] 设计计划四项已写并自检过「换产品是否仍成立」
- [ ] 八状态齐全；focus 可见；对比度达标
- [ ] 无「模板感」清单命中项
- [ ] 文案为动词具体、无 jargon
- [ ] 移动 / 桌面两档不破版

## 工具用法

- 在既有代码库中改动时，先读周边组件与样式（`search_text` / `read_file`），复用既有 token 与组件，命名与风格与所在文件一致。
- 自检手段：如有浏览器接入，用 `browser_screenshot` 看图评审（截图胜过千言）；无则输出「评审清单」请用户核对。
- CSS 选择器保持低特异性，避免互相抵消。

## 输出约定

- 改动落在既有前端代码中（与所在仓库结构一致）；设计决策写入交付说明（色值 / 字阶 / 关键状态一览）。
