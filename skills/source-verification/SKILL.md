# 信源核验手册

目标：让每一个进入交付件的关键事实，都能通过三个问题——**谁说的？他凭什么知道？别人能否复核？**

## 信源分级

| 级别 | 定义 | 用法 |
| --- | --- | --- |
| A 一手 | 官方文件 / 财报 / 实测数据 / 当事人直接陈述 | 可直接引用，标注出处与日期 |
| B 权威二手 | 主流媒体、行业报告、机构研究 | 可用，需与 A 级交叉或两源互证 |
| C 自媒体 / 转述 / 论坛 | 个人观点、无出处转述 | 仅作线索，不进结论；使用必须显式标注「未经证实」 |

- 匿名来源一律按 C 处理；无法溯源的数字不进交付件。
- 「某某说」不够，写清：姓名 / 机构 / 场合 / 时间。

## 交叉验证规则

1. **双源独立**：两个来源不能同源（转载不算两个）。数字一致才可写入结论。
2. **找原始出处**：引用链追溯到最上游；转述与原文有出入时以原文为准。
3. **反例检查**：主动搜「否定证据」（失败案例、反驳观点），找不到才判定成立。
4. **时效检查**：日期超过 12 个月的数字标注「截至 <日期>」；政策 / 价格类必须用最新版本。
5. **口径检查**：数字的单位、统计范围、时间窗一致才能相互比较；不同口径并列呈现。

## 核验记录格式（随交付件附上）

    | 事实 | 来源（级别） | 日期 | 核验方式 | 结论 |
    | --- | --- | --- | --- | --- |
    | 市场规模 120 亿 | B：XX 研究院 | 2026-03 | 与 A 级协会年报交叉 | 一致，采用 |

- 争议事实：并列呈现双方说法与出处，不替读者裁决；明确写出「暂无法核实」。
- 推断与事实分离：推断段落以「推断：」开头，并写依据。

## 常见错误

- 拿聚合站的数字当原始数据（聚合站常转述失真）。
- 「多个来源都这么说」但实为同一篇通稿转载。
- 只搜支持性证据（确认偏误）；只核数字不核口径。
- 把时间敏感信息（价格 / 政策 / 排名）当作长期成立。

## 检查清单

- [ ] 每个关键事实有来源（级别 / 日期 / 出处）
- [ ] 双源独立交叉；已查反例
- [ ] 引用链已追溯到原始出处
- [ ] 时效与口径已核；过期数字已标注
- [ ] 不确定性显式呈现（争议 / 推断 / 无法核实）

## 工具用法

- `web_search` / `web_fetch` 收集与溯源（如可用）；原文提取优先于摘要页。
- 本地资料用 `search_text` / `read_file` 交叉核对；核验表用 write_file 落盘。
- 呈现：`::: details` 收纳逐条核验记录，正文只保留结论与级别标注。

## 输出约定

- 核验记录随研究报告交付：`docs/<报告名>-核验表.md` 或报告末尾附节。
- 报告中每个引用的格式：`来源名（级别，日期）`，链接可选但出处必填。
