# 用户画像与概念测试

画像不是人口统计标签的堆砌（「25–35 岁女性」），而是**一串可解释的行为与动机**（「周五晚上临时找饭局、讨厌排队、信任朋友转发」）。画像的价值在于让设计决策有一个具体的想象对象。

## 触发场景

- 用户研究与需求分析：把访谈、评论、行为数据整理成画像；
- 概念测试：新功能/新文案/新定价面向画像面板做预演；
- 受众分析：营销与内容策划的目标人群具象化。

## 画像构建流程（数据驱动）

1. **收集素材**：访谈记录、客服工单、评论区、行为数据、问卷开放题——先分类贴标签；
2. **选行为变量**（而非人口统计）：使用频率、任务类型、动机、替代方案、决策影响因素、付费意愿；
3. **分群**：按行为变量的组合聚类 2–4 个画像；画像之间必须**在行为上有可判定的区别**（能预测对同一功能的相反反应）；
4. **命名与具象**：给每个画像一个有画面感的代号（「赶时间的通勤党」），补一句典型场景；
5. **证据回链**：每个画像字段标注素材来源（哪次访谈、哪类数据）——无来源的字段标注「假设」。

## 画像卡字段（每张卡固定结构）

| 字段 | 内容要求 |
|---|---|
| 代号与一句话 | 有画面、能引用 |
| 典型场景 | 在什么时间/场合/心情下使用 |
| 核心目标 | 他想完成的事（jobs to be done） |
| 现有替代 | 今天他怎么解决（含「不解决」） |
| 痛点 | 现方案的摩擦点，按强度排序 |
| 决策因素 | 什么让他选/不选（价格、信任、速度…） |
| 一句话引用 | 来自原始素材的真实原话 |
| 证据强度 | 强（多来源）/ 中 / 弱（标注假设） |

## 概念测试（画像面板预演）

1. **概念描述**：一段话讲清「是什么、给谁、替代了什么」，不夹带战术细节；
2. **逐画像三问**：① 我第一反应能理解它是什么吗？② 我会用它替代现在的做法吗，为什么？③ 什么会阻止我（价格/信任/习惯/学习成本）？
3. **反馈矩阵**：行为 × 画像，填「会用 / 犹豫（原因）/ 不会（原因）」——重点是**犹豫与不会的原因分布**；
4. **冲突点提取**：两个画像反应相反的设计点（往往胜负手就在这里）；给出「为 A 优化会牺牲 B 的哪一点」的取舍陈述；
5. **假设清单**：面板预演**不是**真实用户验证——产出的结论一律标注「待真实用户验证」，并列 3 条最关键的待验证假设与验证方法（访谈/灰度/落地页测试）。

## 与需求的衔接

- 需求优先级可参照画像分布：服务 3/4 画像且无画像强烈反对 > 服务 1 个画像但完美；
- 反例澄清：任何画像都「不会反对的优化」通常是伪需求（价值低）；
- 与 ux-researcher 的访谈方法（`deep-research`）接力：深访产出素材 → 本技能产出画像与面板预演。

## 交付约定

- 落盘 `docs/用户画像-<主题>.md`，章节：素材与来源 / 分群依据 / 画像卡（2–4 张）/ 概念反馈矩阵 / 冲突点与取舍 / 待验证假设清单；
- 完成定义：每张画像卡字段齐全且证据强度标注；画像间行为差异可判定；假设清单带验证方法。

## 检查清单与反模式

- 交付前核对：① 分群基于行为变量？② 每字段挂来源或标「假设」？③ 画像间能预测相反反应？④ 反馈矩阵含原因分布？⑤ 假设与结论分开写？
- 反模式：编造「数据」支撑画像；用人口统计代替行为；把所有用户当成一个「平均人」；面板预演被说成「用户已经验证」；画像卡写成广告词。
