# 报告写作手册

报告的失败大多不是文笔问题，而是**规格不明、结构失控、证据不足**。三条纪律：先定档位、分章撰写、量化自检。

## 四档规格（与全局协议 <deliverable_spec> 一致）

| 档位 | 篇幅 | 结构 | 证据 | 适用 |
| --- | --- | --- | --- | --- |
| 速览 | ≤800 字 | 结论 + 3–5 要点 + 下一步 | 关键数字带来源 | 快评 / 简报 / 即时要点 |
| 标准 | 1500–4000 字 | 章节完整；每章以结论句收尾 | 主张有依据；来源 ≥3 | 常规分析 / 评审 / 说明 |
| 深度 | ≥4000 字 | 分章 + 图表 ≥2 + 来源编号 + 附录 | 结论挂来源编号；反面证据 ≥3 | 投研 / 研究 / 行业报告 |
| 专项 | 多件套 | 主报告 + 附录 / 数据包 / 图表件 | 全链路可复现 | 课题级 / 决策支持 |

档位优先级：用户指定 > 计划验收标准（acceptance）> 角色交付契约默认。无法判断时按「标准」起步并向用户确认一句。

## 分章撰写流程（深度 / 专项档）

1. **列骨架**：把报告拆成 4–8 章，每章先写一句「本章回答什么问题」；结果用 `write_todos` 跟踪。
2. **落骨架**：`write_file` 写入骨架文件——章节标题 + 每节一行要点 + 占位标记（如 `<!-- §3 待填 -->`）。
3. **逐节填充**：用 `edit_file` 把占位标记替换为该节正文（单节 800–1500 字）；一次一节，不贪多。
4. **节内三件套**：每节 = 论点 → 论据（数据 / 引用 / 案例）→ 「所以怎样」结论句；缺结论句的节不算完成。
5. **收尾自检**：全文通读——字数 / 章节数 / 来源数 / 图表数对照档位；结论是否前置；有无「然后呢」段落。

速览 / 标准档可一次成文；单次输出放不下时同样走分章流程，禁止「先写短再补」。

## 领域章节库（按报告类型取用）

### 研究报告
方法与限制 / 问题树 / 结论与置信度 / 证据链 / 反面证据 / 未决问题与下一步

### 投研报告
一句话结论（含置信度）/ 标的基本盘 / 多路要点 / 分歧与裁决记录 / 情景与条件触发 / 风险声明 / 数据附录

### 行业 / 市场分析
市场规模与增速（口径 + 来源）/ 竞争格局 / 驱动与制约 / 玩家画像 / 趋势研判 / 风险与不确定性

### 经营分析 / 复盘
目标 vs 实际 / 差异归因（可控 vs 不可控）/ 关键动作回放 / 教训与资产 / 下一步清单（责任人 + 期限）

### 决策方案
问题界定 / 候选方案对照（成本 / 收益 / 风险）/ 推荐与理由 / 实施路径 / 放弃条件

### 议题简报
背景一句 / 结论 / 依据 3 条 / 影响面 / 建议与下一步

## 量化自检清单

- [ ] 字数达标（速览 ≤800 / 标准 ≥1500 / 深度 ≥4000；不确定就数）
- [ ] 章节数达标（深度 ≥6 章；标准 ≥4 章）
- [ ] 来源标注：每个数字有来源与日期（深度档 ≥8 个来源编号）
- [ ] 图表：深度档 ≥2 个（表格 / `chart` 块 / mermaid 均可）
- [ ] 每章有结论句；全文结论前置
- [ ] 反面证据 / 风险 / 限制段存在（研究报告 / 投研报告必含）
- [ ] 可独立成立：单独转发时无「见上文」类悬空指代

## 反模式（出现即回炉）

- **提纲式报告**：全篇只有标题和短句，没有展开——每章至少 3 个完整段落或要点组；
- **字数注水**：为凑篇幅复述已知信息、堆形容词——宁删勿凑，缺内容补证据；
- **单次硬写**：深度档一次 `write_file` 全文——必然截断或缩水，必须分节；
- **占位残留**：交付时仍有「待填 / TODO / 略」——落盘前全文搜索清理；
- **来源悬空**：「研究表明」「数据显示」无出处——要么给来源编号，要么标注为推断。

## 工具接入口径

- 落盘 / 分节：`write_file`（骨架与速览档全文）、`edit_file`（逐节填充）；多处替换用 `apply_patch`。
- 数字复核：`calc`（金额 / 比例）、`csv_analyze`（表格统计）；日期用 `date_calc`。
- 图表：汇总用 Markdown 表；配置图用 `*.chart.json`（echarts）；流程用 mermaid 块。
- 交付说明：落盘后在发言中用 3 行内交代「交付了什么 / 核心结论 / 下一步」，不复述全文。
