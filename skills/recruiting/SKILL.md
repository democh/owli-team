# 招聘手册

招聘的质量由**流程结构化程度**决定：JD 定义清楚、面试题对齐职责、评分锚点先于面试写下、决策看证据不看印象。

## JD 撰写

    岗位名（含职能，不含「超级」类形容词）
    我们是谁：一句话业务现状（真实、具体）
    你将负责：3–5 条（动词开头，含预期产出）
    必须项：≤ 4 条（只写真正卡关的；技能 / 年限 / 场景）
    加分项：≤ 3 条（写清为什么加分）
    薪资与节奏：范围 + 工作方式（远程 / 坐班）——能给的都写清

- 不写歧视性条件（性别 / 年龄 / 婚育）；不写「抗压能力强」「有激情」类无法验证项。
- 「必须项」逐条自问：没有它真的做不了这份工作吗？不是则移到加分项。

## 面试流程（四步，每步有产物）

| 步骤 | 时长 | 产物 |
| --- | --- | --- |
| 简历筛选 | — | 筛选结论表：过 / 不过 + 依据（对照必须项） |
| 首轮（经历与动机） | 30min | 必问两题：最自豪的项目（追问细节）、为什么来 |
| 二轮（能力） | 60min | 结构化题库 3–5 题，每题有评分锚点 |
| 终轮（匹配与期望） | 30min | 期望核对：职责 / 节奏 / 薪资区间 |

- **评分锚点先写**：每题的 1 分 / 3 分 / 5 分各长什么样，面试中只记录证据不现场打分。
- 行为面试为主：问「上次怎么做」，不问「如果怎样你会怎样」。
- 面试记录统一格式：问题 → 回答要点 → 证据归类（某能力 +）→ 待验证点。

## 筛选结论表（每人一行）

    候选人 | 必须项逐条核对（✓/✗ + 依据） | 亮点 | 疑点 | 结论（推进 / 保留 / 婉拒）

## Offer 与上岗

- Offer 前：薪资区间与职级口径和负责人确认（不口头承诺）。
- Offer 信含：岗位 / 薪资构成 / 试用期 / 起点日期 / 接受截止时间（给 3–5 个工作日）。
- 婉拒信：简短、尊重、不解释内部评价（「综合评估后」即可）。
- 30-60-90 上岗计划：30 天学什么（资源清单）、60 天交付什么（一个小目标）、90 天独立负责什么。

## 检查清单

- [ ] JD 必须项 ≤ 4 且逐条可验证；无歧视项
- [ ] 每轮面试有产物；题库含评分锚点
- [ ] 面试记录为证据式，非印象式
- [ ] Offer 要素齐全；区间与决策人核实
- [ ] 婉拒信不泄露内部评价
- [ ] 30-60-90 计划含具体交付

## 工具用法

- 候选人台账落盘 `data/候选人.csv`（阶段 / 轮次 / 结论 / 下一步日期），`csv_analyze` 看漏斗与节奏。
- `template_fill` 批量生成面试邀约 / 婉拒信（占位 `{{候选人.姓名}}`）；措辞分寸对齐 `comms-writing`。
- 面试安排用 `date_calc` 核算（约面时间、截止时间；如不可用直接给具体日期建议）。

## 输出约定

- 交付：`docs/招聘-JD-<岗位>.md`、`docs/招聘-面试记录-<候选人>.md`、`data/候选人.csv`。
