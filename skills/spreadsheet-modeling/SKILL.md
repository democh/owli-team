# 表格建模手册

交付物 = 「规范 CSV（可被 Excel / 表格软件直接打开）+ 一页分析报告」；数据结论必须来自工具统计，禁止目测估数。

## 工作流

1. **先看形状**：`csv_analyze` 的 `describe` 拿列类型与统计；空值 / 异常值在报告开头声明处理方式。
2. **口径声明**：金额单位（元 / 万元）、币种、含税与否、时间口径；同一份交付件不得混用。
3. **算**：能进 CSV 的明细先落盘为 CSV，再用 `csv_analyze` 的 `groupby / filter / sort` 出结论；派生指标用 `calc` 计算并保留公式与代入值。
4. **产出**：CSV 列名用「中文名（单位）」，如 `合同额（万元）`；金额千分位不写进 CSV 原始值（展示层再格式化）。
5. **报告**：结论先行（3 条以内），每条结论标注数据来源与计算口径；图表用 Markdown 扩展的 chart / mermaid 代码块。

## csv_analyze 速查

| 目的 | 调用形态 |
| --- | --- |
| 看行数 / 列类型 | `op: describe` |
| 按维度汇总 | `op: groupby, by: 渠道, agg: "sum:金额"`（缺省 count） |
| 筛选 | `op: filter, where: "金额 > 1000"`、`where: "渠道 ~ 抖音"` |
| 排序取 TOP | `op: sort, column: 金额, order: desc, limit: 10` |
| 预览 | `op: head, limit: 20` |

- 文件上限 5MB；超限先抽样或拆分。
- 数值列混入非数字会直接报错——先清洗（用 edit_file 修正源行）再统计，不要绕过。

## 表格设计规范

- **一表一主题**：明细表不混入汇总行；汇总放在报告或独立汇总表。
- **列齐前置**：维度列（日期 / 渠道 / 产品）在前，度量列（数量 / 金额）在后。
- **假设单列**：模型类表格中，每个假设单独一行并标来源（实测 / 参考 / 用户给出），下游单元格引用假设行。
- **可复算**：关键结果给「公式 + 代入值」，他人可独立复算一致。
- **三档情景**：保守 / 基准 / 乐观分别给一列或一表，写明差异假设。

## 预测与库存类

- 再订货点 = 日均消耗 × 提前期 + 安全库存；安全库存按最大波动周量给出并注明。
- 预测标注「预测」；只给单点数字视为不完整——至少给区间与最相关的 2 个假设。
- 比价 / 供应商对比用加权矩阵：维度（价格 / 交期 / 质量 / 服务 / 风险）× 权重 × 评分，权重占位须写理由。

## 检查清单

- [ ] 结论来自 `csv_analyze` / `calc`，没有目测数字
- [ ] CSV 文件落盘且能被打开；列名含单位
- [ ] 口径与假设在报告开头声明
- [ ] 每张图有标题、单位与来源口径
- [ ] 交付件之间引用同一数字时标注出处，避免互相矛盾

## 工具用法

- `csv_analyze`：表格统计入口（head / describe / groupby / sort / filter）；不在工具清单时，用 `read_file` + `calc` 完成统计并在报告标注方式。
- `calc`：派生指标计算；`date_calc`：周期与排期（如可用）。
- `template_fill`：用数据批量生成同类文档（如可用；否则逐份 write_file 生成）。
- `write_file` / `edit_file`：写 CSV 与报告；CSV 用 UTF-8，逗号分隔。

## 输出约定

- 数据：`data/<主题>.csv`；报告：`docs/<主题>-分析.md`。
- 报告结尾附「数据文件清单」（相对路径 + 行数），方便复算。
